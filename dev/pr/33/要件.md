# 要件

## 要望

- セッションと API を、方針の記録（[構造の決定](https://github.com/shuhei1101/voice-paste/blob/develop/dev/pr/12/%E6%96%B9%E9%87%9D%E6%B1%BA%E3%82%81/4_%E6%A7%8B%E9%80%A0%E3%81%AE%E6%B1%BA%E5%AE%9A.md)・[リスクと移行計画](https://github.com/shuhei1101/voice-paste/blob/develop/dev/pr/12/%E6%96%B9%E9%87%9D%E6%B1%BA%E3%82%81/5_%E3%83%AA%E3%82%B9%E3%82%AF%E3%81%A8%E7%A7%BB%E8%A1%8C%E8%A8%88%E7%94%BB.md)）と、[#26](https://github.com/shuhei1101/voice-paste/pull/26) で起こしたモジュール構成・インターフェース定義のとおりに `src/voice_paste/` に作る
  - セッション: `features/session` の `SessionManager` がセッションを同時に 1 つだけ持ち、入口（API・ホットキー・トレイ）からの開始・停止・完了・一時停止・再開・取り消しで状態を進める。確定した録音を履歴に保存してから、文字起こし → 補正 → 履歴への書き足し → 届けるをワーカースレッドで行い、どの経路でも待機中へ戻す
  - 排他: セッションが残っている間の開始は `SessionBusyError` で断り、2 つ目の録音を始めない
  - API: `POST /sessions`（202 とセッションの ID）・`POST /sessions/{session_id}/stop`（200）・`POST /sessions/{session_id}/complete`（202）を FastAPI で作り、uvicorn を 127.0.0.1 だけで待ち受ける専用のスレッドで動かす
  - 要求の守り: Origin の付いた要求とほかの Host は 403、起動ごとのトークン（`Authorization: Bearer`）が合わなければ 401 で断る。トークンは起動ごとに作り、ポートと共にトークンのファイルへ書く
  - エラーの応答: 入力の検証の失敗と許されない返送先は 400、知らないセッションは 404、処理中の開始は 409、マイクを開けないときは 503 を RFC 9457 の `application/problem+json` で返す
  - 返送: 起こした文字（空も含む）・失敗・上限での打ち切りを、開始で受け取った返送先へ JSON で POST する。返送先は loopback と設定（`api.allowed_callback_hosts`）で許可したホストに限る。届かなければ決めた回数まで再送し、それでも届かなければログに書いて終える（履歴は残る）
  - 上限での打ち切り: 完了が来ないまま開始から上限時間（非機能要件の 600 秒）を過ぎた API のセッションを打ち切り、録音を履歴に残して返送先へ `truncated` を送る
  - 起動: `main.py` で設定からセッションの依存を組み立て、API サーバーを起動する。待ち受けを始められなかったら（`started` が立たない）ERROR のログに残し、ユーザーへの知らせの関数へ渡す
- 完了の定義
  - API で録音を開始・停止・完了し、指定したエンドポイントに文字が届く（品質シナリオ 1。50 回続けて呼んで 50 回とも届き、開始の応答が 500 ms 以内）
  - 処理中の開始が 409 になり、2 つ目の録音が始まらない（品質シナリオ 6。409 の応答が 1 秒以内）
  - import-linter の検査が通る（`features/session` はほかの feature を import せず、関数型で受け取る）
- 普段使い（`voice_paste_legacy` と、リポジトリの直下の `.env`・`history/`・`log/`）には触れない
