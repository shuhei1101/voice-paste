## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| セッションの種類の判定 | Linux で `XDG_SESSION_TYPE` が `wayland` のときを Wayland のセッションとし、それ以外を Xorg のセッションとして今の実装を使う。判定は `shared/` に置き、`select_platform_adapters` が受け取って実装を選ぶ | Windows と Xorg の分岐の中身は変えない |
| ホットキー | Wayland のセッションでは、PoC で決めた方法で設定のホットキーを受け付け、今の `HotkeyListener` と同じく配線された関数を呼ぶ。登録したショートカットは、トレイの終了・SIGTERM での終了で外し、起動のときに前の登録の残りを外してから登録する | `未確定`（[要件](./要件.md) のホットキーの受け方）。残った登録は、押したキーを GNOME が受けてアプリへ届けない |
| 貼り付けのキーと Enter の送信 | Wayland のセッションでは、PoC で決めた方法で貼り付けのキーと Enter（修飾キーつき）を送信する。`PlatformAdapters` に Enter の送信も持たせ、Wayland のセッションでは差し替える。貼り付けのキーは、クリップボードへ書いてから 0.3 秒待って送信する | `未確定`（[要件](./要件.md) のキーの送信の方法）。`wl-copy` は書くときに一瞬フォーカスを取るため、0.1 秒では 10 回中 2 回キーが落ちた |
| クリップボード | Wayland のセッションでは、pyperclip が `WAYLAND_DISPLAY` を見て `wl-copy` を選ぶため、`copy_to_clipboard` は変えない | 「コピーのみ」で書いた文字は、常駐サービスの終了後も貼り付けられる |
| 画面 | Wayland のセッションでは、Qt のプラットフォームを `xcb`（XWayland）に固定する | ネイティブの `wayland` では、録音の画面と文字起こし中の表示が設定の位置に置けず、貼り付け先のフォーカスを取る |
| OS のパッケージと権限 | Wayland のセッションで要る OS のパッケージ（`wl-clipboard`）と、要る設定（`/dev/uinput` の udev の規則・`input` グループへの追加・その後の再起動）を手順のページに記載する。起動のスクリプトは入っているかを確かめない | 権限の設定は利用者が sudo で行う。グループの追加はログアウトでは反映されない（systemd のユーザーマネージャーが残る） |
| 通しの確認 | VM の `/etc/gdm3/custom.conf` の `WaylandEnable=false` を外して Wayland のセッションでログインし、#199 と同じく PipeWire の仮想マイクへ WAV を流して、起動 → ホットキー → 文字起こし → テキストエディターへの貼り付けを通す | 確かめた後、VM を Xorg のセッションへ戻す |

## PoC 結果

結論: 成立。
[要件](./要件.md) の `未確定` の 3 つは、いずれも案 A（Ubuntu 24.04・GNOME のカスタムショートカット・python-evdev の `UInput`）で成り立った。
条件は、画面を `xcb` に固定すること・貼り付けのキーをクリップボードへ書いてから 0.3 秒待って送信すること・グループの追加の後に再起動すること。

検証環境は VM `voice-paste-ubuntu`（Ubuntu 24.04.5・GNOME Shell 46.0・Wayland のセッション）、wl-clipboard 2.2.1、evdev 2.0.0、PySide6 6.11.2。
キーの入力は uinput の仮想キーボード、画面の操作は uinput のペンタブレットと dbusmenu で行った。
貼り付け先は、受けた文字とキーをファイルへ書き出すプローブ（PySide6。ネイティブ = `wayland`、XWayland = `xcb`）にした。

所感:
- GNOME には data-control のプロトコルが無く、`wl-copy` は書くたびに小さなウィンドウでフォーカスを約 4 ms 取る。取るのは copy を始めてから 40〜70 ms 後で、copy が返った後のこともあるため、貼り付けのキーの前の待ちは Xorg の 0.1 秒より長くする
- 今の終了の処理は SIGINT だけを受け、SIGTERM では片付けを通らない。ログアウトで SIGTERM を受けると登録が残るため、SIGTERM でも片付ける
- noble の ydotool は 0.1.8（デーモンが要らない旧版）で、方針に書いた「1.x は ydotoold が要る」は当たらない。python-evdev で足りたため使っていない

最小再現コードの要点（[PoC PR #221](https://github.com/shuhei1101/voice-paste/pull/221) の [96aaa36](https://github.com/shuhei1101/voice-paste/pull/221/commits/96aaa36f6161f4cda37796bd74eb5db715b7d162)）:

```python
# runtime/hotkey_gnome.py: 設定のホットキーを GNOME のカスタムショートカットへ登録する
for index, hotkey in enumerate(bindings):
    path = f"{CUSTOM_KEYBINDING_PATH_PREFIX}{index}/"   # /org/gnome/.../custom-keybindings/voice-paste-N/
    schema = f"{CUSTOM_KEYBINDING_SCHEMA}:{path}"
    command = shlex.join([sys.executable, "-m", "voice_paste.runtime.send_hotkey", self._name, hotkey])
    _gsettings("set", schema, "name", f"voice-paste {hotkey}")
    _gsettings("set", schema, "command", command)
    _gsettings("set", schema, "binding", to_gnome_accelerator(hotkey))   # <cmd>+<alt>+d → <Super><Alt>d
_write_paths(others + own)   # ユーザーの登録は残す

# runtime/send_hotkey.py: ショートカットが起動し、終了の依頼のソケットへ送信する（接続できなければ 0 で終わる）
client.connect(f"\0{name}-quit")
client.sendall(HOTKEY_REQUEST_PREFIX + hotkey.encode("utf-8"))   # b"hotkey:<cmd>+<alt>+d"

# integrations/keyboard/sender_wayland.py: UInput の仮想キーボードで送信する
device.write(ecodes.EV_KEY, code, 1)   # 修飾キー → 主キーを押して離す → 修飾キーを逆順に離す
device.syn()
```

diff の見どころ:
- `runtime/single_instance_linux.py`: 受けたバイト列が `hotkey:` で始まれば受け手を呼んで待ち続け、`quit` なら今までどおり終わる（同じ uid の接続だけを読む）
- `main.py`: Wayland のセッションで `HotkeyListener` を `GnomeShortcutListener` に、`send_paste`・`send_enter` を uinput の実装に差し替える（PoC のため分岐を直に書いた）
- `poc/220/`: プローブ・uinput のキーボードとペンタブレット・通しと計測のスクリプト
