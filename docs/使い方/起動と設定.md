# 起動と設定

ショートカットからの起動と終了、設定・履歴・ログの置き場所

## 環境を作る

リポジトリの直下で、Windows の uv の `uv sync --frozen` を流す。
`.venv/` に、`uv.lock` で固定したバージョンの依存が入る。

```bash
uv sync --frozen
```

ローカルの Whisper（faster-whisper と NVIDIA の CUDA のライブラリ）は `local-whisper` の extra にあり、上のコマンドだけでは入らない。
ローカルの Whisper を使う環境は、extra を含めて作る。

```bash
uv sync --frozen --extra local-whisper
```

[文字起こしのエンジン](#文字起こしのエンジン)に OpenAI API を使う環境は、extra を含めない `uv sync --frozen` で足りる。
faster-whisper と NVIDIA のライブラリが入らないため、GPU の無い端末でも環境を作れる。

ショートカットから起動するたびに、起動のバッチファイルが `local-whisper` の extra を含めて `uv sync --frozen` を流し、`.venv/` を `uv.lock` に揃えてから起動する。
`.venv/` が無いときや、取り込んだ変更で依存が変わったときも、起動すれば `.venv/` が作り直される。
uv は PATH から探し、無ければ `%USERPROFILE%\.local\bin\uv.exe` を使う。

## 起動する

デスクトップかスタートメニューの `voice-paste.bat - ショートカット` を開く。
コンソールは出ず、トレイに voice-paste のアイコンが出る。
`.venv/` を再作成する間は、コンソールに `Syncing .venv with uv sync --frozen.` の行が出たまま残る。依存を再インストールするときは数分かかることがあり、再作成が終わるとコンソールが閉じて常駐サービスが立つ。
文字起こしのモデルを読み込む間は準備中のアイコンで、読み込みが終わるとアイコンが待機中になり、録音を始められる。

常駐中にもう一度ショートカットを開くと、前の常駐サービスに終わるよう頼み、終わってから新しい常駐サービスが立つ。
常駐サービスはいつも 1 つだけ動く。
前の常駐サービスが 55 秒までに終わらないときは、新しい常駐サービスは立たずに終わり（トレイのアイコンは出ない）、理由は `%LOCALAPPDATA%\voice-paste\log\` の日付つきのログに書かれる。

起動に失敗したときは、トレイのアイコンが失敗の表示になり、理由が通知される。

- `settings.toml` を読めないときは、「録音を開始」も「設定…」も押せない。「設定フォルダを開く」から `settings.toml` を修正し、「再起動」を選ぶ
- 文字起こしのモデルを読み込めないときは、録音を始められない。「設定…」から設定を開いて直せる
- 文字起こしのエンジンを準備できないときも、録音を始められない。エンジンが OpenAI API で API キーを読めないとき、エンジンがローカルの Whisper で `local-whisper` の extra が入っていないときが当たる。理由が通知され、ログに記載される。「設定…」でエンジンを選び直すか、API キーを置くか extra を含めて環境を作り直してから、「再起動」を選ぶ
- API の待ち受けを始められないときは、API だけが使えず、ホットキーとトレイからの録音は使える
- ホットキーを受け付けられないときは、トレイから録音できる

環境を作れないときは常駐サービスは立たず、コンソールに `[ERROR]` で始まる理由と `launcher.log` の場所が出て止まる。

| 理由の行 | 起きたこと |
| --- | --- |
| `[ERROR] uv not found. ...` | uv が PATH にも `%USERPROFILE%\.local\bin\uv.exe` にも無く、`.venv/` から voice-paste を読み込めない。uv を入れてからショートカットをもう一度開く |
| `[ERROR] uv sync --frozen failed with code ...` | `uv sync --frozen` が失敗した。出力は `launcher.log` にある |
| `[ERROR] voice_paste cannot be imported from .venv after uv sync.` | `.venv/` を再作成しても voice-paste を読み込めない |

起動の記録（起動した時刻・使った Python・終了コード）は `%LOCALAPPDATA%\voice-paste\log\launcher.log` に書かれる。
`uv sync --frozen` の出力もここに書かれる。
起動のたびに上書きされる。

## トレイから操作する

トレイのアイコンを右クリックするとメニューが開く。

| 項目 | 操作 |
| --- | --- |
| 録音を開始 | 録音を始める（アイコンの既定の操作）。[録音して貼り付ける](./録音して貼り付ける.md) |
| 録音の画面を表示 | 録音中に非表示にした録音の画面を再表示する。非表示にしている間は、アイコンの左クリックもこの操作になる |
| 設定… | 設定画面を開く |
| 設定フォルダを開く | `settings.toml` のあるフォルダをエクスプローラーで開く |
| ログフォルダを開く | ログのフォルダをエクスプローラーで開く |
| 再起動 | 常駐サービスを終え、同じ引数で新しく起動する。`settings.toml` の今の設定で立つ |
| 終了 | 録音の受付・API・文字起こしのワーカーを止めて終わり、アイコンを削除する |

録音から届けるまでの間は「録音を開始」と「設定…」を押せない。
その間に「再起動」「終了」を選ぶと、アイコンはすぐに消え、その回が終わってから再起動・終了する。
「録音の画面を表示」は、録音の画面を非表示にしているときだけ押せる。

## 設定

設定は `%APPDATA%\voice-paste\settings.toml` に置く。
無ければ起動時に既定値で作る。

設定画面（トレイの「設定…」）で変更して保存する。
「保存」を押しても設定画面は閉じず、フッターの上に「保存しました。」と出る。
ホットキーは設定画面を閉じてから新しい組み合わせで効く。
`settings.toml` を直接書き換えてもよく、その場合は再起動してから効く。
設定画面の「再起動で反映」のマーカーがある項目は、保存した後に再起動してから効く。

設定のキーと既定値の見本はリポジトリの直下の `settings.sample.toml` にある。

### 画面の明暗

設定画面の「画面」のまとまりの「画面の明暗」で、全ての画面（録音の画面・文字起こし中の表示・設定画面・ダイアログ・トレイのメニュー）の明暗を選ぶ。
保存すると、再起動せずに開いている画面と次に出す画面へ効く。

| 選択肢 | 配色 |
| --- | --- |
| Windows の設定に従う（既定） | Windows の明暗に合わせる。常駐中に Windows の明暗を切り替えると、画面の配色も切り替わる |
| ライト | Windows の明暗によらずライトにする |
| ダーク | Windows の明暗によらずダークにする |

`settings.toml` では `ui.theme` に `system`・`light`・`dark` を書く。
このキーが無い `settings.toml` は「Windows の設定に従う」として動く。

### ボタンのホットキーの表示

設定画面の「画面」のまとまりで、録音の画面と文字起こし中の表示のそれぞれについて、ボタンの名前の下にホットキーを表示するかを選ぶ（既定は表示する）。
表示しないときはボタンに名前だけが出て、ホットキーでの操作はそのまま効く。
保存すると、次に出す録音の画面・文字起こし中の表示から効く。

`settings.toml` では、録音の画面は `ui.show_hotkeys`、文字起こし中の表示は `ui.transcribing_show_hotkeys` に `true`・`false` を書く。
`ui.show_hotkeys` が無い `settings.toml` は「表示する」として動く。
`ui.transcribing_show_hotkeys` が無い `settings.toml` は `ui.show_hotkeys` と同じ値で動く。

### 外の端末のブラウザに許す Origin

外の端末のブラウザから文字起こしの画面を使うときは、`settings.toml` の `api.allowed_web_origins` に、ゲートウェイの公開のサブドメインのオリジンを記載する。

```toml
[api]
allowed_web_origins = ["https://voice-paste.shuhdev.com"]
```

- オリジンは `scheme://host[:port]` の形式で記載する。末尾の `/` とパスは付けない
- 既定は空で、空のままでは画面は開けても音声を送信できない（`403`）
- 設定画面の「API」のまとまりの「外の端末に許す Origin」の欄（1 行に 1 つ）でも変えられる。再起動してから効く

### 文字起こしのエンジン

録音を文字に起こすエンジンを、設定画面の「文字起こし（エンジン）」のまとまりの「使う文字起こしのエンジン」で選ぶ。
再起動してから効く。

| 選択肢 | `settings.toml` の値 | 文字の起こし方 |
| --- | --- | --- |
| ローカルの Whisper（既定） | `local_whisper` | この端末の faster-whisper で起こす。`local-whisper` の extra を含めて作った環境が要る |
| OpenAI API | `openai` | 録音を OpenAI API へ送信して起こす。API キーが要り、OpenAI の従量課金がかかる |

```toml
[transcription]
engine = "openai"
```

どちらを選んでも、ホットキー・トレイ・API の録音、連続録音の区間、外の端末のブラウザから送信した音声を同じエンジンで起こす。
表記のヒントは OpenAI API にも渡し、文字起こしの後の補正は同じ。
OpenAI API を選んだ間は、起こす録音の音声が OpenAI へ送信される。
文字起こし中の表示は、進みと残りの時間を出さず、経過の時間だけを出す。

設定画面の「文字起こし（OpenAI API）」のまとまりで、OpenAI API のときに使う値を変える。

| 設定のキー | 内容 |
| --- | --- |
| `transcription.openai.model` | 文字起こしに使うモデル |
| `transcription.openai.language` | 文字起こしの言語（ISO-639-1。日本語は `ja`） |
| `transcription.openai.base_url` | 送信先のベース URL（http か https で始まる URL） |

既定値は `settings.sample.toml` にある。

### OpenAI の API キー

API キーは `settings.toml` にも設定画面にも記載しない。
エンジンが OpenAI API のときだけ起動時に読み、次のどちらかに置く。
環境変数があれば、そちらを使う。

| 置き場所 | 中身 |
| --- | --- |
| 環境変数 `OPENAI_API_KEY` | API キーの文字列 |
| `%APPDATA%\voice-paste\secrets\openai_api_key` | API キーの文字列だけを記載したファイル。`settings.toml` と同じフォルダの `secrets\openai_api_key` に自分で置く（常駐サービスは作らない）。前後の空白と改行は除く |

どちらにも無いときは、起動に失敗する。
API キーはログにも出ない。

## 外の端末へ公開する

スマホ・iPad・外の PC のブラウザから使えるように、ゲートウェイ（shuhdev-gateway）で常駐サービスの API を公開する。
外からの認証はゲートウェイの Cloudflare Access が持ち、常駐サービスはトークンの代わりに許す Origin の一覧で `/web/` の下だけを通す。
使い方は[外の端末から文字に起こす](./外の端末から文字に起こす.md)。

<!-- steps -->

1. ゲートウェイが動いている端末の `~/.config/shuhdev-gateway/settings.toml` に、voice-paste の固定の登録を記載する。ポートは設定の `api.port`（既定 47823）。`rewrite_origin` は `false` のままにする。

   ```toml
   [[fixed_registrations]]
   name = "voice-paste"
   port = 47823
   title = "voice-paste"
   path = "/web/"
   rewrite_origin = false
   ```

   `rewrite_origin` を `true` にすると Origin が書き換わり、許す Origin の一覧と合わなくなって `403` になる。
2. ゲートウェイを再起動して、固定の登録を効かせる。`gw ls` に `voice-paste` が出て、公開 URL（例 `https://voice-paste.shuhdev.com`）が分かる。
3. 公開 URL を `settings.toml` の `api.allowed_web_origins` に記載し、トレイの「再起動」で反映する。
4. 外の端末のブラウザで、公開 URL の末尾に `/web/` を付けて開く。Cloudflare Access のログインの後に、文字起こしの画面が出る。

<!-- /steps -->

固定の登録は、常駐サービスを止めても外れない。公開 URL と許す Origin は変わらないため、常駐サービスを再起動しても操作は要らない。
固定の登録のキーとゲートウェイの再起動の仕方は、shuhdev-gateway のドキュメントにある。

## 履歴とログ

履歴・ログ・一時の音声・API のトークンは `%LOCALAPPDATA%\voice-paste\` の下に置く。

| 置き場所 | 中身 |
| --- | --- |
| `history\{日付}\` | 確定した録音（WAV）と起こした文字（テキスト）。`history.enabled` が `false` のときは残さない |
| `log\` | 日付つきのログ、`launcher.log`、クラッシュの記録 |
| `tmp\` | 履歴を残さない設定のときに、文字に起こすまで置く録音 |
| `api_token` | API のトークンとポート。[API](../リファレンス/API.md) |

保持期間を過ぎた履歴とログは、起動時と常駐中の 24 時間ごとに消える。

| 設定のキー | 既定値 | 削除する対象 |
| --- | --- | --- |
| `history.retention_days` | 1 日 | この日数より前の日付の履歴のフォルダ |
| `logging.retention_days` | 7 日 | この日数より前の日付のログ |

`launcher.log` は日付の名前を持たないため、保持期間では消えない。

## `.env` から移した設定

刷新前の設定（リポジトリの直下の `.env`）は `settings.toml` へ移してあり、元の `.env` は `.env.migrated` の名前で残っている。
刷新前の履歴（リポジトリの直下の `history\`）は `%LOCALAPPDATA%\voice-paste\history\` へコピーしてある。

次の設定はコピーしていない。

- OpenAI で文字を起こす設定（`TRANSCRIPTION_ENGINE=openai`・`OPENAI_API_KEY`）。文字起こしのエンジンはローカルの Whisper が既定で、OpenAI API は `settings.toml` の `transcription.engine` と API キーを自分で設定して使う（[文字起こしのエンジン](#文字起こしのエンジン)）
- 1 回だけ録音して終わる設定（`RESIDENT_MODE`）。常駐だけになった
