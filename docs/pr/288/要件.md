# 要件

## 要望

| 要件 | 終わりの条件 |
| --- | --- |
| 録音を開始した直後の取り消しで固まらない | ホットキー・トレイで録音を始めた直後に、録音の画面の「×」・「取り消し」・取り消しのホットキーのどれで取り消しても、画面が操作を受け付けない状態にならず、録音セッションが待機中に戻る |
| 取り消しの原因の特定 | 開始と取り消しが重なったときに固まる原因を、ログか再現のテストで特定し、計画書の `## 変更方針` に記載する |
| 終了の処理の間に録音を始められない理由を示す | 取り消し・確定の後の終了の処理の間に、トレイかホットキーで録音を始めようとした利用者に、終了の処理中で今は録音を始められないことが示される |
| 回帰のテスト | 開始の直後の取り消しと、終了の処理の間の開始を、単体テストか結合テストで確認する |

「取り消し」のボタンは、ホットキーの表示のために残す（利用者の判断）。

`未確定`: 開始と取り消しが重なったときの対策（決める段: モジュール構成設計。原因を特定してから決める）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 取り消しを受けたとき、録音の開始の処理が終わるのを待ってから取り消す。待つ処理と録音を捨てる処理は画面のスレッドで動かさない | 押した操作を捨てずに取り消せる | 録音セッションの状態の遷移が増える |
| B | 録音を開始してから一定の時間は、「×」と「取り消し」を押せないようにする | 変更が録音の画面に閉じる | 取り消しのホットキーは防げない。待つ時間の根拠が要る |

推奨: A

ホットキーの取り消しも同じ経路で固まりうるため、画面のボタンだけを止める B では取り切れない。

終了の処理の間に録音を始める操作を受けたら、処理中のダイアログで理由を示す（[確認ログ](./確認ログ.yaml)）。
本文は「前の録音を文字に起こして届けています。終わってから、もう一度録音開始のホットキーを押してください。」にする。
