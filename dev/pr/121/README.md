# 「設定を変える」の正常シナリオと「カスタムプリセットを足す」の E2E を、録音の入力を WAV に差し替えて置く

## 概要

単一ユースケース「設定を変える」の正常シナリオと「カスタムプリセットを足す」の E2E を、実機のマイクを開かずに流せる形で置く。

## 背景

[Issue #77](https://github.com/shuhei1101/voice-paste/issues/77) の依頼。
作業 PR [#76](https://github.com/shuhei1101/voice-paste/pull/76)（[Issue #75](https://github.com/shuhei1101/voice-paste/issues/75)）の要件.md の `## スコープ外` から切り出した。

- 2 つのシナリオは変えた設定で録音を始めて実機のマイクを開くため、[#65](https://github.com/shuhei1101/voice-paste/issues/65)（[#66](https://github.com/shuhei1101/voice-paste/pull/66)）で E2E を外したままになっている（シナリオ『設定を変える』の補足『E2E のテスト』。2 つのシナリオは `test` を持たない）
- #76 で、画面・トレイの E2E は常駐アプリを pytest のプロセスの中で `main()` から起動し、Qt のイベントで操作する形（`tests/support/resident_app.py`）になり、ホットキーの受付も差し替えて登録された関数を呼べる
- 複合ユースケースの E2E（`tests/support/inprocess.py`）は、録音の入力を WAV を流すものに差し替えてマイクを開かずに流している
