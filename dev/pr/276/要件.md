# 要件

## 要望

develop から、今ある E2E のテストと、E2E だけが使用する部品を削除する。
終わりの条件は次のとおり。

- `tests/e2e/` が無い
- `tests/support/` に、E2E だけが import する・起動するモジュールと関数が残っていない（非機能要件テスト・結合テスト・開発コマンドが使用するものは残す）
- 設計書・手順で、削除した E2E のファイル・レイヤー・実行方法を指す記述が残っていない（シナリオと、その `test_file` は残す）
- 単体テストと結合テストが全 pass し、設計書の検証（`ai_monitor.design_docs validate`）が通る

`未確定`: テスト実行方法の『E2E テスト』のレイヤーの扱い（決める工程: ドキュメント修正のレビュー）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | レイヤーを削除し、非機能要件テストのレイヤーが参照している前提（Linux の環境・Open JTalk・VM での実行方法）を非機能要件テストのレイヤーへ移す | 実行できない E2E の実行方法が残らない | 作り直すときにレイヤーを記載し直す |
| B | レイヤーを残し、`tests/e2e/` が無い間は実行しない旨だけを記載する | tester がリリースで参照するレイヤーの名前が残る | 今ある E2E の実行方法が古いまま残る |

推奨: A

古い実行方法が残ると、作り直すときに古い構造に引きずられる。
