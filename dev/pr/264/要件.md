# 要件

## 要望

文字起こしのエンジンに Haas-ja-v1.0（以下 Haas）を追加し、設定の `transcription.engine` で選べるようにする。

- Haas は WSL の中で動かす文字起こしのサーバーで実行し、Windows の常駐アプリは録音をサーバーへ HTTP で送信して、起こした文字を受け取る
- エンジンが Haas でサーバーへ接続できない環境では、faster-whisper（`local_whisper`）で文字に起こす
- ホットキー・トレイ・API の録音、連続録音の区間、外の端末のブラウザから送信した音声のどれも、選んだエンジンで起こす
- 表記のヒントの単語を、Haas の `haas_asr.Vocabulary`（表記 → 読みの組）へ指定する。文字起こしの後の用語集の補正は今と同じ
- 既定のエンジンは `local_whisper` のまま変えない
- 採用の判断: PoC 検証で、表記のヒントの単語を含む voice-paste の録音を Haas と faster-whisper で起こし、精度（CER）・速さ・表記のヒントの単語の認識を比べる。Haas が表記のヒントの単語の認識で faster-whisper より劣る場合は、続けるかをユーザーへ確認する

`未確定`: Vocabulary の読みの作り方（決める段: PoC 検証。表記のヒントに読みの欄を追加するかは、PoC の結果を添えてユーザーへ確認する）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 表記のヒントの単語ごとに読みを入力する欄を追加し、読みを Vocabulary へ指定する（PoC の V1） | 読みを指定したときの認識の精度を得られる | 設定と設定画面の範囲が広がり、ユーザーの入力が増える |
| B | 表記をそのまま読みとして Vocabulary へ指定する（PoC の V2） | 設定を増やさない | 読みを指定しない分、認識の精度が下がりうる |

推奨: B（暫定。PoC の結果で見直す）

V2 の表記のヒントの単語の正解率が V1 に近ければ、設定を増やさずに済む。

`未確定`: WSL の文字起こしのサーバーの起動方法（決める段: 単一ユースケース設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 常駐アプリが起動時に `wsl.exe` でサーバーを起動し、終了時に止める | ユーザーの操作が増えない。ショートカットからの起動だけで使用できる | WSL の起動とモデルの読み込みの分、常駐アプリの起動が遅くなる |
| B | ユーザーが WSL の中でサーバーを別に起動しておき（systemd 等）、常駐アプリは接続だけする | 常駐アプリの起動の流れを変えない | ユーザーがサーバーの起動を管理する必要がある |

推奨: A

今の常駐アプリはショートカットからの起動だけで文字起こしまで準備でき、文字起こしワーカーも常駐アプリが起動している。同じ流れに統一するほうが使い方が変わらない。

`未確定`: faster-whisper へ切り戻す単位（決める段: 単一ユースケース設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 常駐アプリの起動時にサーバーへの接続を確認し、接続できなければ終了まで faster-whisper で起こす | 文字起こしワーカーを起動するのは接続できないときだけで、GPU のメモリを二重に使用しない | 起動の後にサーバーが落ちたとき、その録音の文字起こしは失敗する |
| B | 録音ごとに Haas へ送信し、失敗したらその録音を faster-whisper で起こす | 起動の後にサーバーが落ちても、その録音を起こせる | 切り戻しに備えて文字起こしワーカーも起動しておくため、GPU のメモリを両方のモデルで使用する |

推奨: A

Issue の要望は「サーバーにつながらない環境では faster-whisper に戻る」で、環境の単位の切り戻しを求めている。起動の後の失敗は今のエンジンの失敗と同じく履歴に録音を残して通知する。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| 既定のエンジンを Haas にする | WSL と NVIDIA GPU が無い環境では動かないため、既定は `local_whisper` のままにする | 予定なし |
| Haas の低遅延のストリーミング | 連続録音も区間を区切ってから起こすため、オフラインの書き起こしで足りる | 予定なし |
| Docker の Linux で Haas を動かす | 要望は WSL の環境で使用できること | 予定なし |
| Linux（Ubuntu）の常駐アプリから Haas を使用する | 判断: 今回は Windows の常駐アプリと WSL に限る。Linux の常駐アプリは同じサーバーを WSL を通さずに起動すれば使用できる見込みだが、今回の方針が決まらないと中身が決まらない。検証の VM には NVIDIA GPU が無い | 起票予定 |
