## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 出力先の登録 | `features/outputs/` に出力先のサブフォルダを足して `OutputFn` を満たす関数を置き、`OUTPUTS` に 1 行登録する。ほかの出力先のサブフォルダは import しない | ID と画面に出す名前はモジュール構成設計で決める |
| 送る処理 | 起こした文字を JSON にして送り先の URL へ POST し、2xx で届いたとする。リダイレクトは追わない。送り直さず、届かなければ `DeliveryError`。送り先のホストは制限しない | 送る中身・認証は要件の `未確定` |
| HTTP の送り方 | `callback/client.py` の `post_json` と同じ httpx の使い方にする。共有するか出力先ごとに持つかはモジュール構成設計で決める | 出力先どうしを import しない（品質シナリオ 5）ため、共有するなら `features/outputs` の外へ出す |
| 設定 | `outputs[]` にこの出力先のモデル（`id`・`enabled`（既定 `false`）・`hotkey`・送り先の URL（http か https））を足し、反映は `immediate` | 認証のヘッダーを持つなら秘密として扱う |
| 既存の設定の読み込み | `outputs` を書いた `settings.toml` を読んだとき、一覧に無い出力先を既定値で補う | 補わないと設定画面に出ず、オンにできない |
| 配線 | `main.py` の `_wire_outputs` にこの出力先の注入（POST する関数・送り先・タイムアウト）を足す。送り先は届けるたびに設定を読む関数で渡す | 確定のホットキーの登録は今の `build_hotkey_bindings` のまま効く |
| 画面 | 録音の画面の出力先の確定のボタンと、設定画面の出力先のまとまりに、今の並びのまま足す | 画面設計で欄を決める |
| エラー | 届けられなければ `DeliveryError` を送出し、セッションが `delivery_failed` を知らせて待機中へ戻す | 今の仕組みのまま |
| テスト | 単体は POST する関数を差し替えて、送る中身・2xx 以外・接続できないときを確かめる。結合は 127.0.0.1 のテスト用の受け口へ届くこと、オフのときと API の録音で送らないことを確かめる。画面の結合テストは確定のボタンと設定画面の欄を確かめる | E2E は単一ユースケース設計でシナリオに `test_file` を置いてから作る |
