## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| dev-docs.yaml | `documents[].schema.ref` の v8.3.0 の 19 行を `design-schemas/v9.2.0` へ書き換える | `source`・`path` は変えない |
| dev-docs.yaml の glossary の行 | `schema` をリポジトリの中の `schemas/glossary.schema.yaml` から knowledge の `design-schemas/v9.2.0` の `schemas/design/glossary.schema.yaml` へ書き換える | リポジトリの中のスキーマは、同じフォルダに無い `common.schema.yaml` を `$ref` で指しており、`design_docs validate` が解決できずに止まる。使わなくなった `schemas/glossary.schema.yaml` は削除し、`files.yml` の行と LAY-1 の `schemas` フォルダの要素・`schema` の中身の種類を外す |
| 設計書の refs の `to`・`item` | 文字列の `{ID}#{項目のパス}` を `#` で分け、前を `to`（空なら自分の `id`）、後を `item`（空なら記載しない）にする | 関連先は変えない |
| 設計書の refs の `type` | 判定フローチャート『関連の張り方』の q6 で決める。関連先が IF・NFR、関連先が LIB でモジュール構成・インターフェース定義から張る関連、関連先が SCR でモジュール構成から張る関連は `requires`（相手の決まりに従わずに実装すると違反になる）。それ以外は `references` | - |
| 設計書の refs の `when` | 関連先のタイトルと、`item` の先頭の項目の種類ごとの文型（関数は引数と戻り値、クラスはメソッドと属性、定数は値、設定は既定値と意味 など）で 1 文にする。`item` が無い関連は関連先の種類ごとの文型にする | - |
| MOD-50 の `data_models[HaasSettings].refs` | CFG-1 の `settings[transcription.haas.*]` を指す 13 件を、CFG-1 全体を指す 1 件にまとめ、`when` に 13 個のキーを並べる | v9.2.0 の `related` は 8 件が上限で、`properties` の要素は `refs` を持てない |
| 書き込みの手段 | refs の行だけを書き換えるスクリプトで書き換え、ほかの行とコメントは変えない | 設計書 100 件・関連 326 件と、`write_docs` へ 1 件ずつ渡すには量が多い |
| 確認 | 作業ブランチで `design_docs validate`（スキーマと関連の検査）と `design_docs publish` を実行し、どちらも終了の状態 0 で終わることを確かめてログを PR ドキュメントに置く | - |
