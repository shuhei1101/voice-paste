# 要件

## 要望

`haas_server/` の中を、マニフェスト（`pyproject.toml`・`uv.lock`）・起動スクリプト（`start.sh`）・コード（`__init__.py`・`main.py`・`app.py`・`audio.py`）に分けて配置する。
コードは knowledge の規約『pyproject.toml 標準テンプレート』の src レイアウトに合わせる。

動きは変えない。
次のものは変えない。

| 対象 | 今の値 |
| --- | --- |
| パッケージ名 | `haas_server`（`python -m haas_server.main {ポート}` で起動する） |
| 起動スクリプトが受ける引数 | 受けた引数を全て `haas_server.main` へ引き渡す |
| サーバーの環境の置き場所 | WSL の ext4 の `~/.local/share/voice-paste/haas_server/.venv` |
| ログの置き場所 | WSL の中の `~/.local/state/voice-paste/haas_server.log` |
| 単体・結合テストを実行する環境 | 常駐アプリと同じ `.venv` |

移したファイルを指す起動する側のパス（[src/voice_paste/integrations/haas/server.py](https://github.com/shuhei1101/voice-paste/blob/7d9ae053c7ce87a869492c465d3ada707cca6a6b/src/voice_paste/integrations/haas/server.py) の `HAAS_SERVER_DIR`）・テスト・`haas_server/files.yml`・`tests/files.yml`・`dev-docs.yaml`・設計書・公開ドキュメントを、移した後のパスに統一する。

`未確定`: `haas_server/` の中の分け方（決める工程: モジュール構成設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | コードを `haas_server/src/haas_server/` へ移し、マニフェスト・`start.sh`・`files.yml` は `haas_server/` の直下に配置したままにする | リポジトリの直下（`pyproject.toml`・`voice-paste.sh`・`src/`）と同じ構成になる | 直下にマニフェストと起動スクリプトが並ぶ |
| B | A に加えて、`start.sh` を `haas_server/scripts/start.sh` へ移す | 直下がマニフェストだけになる | knowledge の規約『フォルダ構成の切り方とレビュー』の「中身が 1 つだけのフォルダは作らない」に該当する |

推奨: A

プロジェクトの直下にマニフェストと起動スクリプトを配置し、コードを `src/` に分けるのはリポジトリの直下と同じ切り方で、1 ファイルだけのフォルダを作らずに済む。

`未確定`: 移した後のコードを import できるようにする方法（決める工程: モジュール構成設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `package = false` のまま、`start.sh` が `haas_server/src` へ移って `-m haas_server.main` を起動する。テストは常駐アプリの `.venv` の pytest に `haas_server/src` を import の検索先として加える | 利用者の WSL の環境を作り直さずに済む | import の検索先を起動スクリプトとテストの設定の 2 か所で持つ |
| B | `package = true` にして build backend を持たせ、サーバーの環境へ `haas_server` を editable で入れる | 環境に入ったパッケージを起動でき、`cd` が要らない | 利用者の WSL で環境を作り直す反映作業が要る。テストは A と同じ設定が要る |

推奨: A

要望は置き場所の整理で動きを変えないため、利用者の環境の作り直しを伴わない方法にする。
