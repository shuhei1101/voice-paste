### ヒントが 2 つ並ぶ原因の切り分け

`release/v0.3.0` の venv の `python.exe` で、最小のトレイのアイコンを出し、UI Automation でボタンの名前を読んだ（2026-10-05、Windows 11 Home 10.0.26200）。

| 出し方 | ボタンの名前 |
| --- | --- |
| `QSystemTrayIcon` にヒント A を付けてから `show()`、ヒントを B、C へ替える | `A` → `A B` → `A C` |
| `QSystemTrayIcon` をヒント無しで `show()` してからヒント A を付け、B、C へ替える | ` A` → ` B` → ` C` |
| Qt を通さず `Shell_NotifyIcon` の `NIM_ADD`（ヒント A）・`NIM_MODIFY`（ヒント B） | `A` → `A B` |
| 1 つのプロセスから `Shell_NotifyIcon` で 2 つのアイコン（ヒント A・X）を出す | ボタンが 2 つ（`X`・`A`） |

Windows は、ボタンの名前を「アイコンを出した時点のヒント」と「今のヒント」を空白でつないで作る。
同じ実行ファイルのアイコンでもボタンはアイコンごとに分かれ、1 つのボタンに並ぶのは 1 つのアイコンの新旧のヒントだけ。
普段使いの `pythonw.exe`（develop の venv）1 つだけのタスクバーのボタンも `voice-paste: 準備中 voice-paste: 待機中` だった。

## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| トレイのアイコンのボタン | `Uia` は、名前が `voice-paste:` で始まるボタンを 1 つのアイコンとみなす（名前に含まれる `voice-paste:` の数では絞らない）。`tray_icon_buttons` もこの形で並べる | `own_tray_icon` はこの候補を右クリックしてメニューで見分ける今の形のまま |
| トレイの状態の読み取り | ボタンの名前を `voice-paste:` で区切り、最後のヒントをそのアイコンの今の状態とする。`tray_tooltips` はアイコンごとに今の状態を 1 つ返す | 起動の前のヒントを除く `AppDriver._own_tooltips` の数え方は、アイコンごとに 1 つになる今の状態の並びで保つ |
| 起動の前の確認 | `start_app` の確認は、タスクバーで読めても隠れたアイコンの一覧を開いて読み、両方の今の状態を合わせて見る | 一覧を開いたときは、閉じて開く前の前面のウィンドウへ戻す（#58 の形を保つ）。`wait_tray_state` の待ちの間の読み方は、タスクバーで読めないときだけ一覧を開く今の形のまま |
| 常駐アプリ | 変えない | アイコンを出す前にヒントを付けない形は、要件.md の `## スコープ外` |
| 既存機能への影響 | `python.exe` が `IsPromoted=0` の環境で、Issue #59 で fail した 3 件と、要件.md の `実行のみ` の行の E2E がトレイの状態を読めないことでは fail・skip しない | ヒントが 1 つだけのボタンの読み方は変わらない（最後のヒント = 唯一のヒント） |
