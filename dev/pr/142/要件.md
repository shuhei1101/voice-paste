# 要件

## 要望

リポジトリの直下に `.gitattributes` を足し、改行コードを git の属性で決める（Windows の git と WSL の git の `core.autocrlf` には頼らない）。

- テキストのファイルは `* text=auto eol=lf` にし、Windows の git（`core.autocrlf=true`）でも WSL の git でも作業ツリーへ LF で書き出す
- `*.bat` は `text eol=crlf` にし、作業ツリーへ CRLF で書き出す（cmd.exe が読むファイルのため）
- 既にあるファイルの正規化（`git add --renormalize`）はしない。index に CRLF を含むファイルは `text=auto` の下で変換されず、改行コードの差として出ない
- 基準: master へ入った後、普段使いのクローンで次の 3 つが成り立つ
  - `git status --short` が `.claude/` 以外を出さない
  - `git ls-files --eol` で作業ツリーが CRLF（`w/crlf`）のファイルが `.bat` だけになる
  - Windows の git で書き出した後も、WSL の git の `git merge --ff-only origin/master` が改行コードだけの差で止まらない

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| `pyproject.toml` の改行の混在（CRLF と LF）を LF に揃える | 正規化をしないため混在は残る。1 ファイルの改行を揃える不具合で、`.gitattributes` が無くても同じ内容で成り立つ | [#140](https://github.com/shuhei1101/voice-paste/issues/140) |
| `dev/pr/` の下のテスト結果のログの改行の混在を揃える | テストランナーの出力をそのまま残した過去の記録で、揃えると記録を一括で書き換える。`text=auto` の下では改行コードの差として出ない | 予定なし |
| Windows の git と WSL の git の `core.autocrlf` を揃える | `.gitattributes` の属性が `core.autocrlf` より優先し、ユーザーの環境の設定を変えずに済む | 予定なし |
