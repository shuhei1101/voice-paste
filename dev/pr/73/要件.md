# 要件

## 要望

前のケースの常駐アプリのトレイのアイコンが隠れたアイコンの一覧に残っていても、画面・トレイの E2E が、この常駐アプリのアイコンを選んでトレイのメニューを開けるようにする。

- `AppDriver.own_tray_icon` が、前のケースで強制終了した常駐アプリ・トレイの「終了」で終わった常駐アプリのアイコンが一覧に残っていても、この常駐アプリのアイコンを返す
- 候補のアイコンを右クリックしてメニューを閉じた後に一覧が閉じても、残りの候補を試せる
- 自分のアイコンの探し方を、隠れたアイコンの一覧が開いたままであることに頼らない形に見直す（同じ範囲を直し続けているため。判定は `## 変更箇所の由来`）
- 着手時に、fail した時点の一覧の中身（ボタンの数と名前・一覧が開いているか）を読み、上の見立て（右クリックとメニューを閉じる操作で一覧が閉じる）を確かめてから直し方を決める
- `python.exe` のアイコンが隠れたアイコンの一覧に入る環境で、単一ユースケース「トレイから操作する」の E2E を全件の実行と同じ順で流したとき、Issue #70 で fail した `test_normal_when_quit`・`test_normal_when_quit_with_unsaved_settings[ctrl_break]`・`test_normal_when_quit_with_unsaved_settings[tray_quit]` と、下の表の `実行のみ` の行の E2E が、`この常駐アプリのトレイのアイコンが見つからない` では fail しない

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| トレイのメニューを実機で操作する E2E を、リリースの条件から外す | 要件を変えるため、ユーザーの判断が要る（規約『ユーザー確認が必須な事項』）。#54・#59・#63・#69 に続く実機のトレイの E2E の不備で、ユーザーは #65 でマイクの E2E を外している。今の判断は、着手時の切り分けで残ったアイコンがあると安定して選べないと分かったときだけユーザーへ確かめ、選べる形にできるなら外さない | 判断と理由を書いてレビューで確定する |
| 常駐アプリのトレイのアイコンに、テストで起動した常駐アプリと見分ける印を付ける | 要望は E2E の支えのコードの探し方で、常駐アプリを変えない（`type:test`） | 予定なし |
| トレイのボタンの名前に起動時の「準備中」のヒントが残ること | 常駐アプリのヒントの付け方で、自分のアイコンを選ぶ処理とは別の事象 | [#62](https://github.com/shuhei1101/voice-paste/issues/62) |
