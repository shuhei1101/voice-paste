# 要件

## 要望

文字起こしのエンジンが OpenAI API のとき、常駐アプリは OpenAI API への要求に、応答と接続を待つ時間の上限を設けない。

- `transcriber.py` の定数 `OPENAI_TIMEOUT_SEC`・`OPENAI_CONNECT_TIMEOUT_SEC` と、それを使う `httpx.Timeout` を削除する
- `httpx.Client` には `timeout=None` を明示して渡す（引数を削除するだけだと httpx の既定の 5 秒が掛かり、長い録音の文字起こしが失敗する）
- 再送（回数 2 回・間隔の基数 0.5 秒・待ちの上限 8 秒）と、再送の対象（429・500 以上・`httpx.TimeoutException`・`httpx.TransportError`）は変えない
- 非機能要件の項目『OpenAIの文字起こしのタイムアウトと再送』は名前を変えず、決定値・根拠・内訳を、アプリ側ではタイムアウトを設けない内容へ書き換える（項目名を変えないため、項目を参照するアーキテクチャ図・モジュール構成の参照は変えない）

## 変更箇所の由来

| 対象箇所 | commit | 目的 | 変更回数 | 影響 |
| --- | --- | --- | --- | --- |
| `transcriber.py` の `OPENAI_TIMEOUT_SEC`（600.0）・`OPENAI_CONNECT_TIMEOUT_SEC`（5.0） | [d31f0497](https://github.com/shuhei1101/voice-paste/commit/d31f04971f2d6ad3533114909c8af81f1e420b89)（`文字起こしのエンジンに OpenAI API を追加し、faster-whisper・nvidia-* を入れなくても使えるようにする (#204)`） | 下流（OpenAI API）の実測が無いため、公開仕様の値として公式の SDK の既定値を置いた（検証済みの値ではない。実測での見直しは #209 に回していた） | 1 回 | 定数を外して上限を設けない直し方は、ユーザーの判断で値を決める目的そのものが無くなったため、目的と衝突しない。同じ commit で入った再送の定数は変えない |

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| OpenAI API の再送の回数・間隔の見直し | 要望は再送の決定値を変えない | 予定なし |
| 呼び出し元へ返す・設定のエンドポイントへ送信するときのタイムアウト | OpenAI API の文字起こしとは別の要求で、要望に含まれない | 予定なし |
| モジュール構成『外部連携』を物理ファイルごとの設計書へ分ける | 今の Schema の検査（1 設計書 = 1 物理ファイル）を満たさず、書くツールで書けないため、この PR では YAML を直接編集した。分割は要望に含まれない | #240 |
