# 要件

## 要望

Ubuntu の Wayland のセッションで、ホットキーで録音を始め、起こした文字をアクティブなアプリへ貼り付けられる。
Windows と Ubuntu の Xorg のセッションの動きは変えない。

- セッションの種類で実装を選ぶ
  - Linux では、起動したときのセッションの種類（`XDG_SESSION_TYPE` が `wayland` か）で、ホットキーの受付・キーの送信・クリップボードの実装を選ぶ
  - 選ぶのは `main.py` の配線だけにし、各モジュールはセッションの種類を見ない
- ホットキー
  - Wayland のセッションでも、設定のホットキー（録音開始・一時停止・取り消し・出力先ごとのホットキー）で操作できる
- 貼り付け
  - Wayland のセッションで、ネイティブの Wayland のアプリ（GNOME のテキストエディター 等）と XWayland のアプリの両方へ、設定の貼り付けのキーで貼り付けられる
  - 貼り付けて送信の Enter も送信できる
  - クリップボードへ書けて、「コピーのみ」で書いた文字を Wayland のアプリで貼り付けられる
- 画面
  - 録音の画面・文字起こし中の表示・トレイ・設定画面が、Wayland のセッションでも表示され、操作できる
- 確かめ方
  - 検証環境の VM（`voice-paste-ubuntu`）を Wayland のセッションで起動し、起動の手段から起動 → ホットキーで録音 → 文字起こし → 貼り付けまでを通す
  - 確かめた結果は、VM の画面のスクリーンショットを PR ドキュメントに残す
- 手順
  - `docs/使い方/起動と設定.md` の Linux の節に、Wayland のセッションで入れる OS のパッケージと、要る設定（権限・ショートカットの登録 等）を記載する

`未確定`: 対象にする Ubuntu のバージョン（決める段: PoC 検証）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | Ubuntu 24.04（GNOME 46）の Wayland を対象にし、25.10 以降でも同じ方法で動く方法を選ぶ | 今の検証環境の VM で確かめられる。動作環境（非機能要件『動作環境』）の Ubuntu 24.04 と揃う | 24.04 の GNOME の portal に GlobalShortcuts が無いため、ホットキーの方法が限られる |
| B | Ubuntu 25.10 以降（Wayland だけ）を対象にする | portal の GlobalShortcuts を使える見込みがある | 検証環境の VM を作り直す必要がある。24.04 の Wayland では動かない |

推奨: A

動作環境の Ubuntu 24.04 は Wayland が既定で、Xorg を選ばない利用者がまず当たる。
24.04 と 25.10 以降の両方で動く方法（下のホットキーの案 A）があり、VM を作り直さずに確かめられる。

`未確定`: Wayland のホットキーの受け方（決める段: PoC 検証）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | GNOME のカスタムショートカットにコマンドを登録し、コマンドが動いている常駐サービスへ操作（録音開始・一時停止・取り消し・出力先を選んでの確定）を伝える | GNOME 46 でも使え、portal に依らない | 利用者が GNOME の設定でショートカットを登録する（設定のホットキーを変えたら登録し直す）。常駐サービスへ操作を伝える受け口が要る |
| B | XDG Desktop Portal の GlobalShortcuts でホットキーを登録する | 設定のホットキーをアプリが登録できる | 24.04 の GNOME の portal に無い（`gnome.portal` の `Interfaces` に `GlobalShortcuts` が無い）。初回に許可のダイアログが出る |
| C | `/dev/input` のキーボードのイベントを evdev で読む | デスクトップ環境に依らない | `input` グループへの追加が要り、全てのキー入力を読める権限をアプリに渡す |

推奨: A

対象の 24.04 で動く方法は A と C だけで、C は全てのキー入力を読める権限を常駐サービスへ渡すことになる。
A の操作を伝える受け口は、#196 で作った単一インスタンスのしくみか、既にある API の上に置けるかを PoC で確かめる。

`未確定`: Wayland のキーの送信の方法（決める段: PoC 検証）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | uinput（`ydotool` か、pynput の uinput のバックエンド）で仮想のキーボードからキーを送信する | 起動のたびの確認が無い。ネイティブの Wayland のアプリにも届く | `/dev/uinput` の権限（udev の規則と `input` グループへの追加）を利用者が sudo で設定する |
| B | portal の RemoteDesktop でキーを送信する | sudo が要らない | 許可のダイアログが出る（起動のたびか、復元のトークンを持つ間は初回だけ）。GNOME の画面の共有の表示が出続ける |

推奨: A

貼り付けは録音のたびに行うため、ダイアログや共有中の表示が出続ける B は使い勝手が悪い。
A の権限の設定は 1 回で済み、手順のページに記載できる。
権限の設定はユーザーの操作が要るため、承認確認でユーザーへ確かめる。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| Wayland のセッションで、端末アプリへの貼り付けを Ctrl+Shift+V に替えること | スコープに含めるか判断が分かれる。Xorg では `python-xlib` でアクティブなウィンドウの WM_CLASS を読んで端末アプリを見分けているが、GNOME の Wayland にはアクティブなウィンドウを読む標準のインターフェースが無い。Issue の要望は貼り付けまでで、端末アプリは求めていない。含めない判断にし、レビューで確定する | 起票予定 |
| Linux での E2E の自動の実行 | 別の Issue の範囲 | [#219](https://github.com/shuhei1101/voice-paste/issues/219) |
| GNOME 以外のデスクトップ環境（KDE Plasma 等）の Wayland | 対応する Linux は Ubuntu の GNOME（非機能要件『動作環境』） | 予定なし |
