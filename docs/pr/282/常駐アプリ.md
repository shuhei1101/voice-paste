## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 図 | 本文の Mermaid の図を、規約『表し方の優先順位』の伝えるものと図の種類の表で選んだ mdmark の部品で描く。図の中のラベルに内部の ID を出さない | Schema が図をデータで持つ項目（`x-shape: diagram`）は、その項目へ移す |
| 表 | 同じ属性を持つ項目が 2 件以上ある文・箇条書きを表にする | 6 行以上の表は `<!-- table: data -->` で囲む |
| 文 | 見出し・図・表と重なる文、既出の言い直し、理由の説明を削除する。残す文の NG の単語を対応表の OK の単語へ修正する | 業務の流れ・入出力・値は変えない |
| タグ | `files.yml` で持つ文書に `action:`・`topic:`・`tool:` のタグを付ける | 付ける前に `group_by: tags` で knowledge の既存のタグを再利用する。YAML の設計書は今の Schema がキーを持たないため、ai-monitor#3188 の後に別の Issue で付ける |
| description | `files.yml` で持つ文書の `description` を「何を定め、どんなときに参照するか」の 1 文にする | YAML の設計書はタグと同じく別の Issue で行う |
| エイリアスと用語 | 判定フローチャート『エイリアスの登録』『用語の登録』で判定し、`aliases` と用語集へ登録する | - |
| 本文に出さないもの | 検討事項の ID は関連のキーへ、生の Issue 番号・文書のパスはタイトル付きのリンクへ移す | - |
| 関連 | `src/files.yml`・`haas_server/files.yml`・`tests/files.yml` を作り、`dev-docs.yaml` に配信する行を追加する。コードの行からモジュール構成へ `implements`、テストの行からコードへ `tests` を張る | モジュール構成の `container`・`test_files` の対応から張る |
| 既存機能への影響 | `src/`・`tests/` は変えない | - |
