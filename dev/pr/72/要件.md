# 要件

## 要望

単一ユースケース「常駐アプリを起動する」の E2E の `test_error_when_engine_unavailable`・`test_error_when_api_unavailable` が、シナリオの期待値「トレイで起動に失敗したことが知らされている」「トレイで API を使えないことが知らされている」を確かめて pass する。

- E2E は、通知センターに残っているかを確かめない
- `test_error_when_api_unavailable` は、常駐アプリのログの「ユーザーへの知らせ（api_unavailable…）」（`AppDriver.notified`）で知らせを出したことを確かめる
- `test_error_when_engine_unavailable` は、トレイが失敗のアイコンになったこと（`wait_tray_state(FAILED)`）と起動に失敗した理由のログで確かめる。エンジンを準備できない経路は `tray.show_failure` を直接呼び、「ユーザーへの知らせ」のログを書かないため、通知を出す処理は結合テスト `test_tray_notification_when_startup_failed` が確かめる
- 2 件が、release PR [#52](https://github.com/shuhei1101/voice-paste/pull/52) の E2E の全件の実行で pass する
- 画面設計『トレイの通知』と単一ユースケース『録音を文字に起こす』を、通知が通知センターに残らない今の動きに合わせる。畳まれた後はトレイのメニューの「ログフォルダを開く」から理由を見る

実機の切り分けの結果（[常駐アプリ](./常駐アプリ.md) の `## 切り分けの結果`）、通知は画面にトーストとして出るが、通知センターには残らない。
起動の失敗・API を使えない知らせは常駐アプリの不具合ではなく、`type:test` のまま進める。
