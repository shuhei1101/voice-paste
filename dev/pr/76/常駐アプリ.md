## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 常駐アプリの起こし方 | 単一インスタンスの入れ替わり以外のケースは、pytest のプロセスの中で `main()` から起動する（`--data-dir` の一時フォルダ、Qt は offscreen）。`exec_loop` に、イベントループを回しながらケースの操作を進める関数を渡す。`main()` が入れる SIGINT・SIGBREAK のハンドラとルートロガーのハンドラ・レベルは、ケースの後にフィクスチャの後始末で元に戻す | 入れ替わりのケースと再起動の後の新しいプロセスは別プロセス（Qt は offscreen）で、操作をしない |
| 操作の渡し方 | トレイのメニューは項目（`menu_settings` など）の `QAction` を trigger し、設定画面のまとまりのメニュー・欄・ボタンは QTest のクリックとキーで渡す。ホットキーの受付（`HotkeyListener`）は差し替え、登録された関数を呼んで押された体にする | マウスカーソルを動かさず、キーの押下を合成しない |
| トレイの状態の読み方 | トレイのアイコンのヒントの文字（`voice-paste: 待機中` など）を、プロセスの中のトレイから読む | Windows のシェルのトレイは読まない（[要件](./要件.md) の `## 要望`） |
| フォルダを開く・再起動・終了の確かめ | フォルダを開くは開く呼び出しを差し替えて渡されたパス、終了は `main()` が戻ったこと・戻り値（0）・トレイのアイコンが出ていない状態・文字起こしワーカーの子プロセスが残っていないこと、再起動は前の `main()` が戻り、別プロセスの新しい常駐アプリが待機中になったことをログとトークンのファイルで確かめる | Ctrl+Break は `signal.raise_signal(signal.SIGBREAK)` で自分のプロセスの中で上げる（`os.kill` の `CTRL_BREAK_EVENT` は同じコンソールのプロセスグループ全体に届くことがあるため使わない） |
| 起動の失敗のケースの録音開始 | 差し替えたホットキーの受付が始まっていないこと（登録された関数が無いこと）で、押しても録音が始まらないことを確かめる | - |
| `tests/support/` | 使われなくなった関数（`click`・`type_keys`・`press_hotkey`・`force_foreground`・`open_notification_center`・`Uia.click_center` など）を消す | `inprocess.py` が使う関数は残す |
| シナリオ | 単一ユースケース 3 つの全シナリオの Mock の行を、差し替える操作と観測に書き換える | シナリオの流れと期待値は変えない |
| テスト実行方法・外部ライブラリ | 上の変更に合わせて、E2E の前提と pywin32 の一覧を書き換える | [要件](./要件.md) の `## 更新ドキュメント` |
| 常駐アプリ（`src/`） | 変えない | 差し込みの口を足す案になったときは、`type:*` と見積もりを見直し、モジュール構成設計で扱う |
