# 要件

## 要望

外の端末のブラウザの画面（`/web`）で、音声を送信する前に、補正に使う用語集のプリセットを 1 つ選択できる。
選択の候補は、設定の用語集のプリセットの一覧（設定画面の「用語集のプリセット」と同じ名前と並び）にする。
画面は、開いたときに常駐アプリから用語集のプリセットの一覧を取得する。
選択しないときは、設定で選んでいるプリセット（`active_glossary_preset`）で補正する。

送信した音声（録音・ファイル送信・再送信のどれも）は、送信した時点で選択していたプリセットで補正する。
送信の後に設定で選ぶプリセットを変えても、そのジョブは送信時に選択したプリセットで補正する（API の `POST /sessions` の指定と揃える）。
ブラウザの音声を受け取る API（`POST /web/transcriptions`）は、プリセットの名前を任意で受ける。
一覧に無い名前は受け付けずに 400 で返す（`POST /sessions` と揃える）。

指定しない今の呼び出しは、補正の結果が変わらない。

選択欄のラベルは「用語集のプリセット」とし、選択しないときの既定は「設定に従う（{設定で選んでいるプリセットの名前}）」の項目を先頭に置いて表す（モック作成でユーザーと決定。[確認ログ](./確認ログ.md)）。

選択は端末（ブラウザ）に覚え、画面を開き直したときに戻す。覚えた名前が一覧に無いときは既定に戻す（画面設計でユーザーと決定。[確認ログ](./確認ログ.md)）。

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| 結果の一覧に、補正に使ったプリセットの名前を表示する | 要望に含まれない | 予定なし |
| ルール案内のフックが、リポジトリ直下の `rules.yaml`（存在しない）を読んで FileNotFoundError を出す | AI Monitor のルール案内の仕組みの不具合で、今回の要望に含まれない | [shuhei1101/ai-monitor#2942](https://github.com/shuhei1101/ai-monitor/issues/2942) |
