## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| WAV の書き出し | `synthesize_speech` を OS で分け、Windows は SAPI のまま、Linux は PoC 検証で決めた音声合成で 16 kHz・モノラル・16 bit の WAV を書き出す | 音声合成の手段は `未確定`（[要件](./要件.md)） |
| ブラウザーの起動 | `launch_edge` の実行ファイルを OS で分け、Linux は PoC 検証で決めたブラウザーの実行ファイルを使う。起動の引数（headless・`--use-file-for-fake-audio-capture`）と DevTools Protocol の操作は変えない | ブラウザーは `未確定`（[要件](./要件.md)） |
| プロセスの一覧と終了 | `process_table` と `kill_tree` を OS で分け、Linux は `/proc` から番号・親・コマンドラインを読み、子孫へ SIGKILL を送る。`inprocess.py` の Toolhelp の snapshot も Linux では `/proc` から読む | Windows の動きは変えない |
| SIGBREAK | Ctrl+Break のケースは Linux では skip し、後片付けで戻すハンドラは、その OS にあるシグナルだけにする | `signal.SIGBREAK` は Windows にだけある |
| 文字起こしの待ちの上限 | Linux の既定（CPU・int8）で起こすため、E2E の待ちの上限が足りるかを PoC 検証で測る | 足りなければ OS で上限を分ける。値は規約『資源の値の決め方』で導く |
| 実行の前提 | Linux は Xorg のセッションで流す（クリップボードの `xclip` が `DISPLAY` を要る）。Qt は今と同じ offscreen | |

## PoC 結果

結論: 音声合成・プロセスの扱い・待ちの上限は成立。
外の端末の画面のケースは、Linux では常駐アプリがブラウザーの文字起こしを持たないため不成立で、要件の見直しが要る（PoC PR [#242](https://github.com/shuhei1101/voice-paste/pull/242)）。

| 成功条件 | 実測 | 判定 |
| --- | --- | --- |
| Open JTalk の WAV を起こした文字に期待する言葉が含まれる | `SPEECH_TEXT`・`THREE_SENTENCES`・`LONG_READING` の 17 文の全てで含まれる（CPU・int8 の large-v3 で 1 文 8.3〜10.6 秒） | 成立 |
| 読み上げの長さの前提 | `LONG_READING` を 0.4 秒の間で並べて 33.45 秒（`MAX_SEGMENT_SEC` の 20 秒を超える）。`long_reading_texts` を 0.4 秒の間・1 秒の頭で並べて 51.07 秒（45 秒以上） | 成立 |
| 待ちの上限（`PLAYED_OUT_TIMEOUT_SEC` 180 秒・`CONTINUOUS_END_TIMEOUT_SEC` 150 秒・`PROCESSED_TIMEOUT_SEC` 120 秒）に収まる | ケース全体で `test_paste_voice_text.py::test_normal` 13.4 秒、`test_transcribe_continuously_from_other_system.py::test_normal` 36.9 秒、同 `test_normal_when_speaking_without_pause` 78.5 秒、`test_record.py::test_normal_when_split_by_max_length` 82.3 秒 | 成立 |
| `/proc` でワーカーを探して止められる | `test_paste_voice_text.py::test_error_when_worker_dies_again` が pass | 成立 |
| 外の端末の画面のケースが Edge の Linux 版で pass する | `OS_UNAVAILABLE_FEATURES` が Linux で `WEB_TRANSCRIPTION` を外しており、`handlers.web_api` が `None` で `start_web_api` が `AttributeError` になる | 不成立 |

所見:

- `test_paste_voice_text.py` の `test_normal`・`test_normal_when_cancel` は、Linux で `LOWER_VOLUME` を外しているため音量の控えが空になり fail する。Linux では音量を下げないことを期待する形に分ける
- `run_resident_app` は API の待ち受けを待たずにケースを始めていた。Windows ではケースの前のワーカーの一覧（PowerShell）が遅いため表に出ず、Linux では `トークンのファイルが読めない` で fail した。トークンのファイルを待ってから始める
- VM のメモリの使用量の最大は約 3.9 GB。#214 の確認で自動起動にした常駐アプリ（ワーカーで約 1.7 GB）と同時に流すと OOM で止まる

最小再現コードの要点:

- 音声合成: [`_synthesize_open_jtalk`](https://github.com/shuhei1101/voice-paste/blob/7a3545ba1e1417cc668a63a37394a39fde391b29/tests/support/inprocess.py#L176-L191) がユーザーの配下（`~/.local/opt/open-jtalk`）の `open_jtalk` へ文を標準入力で渡し、48 kHz の WAV を 16 kHz へ変換する
- プロセス: [`_proc_table`](https://github.com/shuhei1101/voice-paste/blob/7a3545ba1e1417cc668a63a37394a39fde391b29/tests/support/processes.py#L26-L40) が `/proc/*/stat` の最後の `)` の後から親の番号を読む
- 確かめのスクリプト: [`poc/check_tts.py`](https://github.com/shuhei1101/voice-paste/blob/13c0d4cb4e0d59ecec2112160a8a6bf6c077318e/poc/check_tts.py)
- 起動の待ちと後片付け: [7a3545b](https://github.com/shuhei1101/voice-paste/commit/7a3545ba1e1417cc668a63a37394a39fde391b29)
