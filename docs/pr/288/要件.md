# 要件

## 要望

| 要件 | 終わりの条件 |
| --- | --- |
| 開始の直後の取り消しの猶予 | ホットキー・トレイで録音を始めてから猶予の秒数の間に取り消すと、録音の画面だけがすぐ閉じ、録音は内部で続く。始めてから猶予の秒数が経った時点で、内部で録音を捨てて待機中に戻る |
| 猶予の間のほかの操作 | 猶予の間は、取り消した録音を確定する操作（出力先・カスタムプリセットのホットキー、録音開始と同じホットキーの出力先での確定）・一時停止のホットキー・録音の画面を戻す操作（トレイの「録音の画面を表示」・アイコンの左クリック）を受け付けず、取り消した録音は確定も一時停止もされない |
| 猶予の間の再起動・終了 | 猶予の間に再起動・終了を選ぶと、猶予が終わるのを待たず、内部の録音を捨ててすぐ再起動・終了する |
| 猶予の後の取り消し | 始めてから猶予の秒数が経った後の取り消しは、今までどおりその場で録音を捨てて待機中に戻る |
| 猶予の秒数の設定 | 猶予の秒数を設定（`recording.cancel_grace_sec`。秒・0 以上・既定 5。0 は猶予を持たずすぐ捨てる）で変えられ、設定画面の録音のまとまりに並ぶ |
| 取り消しで画面のスレッドを止めない | 取り消し・録音を捨てる処理は毎回新しいスレッドで動き、画面のスレッドはその終わりを待たない |
| 終了の処理の間に録音を始められない理由を示す | 確定の後の終了の処理の間に、トレイかホットキーで録音を始めようとした利用者に、終了の処理中で今は録音を始められないことが示される |
| 回帰のテスト | 猶予の間の取り消し・猶予の後の取り消し・猶予が終わったときの内部の取り消し・猶予の間のほかの操作・猶予の間の再起動と終了・終了の処理の間の開始を、単体テストか結合テストで確認する |

「取り消し」のボタンは、ホットキーの表示のために残す（利用者の判断）。

開始の直後の取り消しで固まる事象の再現と原因の特定は行わない（利用者の判断。調べた範囲は計画書『常駐アプリ』の `## 変更方針`）。

終了の処理の間に録音を始める操作を受けたら、処理中のダイアログで理由を示す（[確認ログ](./確認ログ.yaml)）。
本文は「前の録音を文字に起こして届けています。終わってから、もう一度録音開始のホットキーを押してください。」にする。

`未確定`: 猶予の間（画面を閉じ、内部ではまだ録音している間）にもう一度録音開始を押したときの動き（決める段: レビューの後、利用者に確認する）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 内部で続いている録音を引き継ぎ、それまでに貯めた音を捨てて経過時間を 0 に戻し、録音の画面を開き直す（マイクを閉じて開き直さない） | 開始の直後にマイクを閉じる・開く処理が起きない。録音セッションを 2 つ同時に持たない | 内部では前の録音セッションの続きになる（ログの録音セッションの ID が同じ） |
| B | 内部で続いている録音をその場で捨ててから、新しい録音を始める | 録音セッションが毎回新しくなる | 開始の直後に捨てる処理が起き、猶予で起こさないようにしたい場面に近い |
| C | 内部で続いている録音は猶予が終わるまで残し、別に新しい録音を同時に始める | 前の録音の後始末と新しい録音が独立する | 録音セッションを同時に 1 つだけ持つ今の作りを変え、マイクを 2 つ同時に開く |

推奨: A

録音の画面からは新しい録音に見え、内部ではマイクに触らずに済むため、開始と取り消しが重なる場面を作らずに済む。

`未確定`: 猶予の間に API の開始が届いたときの動き（決める段: レビューの後、利用者に確認する）

猶予の間の録音開始の案 A（内部の録音の引き継ぎ）は、入口・コールバック先・連続録音かが違う API の開始には適用できないため、別に決める。

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 内部の録音をその場で捨ててから、API の録音を始める | ほかのシステムの録音が、利用者の取り消しで断られない | 開始の直後に捨てる処理が起きる（API の開始のスレッドで起き、画面のスレッドは待たない） |
| B | 猶予が終わるまで、今までどおり処理中として断る（API はエラーを返す） | 録音セッションの扱いが今と同じ | 利用者が取り消してから最大で猶予の秒数の間、ほかのシステムの録音が断られる |

推奨: A

利用者からは取り消しが済んでいるため、その後に届いたほかのシステムの録音を断る理由が無い。捨てる処理は画面のスレッドの外で起きる。

`未確定`: 猶予を適用する取り消しの操作（決める段: レビューの後、利用者に確認する）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 録音の画面の「×」・「取り消し」のボタンと、取り消しのホットキーの全てに適用する | どの取り消しでも同じ動きになる | ホットキーで取り消したときも、猶予の間は内部で録音が続く |
| B | 録音の画面の「×」・「取り消し」のボタンだけに適用し、取り消しのホットキーは今までどおりすぐ捨てる | 変える範囲が録音の画面に閉じる | 操作によって内部の動きが変わる |

推奨: A

ホットキーの取り消しも、開始の直後に録音を捨てる処理を通る点は同じ。どの操作でも同じ動きにすると、猶予の秒数の設定の意味が 1 つに決まる。

`未確定`: 猶予の間のトレイの表示（決める段: レビューの後、利用者に確認する）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 取り消した時点でトレイを待機中のアイコンにし、「録音開始」も押せるようにする（押したときの動きは猶予の間の録音開始の `未確定` のとおり） | 利用者から見て、取り消しがすぐ終わったように見える | 内部ではマイクがまだ開いている（OS のマイクの使用中の表示は猶予の間だけ残る） |
| B | 猶予が終わるまで録音中のアイコンのままにし、「録音開始」も押せないままにする | 内部の状態と表示が一致する | 取り消したのに録音中の表示が数秒残り、取り消せていないように見える |

推奨: A

猶予は、利用者からは取り消しが済んだように見せる仕組みのため、表示も待機中にそろえる。
