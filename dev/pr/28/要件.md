# 要件

## 要望

- 作り直しの新しい構成の土台を、方針の記録（[構造の決定](https://github.com/shuhei1101/voice-paste/blob/develop/dev/pr/12/%E6%96%B9%E9%87%9D%E6%B1%BA%E3%82%81/4_%E6%A7%8B%E9%80%A0%E3%81%AE%E6%B1%BA%E5%AE%9A.md)・[リスクと移行計画](https://github.com/shuhei1101/voice-paste/blob/develop/dev/pr/12/%E6%96%B9%E9%87%9D%E6%B1%BA%E3%82%81/5_%E3%83%AA%E3%82%B9%E3%82%AF%E3%81%A8%E7%A7%BB%E8%A1%8C%E8%A8%88%E7%94%BB.md)）と、[#26](https://github.com/shuhei1101/voice-paste/pull/26) で起こしたモジュール構成のとおりに置く
  - レイアウト: `src/voice_paste/` の下に `main.py`・`shared/`・`features/`・`integrations/`・`runtime/`・`server/`・`ui/` を置き、`python -m voice_paste` で起動できる
  - 設定: `shared/settings.py` の設定のモデル（pydantic）で `settings.toml` を検証して読み、tomlkit でコメントを保ったまま書き戻す。無ければ既定値で作る
  - 置き場所: `shared/constants.py` の置き場所のパスを platformdirs で引き、開発用の置き場所を渡せる
  - ログ: `shared/logger.py` で標準の logging を日付ごとのファイルへ書き、保持期間を過ぎた日付のログだけを消す
  - 例外: `shared/errors.py` に例外の階層を置く
  - `.env` からの移行: `.env` を読むだけで改名も書き込みもせず、`.env.sample` の全キーを `settings.toml` のキーへ写す
  - 依存の検査: import-linter の契約（層・feature の独立・出力先の独立）を `pyproject.toml` に置き、検査が通る
  - 依存: 新しい構成が使う依存を `pyproject.toml` に全て書き、pycaw は `==` で固定する
- 完了の定義は、`src/voice_paste/` が起動でき、`.env` を読むだけで改名も書き込みもせずに開発用の置き場所の `settings.toml` へ移した設定を読め、import-linter の検査が通ること
- 普段使い（`voice_paste_legacy` と、リポジトリの直下の `.env`・`history/`・`log/`）には触れない
  - `voice-paste.bat` は `voice_paste_legacy` を起動したままにする
  - 普段使いの置き場所（`%APPDATA%\voice-paste\`・`%LOCALAPPDATA%\voice-paste\`）にも書かない
