## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 複合 UC シナリオ（ホットキー） | 声で入力した文字を貼り付けるを、常駐サービスのホットキーの受付 → 録音する → 録音を文字に起こす → 起こした文字を届けるの連鎖に書き換え、1 回だけ実行する起動の分岐を消す | 録音の取り消し・文字起こしの失敗・結果が空の分岐は残す |
| 複合 UC シナリオ（API） | ほかのシステムから録音を文字に起こすを新しく起こし、APIで録音を操作する → 録音する → 録音を文字に起こす → 起こした文字を届ける（呼び出し元のエンドポイントへ返す）の連鎖にする | 処理中の開始が 409 になる分岐を持つ |
| 単一 UC シナリオ | 要件.md の単一 UC ごとに、方針の記録の機能の扱い（作り直す・残す）とリスクの対策を正常・異常の分岐として書く | 今の振る舞いは [#10](https://github.com/shuhei1101/voice-paste/pull/10) のマージの版に残る |
| アーキテクチャ図 | 常駐アプリの役割を 1 つの常駐サービス（API のサーバー・画面とトレイ・ホットキー）へ書き換え、外部システムに API の呼び出し元を足す。制約を方針の制約（ショートカットから起動・ビルドしない・Python）に合わせる | 文字起こしワーカーの子プロセスは残す |
| 非機能要件 | 品質シナリオ 1〜7 を要件に足し、決定値を未確定、根拠に仮の値と [#15](https://github.com/shuhei1101/voice-paste/issues/15) で測ることを書く。対応 OS は方針の制約から埋める | 応答の測定をテストの条件・期待値に写す |
| インターフェース定義 | API の開始・停止・完了を 1 エンドポイント = 1 設計書で起こし、リクエスト・レスポンス・エラー応答（処理中は 409・守りに当たらない要求の拒否）と返送先の制限を書く | トークンの受け渡し方もここで決める |
| モジュール構成 | `src/voice_paste/` の `main.py`・`shared`・`features`（`session`・`recording`・`transcription`・`correction`・`outputs`・`history`）・`integrations`（`openai`・`volume`・`keyboard`）・`runtime`（`hotkey`）・`server`・`ui` を起こし、依存の向きと `features` どうしを import しないことを書く | `ui` は置き場所と `session` を呼ぶ境界だけを書き、画面の中身は [#21](https://github.com/shuhei1101/voice-paste/issues/21) で書く |
| 外部ライブラリ | モジュール構成が参照する FastAPI・uvicorn・httpx・PySide6・pydantic の設計書を、モジュール構成設計の段で起こして `verification` で動作確認する | tomlkit・platformdirs・import-linter は [#16](https://github.com/shuhei1101/voice-paste/issues/16) で起こす |
| 項目の状態 | 起こす項目は `status: planned` で置き、実装した移行の Issue が `implemented` にする | - |
