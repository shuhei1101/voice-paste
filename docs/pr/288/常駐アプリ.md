## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 原因の特定 | 開始の直後に取り消したときに、画面のスレッドがどこで止まるかを、ログと再現のテストで特定する | 録音セッションのロック・マイクの入力を閉じる処理・音量のフェードの待ち合わせを順に調べる。報告の時刻（2026-11-13 00:55〜00:58 JST）の常駐アプリのログでは、取り消しは全て「録音を捨てた」「録音を取り消した」まで警告なしで進んでおり、止まった箇所はログに出ていない |
| 開始と取り消しの重なり | 特定した原因に合わせて、取り消しが画面のスレッドを止めないようにする | `未確定`（[要件](./要件.md) の対策の案。決める段: モジュール構成設計） |
| 終了の処理の間の開始 | 終了の処理の間に録音を始める操作を受けたら、終了の処理中で今は録音を始められないことを示す | 処理中のダイアログで示す（[確認ログ](./確認ログ.yaml)） |
| 処理中のダイアログ | 断った理由（API の録音の処理中・終了の処理中）ごとに本文を分ける | 終了の処理中の本文は「前の録音を文字に起こして届けています。終わってから、もう一度録音開始のホットキーを押してください。」 |
| 回帰のテスト | `SessionManager` の単体テストに開始の直後の取り消しを、処理中のダイアログの結合テストに終了の処理中の本文を追加する | 音量のフェードとの重なりは E2E の差し替えでは起こせないため、原因の特定後に `SessionManager`・音量のアダプタの単体テストで確認する |
