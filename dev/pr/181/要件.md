# 要件

## 要望

起動のバッチファイル（`voice-paste.bat`）が、`.venv` の無い・使えないクローンでも常駐アプリを立て、環境を作れないときは失敗したことと理由をユーザーに示す。

- 起動のたびに、リポジトリの直下で `uv sync --frozen` を流して `.venv` を `uv.lock` に揃えてから、`.venv\Scripts\python.exe` で `voice_paste` を import できるかを確かめて起動する（`.venv` が無い・中途半端に残っている・依存が `uv.lock` とずれている状態を 1 つの経路で直す）
  - uv は PATH から探し、無ければ `%USERPROFILE%\.local\bin\uv.exe` を使う
  - uv が見つからないときは `uv sync --frozen` を飛ばし、import できれば起動する
  - `uv sync --frozen` を流す前に、コンソールに 1 行表示する
  - uv の出力は `launcher.log` に残す
- 次のときは起動せず、コンソールに失敗したことと理由（uv が見つからない・`uv sync` の終了コード・作り直しても import できない）と `launcher.log` の場所を表示し、`pause` で止まる。バッチファイルの終了コードは 0 以外にする
  - uv が見つからず、import もできない
  - `uv sync --frozen` が 0 以外で終わる
  - `uv sync --frozen` の後も import できない
- `.venv` が無いときにシステムの `pythonw` で起動する動きをやめる
- `.venv` で import できる今の起動（`.venv` を有効にし、CUDA の DLL を `PATH` に足して `.venv\Scripts\pythonw.exe -m voice_paste` を引数なしで起動する）は変えない
- 設計書『常駐アプリ / 起動と配線』のバッチファイルの記述と、使い方『起動と設定』の「環境を作る」「起動する」を合わせて修正する

- コンソールに出す理由は英語の `[ERROR]` で始まる 1 行にし、続けて `launcher.log` のパスを出す（文言は設計書『常駐アプリ / 起動と配線』の `directory`）

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| シナリオ『常駐アプリを起動する』へ、環境を作れないときの異常シナリオを追加する | バッチファイルは E2E が通らない場所で、常駐サービスが立つ前に止まる。シナリオに置くと、E2E にバッチファイルを流す仕組みが要る。追加せず、実装の工程で状態ごとにバッチファイルを手で流して確かめる | 予定なし |
| 普段使いのクローン（master）の `.venv` の作り直し | このバッチファイルが入れば、起動のときに自分で作り直す | 予定なし |
