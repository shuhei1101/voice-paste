## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| セッションの状態と排他 | `SessionManager` は `threading.Lock` の中で状態を確かめて書き換え、セッションが残っていれば入口を問わず `SessionBusyError` で開始を断る。確定後の流れはワーカースレッドで動かし、どの経路でも（finally）セッションを空にする | API・ホットキー・トレイ・上限のタイマーが別のスレッドから呼ぶ |
| 入口ごとの操作の分け | API のセッションには一時停止・再開・取り消しとホットキーの確定が来ても状態を変えない。ホットキー・トレイのセッションには session_id 付きの停止・完了を受けない | モジュール構成のとおり |
| 開始 | `POST /sessions` は返送先を確かめてから `SessionManager.start(entry="api")` を呼び、202 とセッションの ID を返す。マイクを開けなければ録音の開始が音量を戻し、セッションを作らずに 503 を返す | 録音の開始の失敗で音量を戻すのは [#32](https://github.com/shuhei1101/voice-paste/pull/32) の `Recorder` |
| 停止 | `POST /sessions/{session_id}/stop` は録音を止めて stopped にし、200 を返す。止めたセッションへの停止は何も変えずに 200 | - |
| 完了 | `POST /sessions/{session_id}/complete` は録音を履歴に保存してから 202 を返し、文字起こし → 補正 → 履歴への書き足し → 返送をワーカースレッドで行う | 録音を確定した時点で履歴に残す（品質シナリオ 4） |
| 返送 | `deliver` は入口が API なら `OUTPUTS` の呼び出し元へ返す出力先（`deliver_to_caller`）へ渡す。`deliver_to_caller` は `post_json`（httpx・リダイレクトを追わない）で `CallbackPayload`（セッションの ID・result・text・理由）を返送先へ POST し、一時的な失敗（5xx・408・429・タイムアウト・接続できない）だけを、Retry-After があればその秒数、無ければ指数バックオフ + フルジッターの間を置いて再送する。Retry-After が待ちの上限を超えるときと、ほかの 4xx は再送しない。タイムアウト・再送の回数・間隔の基数は非機能要件の決定値に従う。全て失敗したら ERROR のログに書いて終える | `OUTPUTS` は [#20](https://github.com/shuhei1101/voice-paste/issues/20) までは呼び出し元へ返す 1 行だけ |
| 返送先の確かめ | `is_callback_allowed` は返送先のホストが loopback（`127.0.0.1`・`::1`・`localhost`）か `api.allowed_callback_hosts` にあるときだけ許す。許さなければ `CallbackNotAllowedError`（400）で開始しない | - |
| 上限での打ち切り | `runtime/timer.py` の `RepeatingTimer` が 1 秒ごとに `truncate_if_expired` を呼び、上限時間を過ぎた API のセッションの録音を止めて履歴に残し、ロックを離してからワーカースレッドで返送先へ `truncated` を送る | 呼んだ関数が例外を出してもタイマーは止まらない |
| 要求の守り | `RequestGuardMiddleware` が Origin・Host・Authorization の順に確かめ、Origin 付きとほかの Host は 403、トークンが合わなければ 401 を返す。トークンは定数時間で比べ、ログに書かない | - |
| エラー返却 | `register_exception_handlers` が `CallbackNotAllowedError`・入力の検証の失敗 → 400、`SessionNotFoundError` → 404、`SessionBusyError` → 409、`MicrophoneUnavailableError` → 503、それ以外 → 500 を RFC 9457 の `application/problem+json` で返す | 入力の検証の失敗は FastAPI の既定の 422 でなく 400 |
| トークン | `create_token` が secrets で起動ごとのトークンを作り、待ち受けを始められた後にだけ `write_token_file` がポートと共に `token_file`（置き場所は `--data-dir` の下）へ書く。待ち受けに失敗した起動はファイルを書き換えない | 呼び出し元はこのファイルを読んで `Authorization: Bearer` に付ける |
| 待ち受け | `ApiServerRunner` が uvicorn を `127.0.0.1:{api.port}` で専用のスレッドに動かし、`started` が立つかスレッドが終わるまで待つ。立たなければ False を返す | uvicorn は待ち受けに失敗しても例外を出さずにスレッドを終える |
| 起動と配線 | `main.py` の `build_handlers` が設定から録音・文字起こし・補正・履歴・返送を組み立てて `SessionDeps` と `SessionManager` を作り、トークンを発行して API サーバーを起動する。待ち受けに失敗したら `api_unavailable` を知らせ、エンジンを止めて 1 を返す。起動できたら Ctrl+C・Ctrl+Break を待ち、新しい開始が来ないようにタイマー・API サーバーを先に止めてから録音を捨て、エンジンを止めて 0 を返す | 知らせの関数（`log_notify`）と終了の合図の待ち（`wait_for_shutdown_signal`）は、画面とトレイが入る [#21](https://github.com/shuhei1101/voice-paste/issues/21) までの実装で、#21 でトレイとイベントループに差し替える |
| 依存の向き | `features/session` はほかの feature を import せず、`SessionDeps` の関数型で受け取る。`server` は `features/session` の route を集めるだけ。import-linter の検査を通す | - |
| 性能 | 開始の応答が 500 ms 以内、処理中の開始への 409 が 1 秒以内。非機能要件テストで実機の HTTP の往復を含めて測る | 品質シナリオ 1・6 |
| セキュリティ | 127.0.0.1 以外で待ち受けない。トークン・API キーをログと応答に出さない | ブラウザからの DNS リバインディングと CSRF を Host と Origin で断る |
| 既存機能への影響 | `voice_paste_legacy`・`voice-paste.bat`・リポジトリの直下の `.env`・`history/`・`log/` を変えない | 並走の間の普段使い |
