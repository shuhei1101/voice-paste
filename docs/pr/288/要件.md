# 要件

## 要望

| 要件 | 終わりの条件 |
| --- | --- |
| 開始の直後の取り消しの猶予 | ホットキー・トレイで録音を始めてから猶予の秒数の間に取り消すと、録音の画面だけがすぐ閉じ、録音は内部で続く。始めてから猶予の秒数が経った時点で、内部で録音を捨てて待機中に戻る |
| 猶予の間のほかの操作 | 猶予の間は、取り消した録音を確定する操作（出力先・カスタムプリセットのホットキー、録音開始と同じホットキーの出力先での確定）・一時停止のホットキー・録音の画面を戻す操作（トレイの「録音の画面を表示」・アイコンの左クリック）を受け付けず、取り消した録音は確定も一時停止もされない |
| 猶予の間の再起動・終了 | 猶予の間に再起動・終了を選ぶと、猶予が終わるのを待たず、内部の録音を捨ててすぐ再起動・終了する |
| 猶予の後の取り消し | 始めてから猶予の秒数が経った後の取り消しは、今までどおりその場で録音を捨てて待機中に戻る |
| 猶予の秒数の設定 | 猶予の秒数を設定（`recording.cancel_grace_sec`。秒・0 以上・既定 5。0 は猶予を持たずすぐ捨てる）で変えられ、設定画面の録音のまとまりに並ぶ |
| 取り消しで画面のスレッドを止めない | 取り消し・録音を捨てる処理は毎回新しいスレッドで動き、画面のスレッドはその終わりを待たない |
| 終了の処理の間に録音を始められない理由を示す | 確定の後の終了の処理の間に、トレイかホットキーで録音を始めようとした利用者に、終了の処理中で今は録音を始められないことが示される |
| 回帰のテスト | 猶予の間の取り消し・猶予の後の取り消し・猶予が終わったときの内部の取り消し・猶予の間のほかの操作・猶予の間の再起動と終了・終了の処理の間の開始を、単体テストか結合テストで確認する |

「取り消し」のボタンは、ホットキーの表示のために残す（利用者の判断）。

開始の直後の取り消しで固まる事象の再現と原因の特定は行わない（利用者の判断。調べた範囲は計画書『常駐アプリ』の `## 変更方針`）。

終了の処理の間に録音を始める操作を受けたら、処理中のダイアログで理由を示す（[確認ログ](./確認ログ.yaml)）。
本文は「前の録音を文字に起こして届けています。終わってから、もう一度録音開始のホットキーを押してください。」にする。

猶予の扱いは次のとおりにする（[確認ログ](./確認ログ.yaml)）。

| 場面 | 動き |
| --- | --- |
| 猶予の間の録音開始 | 内部で続いている録音を引き継ぎ、貯めた音を捨てて経過時間を 0 に戻し、録音の画面を開き直す（マイクを閉じて開き直さない） |
| 猶予の間の API の開始 | 内部の録音をその場で捨ててから、API の録音を始める（捨てる処理は API の開始のスレッドで起き、画面のスレッドは待たない） |
| 猶予を適用する操作 | 録音の画面の「×」・「取り消し」のボタンと、取り消しのホットキーの全て |
| 猶予の間のトレイ | 取り消した時点で待機中のアイコンにし、「録音開始」も押せるようにする |
