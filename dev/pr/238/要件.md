# 要件

## 要望

Ubuntu 24.04 の Linux で見つかった不具合 4 件を修正する。
Windows の動きと表示は変えない。

| Issue | 終わりの条件 |
| --- | --- |
| [#217](https://github.com/shuhei1101/voice-paste/issues/217) | Ubuntu 24.04 の GNOME（Xorg と Wayland のセッション）で、faster-whisper のモデルを取得する初回の起動でもトレイのアイコンが上のバーに出る。使い方『起動と設定.md』の起動し直す回避の記述を見直している |
| [#218](https://github.com/shuhei1101/voice-paste/issues/218) | 設定画面の左の一覧（`group_menu`）で「エンドポイントへ送信」の末尾が切れず、横のスクロールバーが出ない。一覧の幅の決め方を画面設計『設定画面』に記載している。Windows の表示は変わらない |
| [#222](https://github.com/shuhei1101/voice-paste/issues/222) | 使い方『起動と設定.md』の「Linux の環境を作る」、単一 UC『常駐アプリを起動する』の preconditions、開発コマンド『開発コマンド』の Ubuntu の環境構築の前提、非機能要件の rationale に `gcc` と `linux-libc-dev` を記載している |
| [#223](https://github.com/shuhei1101/voice-paste/issues/223) | GNOME の Wayland のセッションで、貼り付け先が端末アプリのときに Ctrl+Shift+V を送信する。端末アプリを見分ける手段は着手時にユーザーへ確かめる。単一 UC『起こした文字を届ける』の notes、設定『常駐アプリ』の貼り付けのキー、モジュール構成『外部連携』、使い方『録音して貼り付ける.md』の記載を合わせている。Xorg と Windows の動きは変わらない |

- [#218](https://github.com/shuhei1101/voice-paste/issues/218) の一覧の幅は、今の 160px を下限にし、項目の文字幅が収まらないときだけ広げる（Windows では今の 160px に収まるため変わらない）
- [#217](https://github.com/shuhei1101/voice-paste/issues/217) と [#223](https://github.com/shuhei1101/voice-paste/issues/223) は検証環境の VM（`voice-paste-ubuntu`）で確かめ、確かめた結果を VM の画面のスクリーンショットで PR ドキュメントに残す

[#223](https://github.com/shuhei1101/voice-paste/issues/223) の Wayland のセッションで端末アプリを見分ける手段は案 A に決めた（[確認ログ](./確認ログ.md)）

| 案 | 内容 |
| --- | --- |
| A | 既存の GNOME Shell の拡張 [Focused Window D-Bus](https://extensions.gnome.org/extension/5592/focused-window-d-bus/)（フォーカスしているウィンドウの `wm_class`・`wm_class_instance` を D-Bus で返す）をユーザーが入れ、常駐アプリが D-Bus で読む。拡張が無いときは今のとおり設定の貼り付けのキーを送信する |
| B | GNOME Shell の拡張を自前で作って同梱し、ユーザーが入れる。拡張が無いときは A と同じ |
| C | 見分けずに、Wayland のセッションでは端末アプリへ貼り付けるときの貼り付けのキーをユーザーが設定で選ぶ（出力先ごとのキー 等） |

推奨: A

GNOME 41 以降は `org.gnome.Shell.Eval` が使えず、アクティブなウィンドウを読むには Shell の拡張が要る。既存の拡張を使えば、拡張の JS と導入手順を自前で持たずに済む。PoC で、拡張が Wayland のウィンドウでも Xorg と同じ名前（GNOME Terminal は `gnome-terminal-server`）を返し、端末アプリを見分けられることを確かめた（[常駐アプリ](./常駐アプリ.md) の `## PoC 結果`）。B は成果物が常駐アプリの外へ増え、計画の pt 3 の前提を超える。
