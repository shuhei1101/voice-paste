## 要望

- [#10](https://github.com/shuhei1101/voice-paste/pull/10) で起こした現状の設計書と[リスクと技術的負債の一覧](https://github.com/shuhei1101/voice-paste/blob/develop/dev/pr/10/%E3%83%AA%E3%82%B9%E3%82%AF%E3%81%A8%E6%8A%80%E8%A1%93%E7%9A%84%E8%B2%A0%E5%82%B5.md)を入力に、作り直し（[#1](https://github.com/shuhei1101/voice-paste/issues/1)）の方針を方針決めの 5 つのステップ（目的と制約・品質目標・機能の残す・捨てる・構造の決定・リスクと移行計画）で決める
- 一覧に溜めた次の観点は、いずれかのステップで結論を出す
  - 責務の混在（`main.py`・`gui.py`・`settings_gui.py`）
  - 録音・文字起こし・補正・貼り付けの境界
  - 文字起こしのエンジンの付け替えやすさ
  - 設定の持ち方
  - 置き換えの候補（tkinter・pycaw と comtypes・python-dotenv）
  - GUI の見た目とメニューの並び
  - [#4](https://github.com/shuhei1101/voice-paste/issues/4)・[#5](https://github.com/shuhei1101/voice-paste/issues/5) を作り直しで受けられるか
  - テストの扱い
- Windows のショートカットから起動できることは残す前提で決める（手段はバッチファイルに限らない）
- GUI（画面の見た目・メニュー項目）も綺麗にする前提で決める
- 出口で方針の Issue と移行の Issue を起票する
- コード（`voice_paste/`・`tests/`・`setup/`・起動のバッチファイル）と設計書は変えず、diff は PR ドキュメントに閉じる
