# 要件

## 要望

用語集の上に、補正に使う用語集を複数まとめて選んでおく「用語集のプリセット」を持つ。
プリセットは名前と、補正に使う用語集の並びを持つ。
補正は、選んでいるプリセットの用語集のオンの行を全て当てる。
設定画面で、プリセットを足す・名前を変える・消すことができ、プリセットごとに使う用語集を選べる。
補正に使うプリセットを設定画面で 1 つ選ぶ。

既定で、プリセットを 1 つ用意する。
既定のプリセットは、今の補正に使う用語集（`active_glossary`。無ければ 1 つ目の用語集）だけを使う。
今の `active_glossary` を持つ settings.toml は、そのまま読めて補正の結果が変わらない。

API で録音を始めるとき（`POST /sessions`）に、補正に使うプリセットを指定できる。
指定しないときは、設定で選んでいるプリセットを使う。

`未確定`: 複数の用語集で同じ誤変換の行が重なったときの当て方（決める段: 単一ユースケース設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | プリセットに並べた用語集の順に、用語集ごとの行の順で全ての行を続けて当てる（前の行で置き換えた結果へ次の行を当てる今の当て方を、用語集をまたいで続ける） | 1 つの用語集の今の当て方と同じで、並べ替えで優先を変えられる | 先に当たった行の置き換えで、後の用語集の同じ誤変換が当たらなくなる |
| B | 同じ誤変換の行は、プリセットで先に並べた用語集の行だけを使い、後の用語集の行を飛ばす | どの行が効くかが並びで一意に決まる | 誤変換が部分的に重なる行（「あい」と「あいう」）は重なりとして扱えない |

推奨: A

今の 1 つの用語集の中でも、行の順に続けて当てる当て方で重なりを扱っており、用語集をまたいでも同じ規則で読めるため。

`未確定`: 画面に出す呼び名（決める段: 単一ユースケース設計）

今の設計書は、用語集 1 つを「用語集のプリセット」と呼んでいる箇所がある（シナリオ『設定を変える』の「用語集のプリセットを足して切り替える」）。

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 束ねる側を「用語集のプリセット」、1 つの CSV を「用語集」と呼び、今の設計書の「用語集のプリセット」を「用語集」へ直す | Issue の言い方のままで、表記のヒントのプリセットとも呼び方が揃う | 既存のシナリオの呼び名を直す差分が出る |
| B | 束ねる側を「用語集のセット」と呼ぶ | 既存の呼び名を直さずに済む | 表記のヒントのプリセットと呼び方が揃わない |

推奨: A

ユーザーの言葉と、設定画面の他のまとまり（表記のヒントのプリセット・出力先のプリセット）の呼び方に揃うため。

`未確定`: API でのプリセットの指定の仕方（決める段: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `POST /sessions` の本文に、プリセットの名前を渡す項目を足す。一覧に無い名前は 400 で返す | 呼び出し元が設定画面で見る名前のまま指定できる | プリセットの名前を変えると、呼び出し元の指定も直す必要がある |
| B | プリセットに名前とは別の ID を持たせ、本文に ID を渡す | 名前を変えても呼び出し元の指定が変わらない | 設定画面に ID を出す欄が増える |

推奨: A

今の API の指定（返送先など）は設定画面で見える値をそのまま渡しており、名前の重なりは設定のモデルが既に許さないため。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| 外の端末のブラウザの画面（`/web`）から送る音声でのプリセットの選択 | 判断が分かれる。要望の「API 経由で実行するとき」は、ほかのシステムが録音を始める `POST /sessions` を指すと読んだ。ブラウザの画面は人が操作する画面で、選ぶ欄を足すと画面設計が増える。ブラウザの音声は設定で選んでいるプリセットを使う判断を、レビューで確定する | 起票予定 |
| ルール案内のフックが、リポジトリ直下の `rules.yaml`（存在しない）を読んで FileNotFoundError を出す | AI Monitor のルール案内の仕組みの不具合で、今回の要望に含まれない | [shuhei1101/ai-monitor#2942](https://github.com/shuhei1101/ai-monitor/issues/2942) |
