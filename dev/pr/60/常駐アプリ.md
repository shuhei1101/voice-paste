## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 原因の切り分け | 常駐アプリを 1 つだけ起動し、`Tray` のヒントの替え方・アイコンを出す順を変えた最小の `QSystemTrayIcon` と見比べて、ボタンの名前に状態が並ぶかを UI Automation で確かめる | `未確定`（要件.md の `## 要望`） |
| トレイのヒントの更新 | 常駐アプリ側が原因なら、ボタンの名前が今の状態の `voice-paste: {状態}` 1 つだけになるように `Tray` を直す | 状態ごとのアイコンとヒントの出し分け・メニューは変えない |
| トレイの状態の読み取り | `AppDriver.tray_state` は、1 つのボタンに状態が 2 つ以上並んでいても、この常駐アプリの今の状態を返す。`tray_icon_gone` は、この常駐アプリの状態が並びから消えたかで見る | 普段使いの旧版のアイコンを除く目的は保つ |
| 起動の前の確認 | `start_app` は、タスクバーにほかの voice-paste のボタンがあっても、隠れたアイコンの一覧の中のアイコンを読み落とさずに確かめる | 一覧を開いたときは、閉じて開く前の前面のウィンドウへ戻す（#58 の形を保つ） |
| 既存機能への影響 | `python.exe` が `IsPromoted=0` の環境で、Issue #59 で fail した 3 件と、要件.md の `実行のみ` の行の E2E がトレイの状態を読めないことでは fail・skip しない | ヒントが 1 つだけの環境の読み方は変えない |
