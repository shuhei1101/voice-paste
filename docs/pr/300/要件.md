# 要件

## 要望

- `docs/layout/LAY-1.yaml` に、knowledge の `schemas/design/layout.schema.yaml` の書式で voice-paste のフォルダ構成の設計書を 1 枚作る
  - リポジトリの直下からのフォルダとファイルを `entries[]` の入れ子で記載する
  - 生成物・一時ファイルは `gitignore[]`・`generated_from`、中身の種類は `content_types` で記載する
  - 配下の細かい配置を言語の規約が定めるフォルダ（`src/voice_paste/` など）は、`children` を記載せずに `convention` で規約を指す
- `dev-docs.yaml` の `documents[]` に layout の行を加え、`schema` は knowledge の `schemas/design/layout.schema.yaml` を `design-schemas/v{バージョン}` のタグつきで参照する（スキーマのコピーは `schemas/` に配置しない）
- `docs/layout/index.yaml` を作り、`docs/index.yaml` の `items` に `layout/` の行を加える
- 作った設計書を、knowledge の規約『フォルダ構成の切り方とレビュー』（`dev-folder-layout`）のレビューの観点で確認し、見つかった問題ごとに Issue を起票する（対処はこの作業 PR では行わない）

終わりの条件:

- 設計書のエントリが `git ls-files` の結果と食い違わず、`gitignore[]` が今の `.gitignore` と一致するか、食い違いを起票した Issue が指している
- `docs/layout/LAY-1.yaml` が dev-docs の layout の文書として検査に通る

`dev-docs.yaml` の先頭の `$schema` は変えない。
`$schema` はエディタの補完の指定で、指す `v0.0.0` は dev-docs のリポジトリにタグが無く、ai-monitor の `dev-docs.yaml` が指す commit のスキーマは `schema` を文字列に限る。
`schema` の `source`・`path`・`ref` の指定は、設計書の検証のコマンド（`ai_monitor.design_docs validate`）が解決して `docs/layout/LAY-1.yaml` を検査する。
参照するタグは、作成した時点の最新の `design-schemas/v8.2.0` にする。

## テスト結果

単体・結合テストは回さない。
変更はフォルダ構成の設計書と目次・`dev-docs.yaml` の行だけで、規約『V字モデル』の対応表で対応する単体・結合テストが無い。
設計書の検証のコマンドは、base ブランチと同じ結果（シナリオの対応テストファイルが無い 12 件だけ）で、`docs/layout/LAY-1.yaml` に Schema に無い項目を入れると検出することを確かめた。
