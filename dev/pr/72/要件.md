# 要件

## 要望

単一ユースケース「常駐アプリを起動する」の E2E の `test_error_when_engine_unavailable`・`test_error_when_api_unavailable` が、シナリオの期待値「トレイで起動に失敗したことが知らされている」「トレイで API を使えないことが知らされている」を確かめて pass する。

- E2E は、常駐アプリのログの「ユーザーへの知らせ（{種類}…）」（`AppDriver.notified`）で知らせを出したことを確かめ、通知センターに残っているかを確かめない
- `test_error_when_engine_unavailable` も、`test_error_when_api_unavailable` と同じく知らせの種類（`engine_unavailable`）を確かめる
- 2 件が、release PR [#52](https://github.com/shuhei1101/voice-paste/pull/52) の E2E の全件の実行で pass する
- 画面設計『トレイの通知』と単一ユースケース『録音を文字に起こす』を、通知が通知センターに残らない今の動きに合わせる

実機の切り分けの結果（[常駐アプリ](./常駐アプリ.md) の `## 切り分けの結果`）、通知は画面にトーストとして出るが、通知センターには残らない。
起動の失敗・API を使えない知らせは常駐アプリの不具合ではなく、`type:test` のまま進める。

`未確定`: 通知が通知センターに残らないことの扱い（決める段: 画面設計のユーザーの確認）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 設計書を今の動きに合わせ、通知センターに残らないと書く。畳まれた後はトレイのメニューの「ログフォルダを開く」から理由を見る | 実装を変えず、v0.3.0 を止めない | [#37](https://github.com/shuhei1101/voice-paste/pull/37) のモック作成で決めた「後から見返せる」が無くなる |
| B | 通知の出し方を、アプリの ID を登録した Windows のトースト通知へ作り替え、通知センターに残す | モック作成で決めた振る舞いになる | 通知の出し方の作り替え（ID の登録・押したときの受け取り）が要り、v0.3.0 の E2E の修正の範囲を超える |

推奨: A

トレイのメニューに「ログフォルダを開く」があり、畳まれた後も理由を見る手段は残っている。
B を選ぶ場合も、v0.3.0 はこの PR で A の記述にして入れ、作り替えは別の Issue で扱う。
