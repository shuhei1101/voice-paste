## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| トレイを出す時点（#217） | VM の Xorg のセッションでモデルを削除して起動して再現し、原因を特定してから、初回の起動でもアイコンが上のバーに出るように直す。PoC で確かめる変更は、ワーカーの ready の待ちをメインスレッドの外へ移し、ready の後の配線をメインスレッドへ戻すもの（モデルの取得の間もイベントループを止めない） | `未確定`（決める工程: PoC 検証。要件『未確定』の 1 つ目） |
| 回避の記述（#217） | 修正後、使い方『起動と設定.md』の「モデルを取得する初回の起動でトレイのアイコンが出ないとき」を削除するか、残る事象に合わせて書き換える | - |
| 設定画面の一覧の幅（#218） | 一覧の幅を、160px を下限にし、項目の文字幅（とスクロールバー・余白）が収まらないときだけ広げる。横のスクロールバーは出さない | 画面設計『設定画面』の `group_menu` に幅の決め方を記載する。Windows では 160px のまま |
| 環境構築の前提（#222） | Linux の OS のパッケージを並べた 4 か所（使い方・単一 UC・開発コマンド・非機能要件）に `gcc`・`linux-libc-dev` を追加し、使い方の表に用途（`evdev` のビルド）を追加する | - |
| Wayland の端末アプリの見分け（#223） | Wayland のセッションでも、貼り付けのキーを送信する直前にアクティブなウィンドウが端末アプリかを見て、端末アプリなら Ctrl+Shift+V を送信する。端末アプリの一覧は、PoC で拡張が返した値（GNOME Terminal・テキストエディター・XWayland のアプリ）を記録して決める（Wayland の app_id `org.gnome.terminal` 等を追加するか）。見分けられないとき（拡張が無い 等）は今のとおり設定の貼り付けのキーを送信する | `未確定`（決める工程: PoC 検証。要件『未確定』の 2 つ目） |
| 既存機能への影響 | Windows と Xorg のセッションの貼り付け・設定画面・トレイの動きは変えない | - |
| 動作環境 | 非機能要件の動作環境の決定値は変えない（rationale の OS のパッケージだけ） | - |
