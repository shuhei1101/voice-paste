受付の時点で、検証環境の VM（Ubuntu 24.04.5・Xorg）の gsettings（`org.gnome.desktop.wm.keybindings`・`org.gnome.settings-daemon.plugins.media-keys`・`org.gnome.shell.keybindings`・`org.gnome.mutter.keybindings`）を見た。
Ctrl+Alt を使う既定のショートカットは `T`（端末）・`Delete`（ログアウト）・矢印（ワークスペース）・`Tab`・`Escape`・`F1`〜`F12` で、既定のホットキーの `D`・`Z`・`Q`・`V`・`C`・`1`〜`3` とはぶつからない。
有効な拡張（dash-to-dock・tiling-assistant・ding・appindicators）のショートカットも Super の組み合わせだけで、ぶつからない（モジュール構成設計の時点で確かめた）。

## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| キーの表示名 | `<cmd>` の表示名を OS ごとに引く（Windows は「Win」、Linux は「Super」）。`format_hotkey` を使う全ての画面に効く | 表示名の表は OS の判定（`shared/os_kind.py`）から引き、`sys.platform` を直に読まない |
| 既定のホットキー | VM の Xorg のセッションで既定のホットキーが受け付けられることを確かめ、ぶつかるキーだけ `OS_DEFAULT_OVERRIDES` で Linux の既定値を変える | gsettings（拡張を含む）の上ではぶつかりは無く、Linux の既定値は変えない |
| 貼り付けのキー（一般のアプリ） | Linux の既定値も `<ctrl>+v` | - |
| 端末アプリへの貼り付け | Linux で、アクティブなウィンドウ（`_NET_ACTIVE_WINDOW` の WM_CLASS）が端末アプリなら `Ctrl+Shift+V`、それ以外なら設定の貼り付けのキーを送信する（要件.md の案 A） | 端末アプリのクラス名の一覧は定数 `TERMINAL_WM_CLASSES` で持ち、設定のキーを追加しない |
| 貼り付けのキーの送信（Linux） | 主キーを XTEST で送信する（pynput に `KeyCode.from_vk` で渡す） | 文字で渡すと XSendEvent になり、GTK4 のアプリが受け付けない（`## PoC 結果`） |
| Windows | 表示・既定値・送信の処理を変えない | - |
| 既存機能への影響 | 設定のスキーマを変えない（端末アプリへの貼り付けで設定のキーを追加する場合は、既定値で今の動きと同じにする） | - |
| 動作環境 | 非機能要件『動作環境』の決定値は変えない（Ubuntu 24.04 の Xorg のセッション） | - |

### 結論

成立。案 A を採る。
B と D はどちらも全部は成功しなかった。両方が成功していた場合は、D が VS Code（Markdown のプレビュー）・LibreOffice（形式を選択して貼り付け）で貼り付けにならないため、B を採る予定だった。

Linux では、貼り付けのキーの主キーを XTEST で送信する。
今の `send_paste` は主キーを文字（`controller.press("v")`）で渡しており、pynput（Xorg）は文字のキーを XSendEvent で送る（修飾キーと `Insert` などの名前のあるキーは vk を持ち、XTEST で送る）。
GTK4 のアプリ（GNOME Text Editor 等）は XSendEvent のキーを受け付けないため、今の作りでは Linux の既定の `Ctrl+V` が GTK4 のアプリで貼り付けにならない。
主キーを `KeyCode.from_vk`（Xorg の pynput では vk が keysym）で渡すと XTEST で送られ、3 アプリとも受け付けた。
Windows の送り方は変えない。

端末アプリのクラス名は、GNOME Terminal では WM_CLASS のインスタンス名 `gnome-terminal-server`。
ほかの端末（GNOME Console・Ptyxis 等）を含めたクラス名の一覧を設定に持つか固定値にするかは、モジュール構成設計で決める。

### 本番との違い

- クリップボードへは、本番は pyperclip で書くが、PoC は xclip で書いた
- 録音の画面の代わりに、PySide6 の `QLabel` を出して閉じた
- PRIMARY は `primary-sentinel` にして CLIPBOARD と見分けた（本番では利用者が最後に選んだ文字が入っている）
- 端末アプリは GNOME Terminal、一般のアプリは GNOME Text Editor と Firefox のそれぞれ 1 つで確かめた

### 検証中に見つかったこと

- VM で PySide6 の画面を出すのに `libxcb-cursor0` が要った（無いと Qt の xcb のプラグインを読めずに落ちる）。apt で入れた。Linux の環境の作り方は [#199](https://github.com/shuhei1101/voice-paste/issues/199) の範囲
- 検証のため、VM の画面ロックを止めた（`org.gnome.desktop.screensaver lock-enabled` を `true` → `false`、`org.gnome.desktop.session idle-delay` を `300` → `0`）

```python
def read_active_wm_class(xdisplay: display.Display) -> tuple[list[str], float]:
    """_NET_ACTIVE_WINDOW の WM_CLASS を読み、かかった時間（ms）とあわせて返す。"""
    started = time.perf_counter()
    root = xdisplay.screen().root
    atom = xdisplay.intern_atom("_NET_ACTIVE_WINDOW")
    prop = root.get_full_property(atom, X.AnyPropertyType)
    if prop is None or not prop.value:
        return [], (time.perf_counter() - started) * 1000
    window = xdisplay.create_resource_object("window", prop.value[0])
    wm_class = window.get_wm_class() or ()
    return list(wm_class), (time.perf_counter() - started) * 1000


def xkey(char: str) -> KeyCode:
    """文字のキーを、XTEST で送る pynput のキーにする。"""
    return KeyCode.from_vk(ord(char))


# 端末なら Ctrl+Shift+V、それ以外は Ctrl+V（主キーは XTEST で送る）
keys = (Key.ctrl, Key.shift, xkey("v")) if wm_class[0] == "gnome-terminal-server" else (Key.ctrl, xkey("v"))
```
