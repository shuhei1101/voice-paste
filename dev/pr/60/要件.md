# 要件

## 要望

常駐アプリのトレイのアイコンのボタンにヒントの状態が 2 つ並ぶ環境（Issue #59 の `voice-paste: 準備中 voice-paste: 待機中`）でも、画面・トレイ・ホットキーの E2E がトレイの今の状態を読んで流れるようにする。

- ヒントが 2 つ並ぶ原因が、常駐アプリのトレイの更新の仕方（`Tray` のヒントの替え方・アイコンを出す順）か、Windows の表示かを、常駐アプリのトレイから先に切り分ける
- 常駐アプリのトレイの更新の仕方が原因なら、常駐アプリを 1 つだけ動かしたとき、トレイのアイコンのボタンの名前が今の状態の `voice-paste: {状態}` 1 つだけになるように直す（普段使いの表示も直る）。このときは Issue の `type:test` を `type:bug` へ書き直す
- `AppDriver.tray_state`・`wait_tray_state`・`tray_icon_gone` が、1 つのボタンに状態が 2 つ以上並んでいても、この常駐アプリの今の状態を返す
- `start_app` の起動の前の確認は、タスクバーにほかの voice-paste のボタンがあっても、隠れたアイコンの一覧の中のアイコンを読み落とさない
- `python.exe` が `IsPromoted=0` の環境で、Issue #59 で fail した複合ユースケース「声で入力した文字を貼り付ける」の `test_normal`・`test_normal_when_cancel`・`test_error_when_transcription_failed` と、下の表の `実行のみ` の行の E2E が、トレイの状態を読めないことでは fail・skip しない

`未確定`: ヒントが 2 つ並ぶ原因と、直す場所（決める段: モジュール構成設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 常駐アプリのトレイの更新の仕方が原因なら `src/voice_paste/ui/tray.py` を直し、テストの支えのコードの読み方も今の状態を選ぶ形にする | 普段使いのトレイの表示も直る | 常駐アプリのコードと設計書（モジュール構成）が変わる |
| B | Windows の表示が原因なら、テストの支えのコードの読み方だけを直す | 常駐アプリを変えない | 普段使いの表示に 2 つ並ぶのは残る |

推奨: A

切り分けの結果で決まる。常駐アプリ側が原因なら、テストの読み方だけを直すと普段使いの表示に 2 つ並ぶのが残るため、常駐アプリを直す。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| トレイの通知の出し分け（コピーの完了の通知） | 要望に含まれない。常駐アプリ側が原因のときに `ui/tray.py` が重なるが、ヒントの更新だけを触り通知の出し分けを作り替えない | [#50](https://github.com/shuhei1101/voice-paste/issues/50) |
| E2E の前提として `python.exe` のトレイのアイコンをタスクバーへ出しておく（`IsPromoted=1`） | ユーザーの Windows のトレイの表示設定を変える前提になる（#58 で予定なしとした）。テストが隠れたアイコンの一覧を開いて読む形で足りる | 予定なし |
| エクスプローラーの再起動の直後に前面がタスクバーのままで `PasteTarget.focus` の `SetForegroundWindow` が失敗すること・失敗したテストが貼り付け先の窓を残すこと | Issue #59 の実行の環境で整えたことで、トレイの状態の読み取りとは別の事象。要望に含まれない | [#61](https://github.com/shuhei1101/voice-paste/issues/61) |
