## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 差し替えの補助 | `run_resident_app` で、貼り付けのキーを `KeyLog` に差し替えられるようにする。ほかに要る差し替え（通知・マイクを開けない入力 等）はシナリオごとに単一ユースケース設計で決める | 渡さないケースの起動は変えない |
| 常駐アプリを起動する | 正常シナリオ・「API の待ち受けを始められない」のケースで、録音開始のホットキーの関数を呼んでトレイが録音中になることを確かめる。「古い AI チャットの設定が残っている」のケースで、プリセットのボタンが出ることと確定して送るまでを確かめる | 入力は無音の WAV。送るまでは `speech_input` |
| 録音する | 新しいテストファイルに全シナリオのケースを置く | `tests/e2e/単一ユースケース/test_record.py`（名前は単一ユースケース設計で確定） |
| 起こした文字を届ける | 新しいテストファイルに全シナリオのケースを置く。貼り付けは控えたキーとクリップボードで、返送先・送り先は受け口に届いた中身で確かめる | `tests/e2e/単一ユースケース/test_deliver_text.py`（同上）。クリップボードはテストの後に元の文字へ戻す |
| 録音を文字に起こす | 既存のテストファイルに「文字起こしの手がかりを渡す」以外のシナリオのケースを足す | - |
| 4 つのシナリオ | 各シナリオに上のケースのテスト名の `test` を持たせ、Mock の行に録音の入力（WAV）・システム音量・貼り付けのキーの差し替えを足す。補足『E2E のテスト』の E2E を置かない旨を、差し替えた形の説明に書き換える | シナリオの流れと期待値は変えない |
| テスト実行方法 | [要件](./要件.md) の `## 更新ドキュメント` | - |
| 常駐アプリ（`src/`） | 変えない | - |
