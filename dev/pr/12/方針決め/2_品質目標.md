# 品質目標

## 品質特性の点検

| 特性 | 重要度 | 根拠 | 補足 |
| --- | --- | --- | --- |
| 機能適合性（機能正確性） | 高 | 成功の基準「今の使い方が同じ操作で新しい構成の上で動く」。刷新で文字起こし・用語の補正・貼り付けの結果が変わると普段使いが止まる | - |
| 性能効率性（時間効率性） | 高 | 成功の基準「話し終えてから貼り付くまでの時間が今より延びない」 | 常駐するサーバーと文字起こしワーカーの分だけ経路が増える |
| 互換性（相互運用性・共存性） | 高 | 目的 1（ほかのシステムから呼べる API）。ホットキーと API の両方から録音を始められるため、マイク・GPU を取り合わないことも要る | 処理中に別の開始が来たら、API はエラー・画面はダイアログで知らせる（目的と制約の回答） |
| インタラクション容易性（運用操作性・ユーザーエラー防止性） | 中 | 目的 3（画面の見た目・画面構成・メニューの並び）。利用者は 1 人で、習得性・インクルーシビティは要らない | 画面の見直しは構造の決定で扱う |
| 信頼性（障害許容性・回復性） | 高 | 困っている変更の具体例（CUDA のクラッシュで 2 度作り替えた）と、問題にどう気づくか（起動の失敗に気づけない）。文字起こしの失敗で録音が消えるリスクもある | リスクと技術的負債の一覧の、録音の上書き・起動の失敗の行 |
| セキュリティ（機密性・耐攻撃性） | 中 | API がマイクで録音を始められるため、端末の外やブラウザから呼ばれると盗聴になる | 待ち受けを端末の中（localhost）に限れば範囲は小さい |
| 保守性（モジュール性・修正性・試験性） | 高 | 目的 2（出力先・エンジン・設定を 1 か所で変えられる）と、困っている変更の具体例（pycaw の追従・送り先の追加）。今のテストは実装を守っていない | - |
| 柔軟性（置換性・適応性） | 低 | Windows で 1 人が使う道具で、他の環境への移植は要望に含まれない（[#9](https://github.com/shuhei1101/voice-paste/issues/9) はスコープ外） | エンジンの付け替えやすさは保守性（モジュール性）で扱う |
| 安全性 | なし | 人命・財産への危険が無い | 録音中であることの表示はインタラクション容易性で扱う |

## 品質シナリオ

| 優先度 | 特性 | 刺激の源 | 刺激 | 環境 | 対象 | 応答 | 応答の測定 | 補足 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 互換性（相互運用性） | 同じ端末の別のプロセス | API で録音の開始 → 停止 → 完了を呼ぶ | 常駐中・ほかの録音が動いていない | API のサーバー | 開始で画面を出さずに録音を始め、完了で呼び出し元が指定したエンドポイントへ起こした文字を返す | 50 回続けて呼び、50 回とも指定したエンドポイントに文字が届く。開始の要求への応答が 500 ms 以内 | 目標値は仮。PoC で測って確定する |
| 2 | 性能効率性（時間効率性） | 利用者 | 約 10 秒話して、ホットキーで録音を止める | 常駐中・ローカルの Whisper（GPU）・モデルは読み込み済み | 録音 → 文字起こし → 貼り付けの経路 | 前面のアプリに起こした文字を貼り付ける | 止めてから貼り付くまでの時間の中央値が、刷新前の中央値以下（新旧それぞれ 20 回測る） | 刷新前の値は PoC で測る |
| 3 | 信頼性（障害許容性・回復性） | 文字起こしワーカー | 文字起こしの途中で CUDA のエラーでワーカーが落ちる | 常駐中・ローカルの Whisper を使っている | 文字起こしワーカーと常駐のサーバー | 常駐とサーバーは動き続け、呼び出し元（API はエラー応答・画面は知らせ）へ失敗を伝え、ワーカーを立て直す。録った音声は履歴に残す | 常駐が止まる回数 0・録った音声が消える件数 0・ワーカーが落ちてから 30 秒以内に次の録音を受け付ける | 目標値は仮。PoC で測って確定する |
| 4 | 保守性（修正性） | 開発者 | 出力先を 1 つ足す | 実装時 | 出力先のモジュールと設定 | 新しいモジュールと設定の追加で動き、既存のテストが通る | 既存のモジュールの変更が、出力先の一覧への登録の 1 か所まで | 比べる対象は、送り先を 1 つ足すのに設定画面の 4 か所を直した [ccc3427](https://github.com/shuhei1101/voice-paste/commit/ccc3427) |
| 5 | 互換性（共存性） | 利用者と別のプロセス | 録音か文字起こしの途中に、もう一方から録音の開始が来る | 常駐中・録音か文字起こしを処理中 | API のサーバーとホットキーの受付 | 後から来た開始を受け付けず、API の呼び出し元にはエラーを返し、ホットキーならダイアログで知らせる | 2 つ目の録音が始まる回数 0・後から来た API の呼び出しへのエラー応答が 1 秒以内 | 目標値は仮 |
| 6 | 保守性（修正性） | 外部ライブラリ | システム音量の操作に使うライブラリの版が上がり API が変わる | 依存の更新時 | システム音量の操作のモジュール | そのモジュールだけの修正で追従する | 変更するファイルが 1 件 | 比べる対象は、pycaw の追従に 3 つの修正 commit を要した PR #15 |
