# 要件

## 要望

録音の画面の確定の操作を「固定の出力先」と「カスタムプリセット」の 2 つに分け、カスタムプリセットの種類に「エンドポイントへ送る」を足す（[PR の確認事項](https://github.com/shuhei1101/voice-paste/pull/44#discussion_r4172598315) の回答）。
送り先を複数持ち、送り先ごとのボタン・ホットキーで送る [#40](https://github.com/shuhei1101/voice-paste/issues/40) の中身もこの PR で受ける（#40 の一本化と見積もりの見直しは task-planner へ [連絡](https://github.com/shuhei1101/voice-paste/issues/35#issuecomment-5967936544) した）。

- 固定の出力先は、貼り付けて送信・貼り付けのみ・コピーのみの 3 つだけにする（今の設定でオン・オフとホットキーを持つ形のまま）
- 今の「AI チャットへ送る」の出力先と送り先の一覧を、カスタムプリセットの一覧に置き換える
  - ユーザーが設定画面でプリセットを自由に足し・消し・並べられる
  - 1 件ごとに、タイトル（ボタンに出す名前）・種類・種類ごとの値・確定のホットキー・有効 / 無効を持つ
  - 既定のプリセットは持たない（最初は空）
- プリセットの種類は、後から種類を足せる形にし、まずは次の 2 つを持つ
  - ブラウザ添付: 起こした文字をクリップボードへ書き、URL を Microsoft Edge のアプリのウィンドウで開いて（見つからなければ既定のブラウザ）、設定の間を置いて貼り付ける。プリセットごとに、貼り付けた後に Enter まで送るか、貼り付けだけで止めるかを選べる（既定は Enter まで送る。今の AI チャットへ送ると同じ）
  - エンドポイントへ送る: 起こした文字を URL へ JSON で 1 回 POST する
    - 送る中身は呼び出し元へ返す出力先と同じ JSON（`session_id`・`result`・`text`・`error`）に固定する
    - プリセットごとに `Authorization` ヘッダーの値を 1 つ持てる。空でなければ付けて送る。値は秘密として画面とログで伏せる
    - 届かなかったとき（タイムアウト・接続できない・2xx 以外）は送り直さず、1 回で届かなければすぐ知らせる
    - 送るときのタイムアウトは「エンドポイントへ送る」の全てのプリセットで共通の設定にする（既定 1.5 秒、0.5 秒以上 10 秒以下）
    - 送り先のホストは制限せず、設定に書いた URL へそのまま送る（`api.allowed_callback_hosts` は API の返送先だけに効く）
- `outputs` に `id = "ai_chat"` の項目が残った `settings.toml`（今の既定の一覧で作られた全ての設定）を読んだときは、`ai_chat` の送り先（`targets[]`）を、同じタイトル・URL・ホットキー・有効 / 無効を持つ「ブラウザ添付」種類のプリセット（Enter まで送る）へ読み替えて起動する。次に保存するときに新しい形で書く
  - 読み替えで常駐アプリが起動できなくならないこと、ユーザーの今の送り先（ChatGPT・Google AI・Claude）がそのまま残ることを満たす
- 設定画面では、カスタムプリセットを種類ごとに左のメニューのタブ「ブラウザ添付」「エンドポイントへ送る」（「出力先」のすぐ下）へ分け、それぞれのタブにプリセットの一覧とその種類のオプションを置く。「出力先」のタブには固定の出力先と貼り付けてから Enter を送るまでの秒数が残る
  - 確定のホットキーは空にでき、空のプリセットは録音の画面のボタンだけで選ぶ
- 録音の画面は、固定の出力先のボタンの下に、有効にしたプリセットのボタンを、見出し「カスタムプリセット」の下に「ブラウザ添付」のタブの並び → 「エンドポイントへ送る」のタブの並びの順で出す
- ホットキー・トレイから始めた録音で、ボタンか確定のホットキーで選んだときだけそのプリセットで届ける。API から始めた録音では使わない（今の `deliver` のとおり、API の録音は呼び出し元へ返す出力先だけを使う）
- 届けられなかったときは、ほかの出力先と同じく `DeliveryError` にしてトレイで届けられなかったことを知らせ、ログに理由を書く
- 完了の定義
  - ブラウザ添付種類のプリセットで、選んだときに今の AI チャットへ送ると同じく貼り付けて送れる。Enter まで送らない設定のプリセットでは貼り付けだけで止まる
  - エンドポイントへ送る種類のプリセットで、選んだときに送り先へ起こした文字が 1 回届く
  - 無効にしたプリセット・API から始めた録音では送らない
  - `ai_chat` の項目が残った `settings.toml` で常駐アプリが起動し、その送り先がブラウザ添付種類のプリセットとして録音の画面に出る
  - 読み替えた設定を保存すると、`settings.toml` から `id = "ai_chat"` の項目が無くなり、同じ送り先がプリセットとして書かれる（結合テストで確かめる）
  - import-linter の検査が通る

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| 出力先を足すときに、`OUTPUTS` のほかに設定のモデル（`OutputSettings`）・配線（`_wire_outputs`）・画面の出力先の名前（`OUTPUT_NAMES`）も直す今の形を、`OUTPUTS` への登録だけで済む形に寄せる | 品質シナリオ 5 は「既存のモジュールで変えるのは `OUTPUTS` への登録だけ」だが、今の実装は出力先ごとの設定と表示名を別の場所に持つ。この PR の要望（カスタムプリセット）は固定の出力先の登録の形を変えず、別の作り直しで、この PR がマージされなくても同じ内容で成り立つ | [#45](https://github.com/shuhei1101/voice-paste/issues/45) |
