# 要件

## 要望

出力先を 1 つ足すときに既存のモジュールで変えるのを、`features/outputs/registry.py` の `OUTPUTS` への登録だけにする（品質シナリオ 5、非機能要件「出力先を足すときに変える既存のモジュール」の決定値 1 か所）。
出力先のパッケージ（`features/outputs/{出力先}/`）を新しく足す差分は数えない。

develop（[aec3c32](https://github.com/shuhei1101/voice-paste/commit/aec3c32292ad05bd192df1ef0ce422c146240d0d)）で、`OUTPUTS` のほかに出力先ごとの書き足しが要る箇所は次のとおり。
Issue が挙げた `AiChatSettings` での分け方は、[#44](https://github.com/shuhei1101/voice-paste/pull/44) で AI チャットの出力先をカスタムプリセットへ置き換えたため無くなっている。

| ファイル | 出力先ごとの書き足しが要る箇所 |
| --- | --- |
| `src/voice_paste/shared/settings.py` | 出力先ごとの設定のモデル（`PasteAndSendSettings` など）・`OutputSettings` の判別共用体・`_default_outputs` |
| `src/voice_paste/main.py` | `_wire_outputs` の `injections`（出力先の ID ごとに注入する関数） |
| `src/voice_paste/ui/windows/settings_window.py` | `OUTPUT_NAMES`・`OUTPUT_MODELS`・`_add_outputs` の出力先の型での分け方（録音の画面も `OUTPUT_NAMES` を引く） |

- 完了の定義
  - `OUTPUTS` に出力先を 1 つ登録するだけで、その出力先が設定の読み込み・既定の一覧・保存、確定のホットキーの登録と重なりの確かめ、設定画面の欄、録音の画面のボタン、届けに乗る（試しの出力先を登録したテストで確かめる）
  - `settings.toml` の `outputs` の形（キーと値）は変えず、今の設定ファイルがそのまま読める
  - 設定画面・録音の画面の表示と操作、届け方は変わらない
  - import-linter の検査が通る

`未確定`: 出力先ごとの設定のモデル・画面の名前・注入するものの置き場所（決める段: モジュール構成設計）

`shared` と `ui` は `features` を import できない（import-linter の「層の向き」「画面から feature の中へ」）。

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 出力先ごとの設定のモデル・既定値・注入するものを各出力先のパッケージと `OutputSpec` に持たせ、`main.py` が `OUTPUTS` から設定の検証と設定画面の欄を組み立てて渡す | import の向きを変えずに、出力先の知識が出力先のパッケージに閉じる | 設定のモデルと設定画面が、受け取った出力先の定義で組み立てる形へ変わる |
| B | 設定の出力先を出力先に依らない共通の形（`id`・`enabled`・`hotkey` と出力先固有の値の表）にし、固有の値の検証を `OutputSpec` が持つ定義で行う | `shared/settings.py` の判別共用体が要らなくなる | 出力先固有の値の型が設定のモデルから読めなくなる |
| C | import-linter の契約を緩め、`shared` と `ui` から `features.outputs.registry` を import できるようにする | 書き換えが最も少ない | 品質シナリオ 5 を支える層の向きを崩す |

推奨: A

出力先を足すときの知識を出力先のパッケージに閉じたまま、今の import の向きと設定のモデルの型を保てるため。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| カスタムプリセットの種類を足すときの書き足し（`Preset` の判別共用体・`PresetOptions`・設定画面の `PRESET_KIND_NAMES`・`_wire_preset_kinds` の `injections`） | 品質シナリオ 5 は出力先が対象で、種類を足すときに設定のモデル・`PRESET_KINDS`・画面の種類の名前へ登録する形はモジュール構成『共通』の `Preset` に決めてある。要望に含まれない（判断が分かれるためレビューで確定する） | 予定なし |
| 録音の開始のホットキーと貼り付けて送信の重なりを許す扱い（`PASTE_AND_SEND_ID`）と、ブラウザ添付が貼り付けて送信の Enter までの間を使う扱い | 既存の出力先に固有の扱いで、出力先を足すときに書き足しは要らない | 予定なし |
