# リスクと技術的負債

| 見つけた段 | 場所 | 内容 | 種別 | 影響 | 補足 |
| --- | --- | --- | --- | --- | --- |
| 複合ユースケース設計 | `voice_paste/main.py` | 録音・音量の制御・文字起こし・用語集の補正・履歴・届け方・AI チャットへの送信が 1 つの関数に続けて書かれており、貼り付けを外して文字起こしだけを取り出す切れ目が無い | 技術的負債 | ほかのシステムから文字起こしを使えるようにする（#1）には、流れの全体を組み直すことになる | - |
| 複合ユースケース設計 | `voice_paste/main.py` | 起動時に PID ファイルに残った番号のプロセスを `taskkill /F` で強制終了する | リスク | 前回の終了後に同じ番号が別のプロセスへ使い回されていると、無関係なプロセスを止める | - |
| 複合ユースケース設計 | `voice_paste/main.py` | 文字起こしに失敗すると、録音は一時ファイル（`cache/recording.wav`）に残るだけで履歴に入らず、次の録音で上書きされる | リスク | 長く話した内容が文字起こしの失敗で失われ、やり直す手段が無い | - |
| 単一ユースケース設計 | `voice_paste/main.py` | マイクを開けずに録音が始まらないと、先に下げたシステム音量を戻さず、トレイも赤（録音中）のまま残る | リスク | マイクが外れているだけで、音量が下がったままになり、トレイの表示も実際の状態と食い違う | - |
| 単一ユースケース設計 | `voice_paste/main.py` | 起動時に文字起こしのエンジンを準備できないと、例外で起動の処理が止まり、画面にも知らせが出ず、例外の内容もログに書かれない | リスク | API キーの入れ忘れやモデルの読み込み失敗に、ユーザーが気づけない | - |
| 単一ユースケース設計 | `voice_paste/settings_gui.py` | 設定画面は値を確かめずに `.env` へ書き、その後に実行中の設定へ反映するため、数値の欄に数値でない値を入れると `.env` だけが壊れる | リスク | 次の起動で設定を読めずに起動できなくなる | - |
| 単一ユースケース設計 | `voice_paste/settings_gui.py` | 画面の組み立て・入力の読み取り・`.env` への書き込み・実行中の設定の書き換えを 1 つのクラスで行い、項目ごとに同じ手順を並べている（AI 送信は 3 件に固定） | 技術的負債 | 設定を 1 つ足すたびに 4 か所を直すことになり、足し漏れが起きやすい | - |
| 単一ユースケース設計 | `voice_paste/config.py` | 設定をモジュールの変数に持ち、設定画面が直接書き換える。保存した設定がその場で効くかは項目ごとの書き分けで決まる（ホットキーは録音開始だけ登録し直し、エンジンとモデルは再起動が要る） | 技術的負債 | どの設定が再起動なしで効くかがコードを読まないと分からず、設定の持ち方を変えるときに影響を追いにくい | - |
| 単一ユースケース設計 | `voice_paste/gui.py` | 届け方の型（`ConfirmMode`）に AI チャットへ送る届け方が無く、`send_to_ai_{番号}` の文字列で何番目の AI かを渡している | 技術的負債 | 届け方を足すと、型に現れない文字列の取り決めを画面と流れの両方で合わせることになる | - |
| 単一ユースケース設計 | `voice_paste/transcription/transcribable.py` | 文字起こしのインターフェースの `transcribe` が経過を知らせる引数を持たず、2 つの実装（Whisper・OpenAI）の引数と食い違っている | 技術的負債 | エンジンを付け替えるときに、インターフェースだけを見ても実装に要るものが分からない | - |
| 単一ユースケース設計 | `voice_paste/transcription/openai_transcriber.py` | OpenAI のモデルを `whisper-1` に固定し、言語と温度はローカルの Whisper の設定（`WHISPER_LANGUAGE`・`WHISPER_TEMPERATURE`）を流用している | 技術的負債 | OpenAI 側のモデルを選べず、片方のエンジンの設定を変えるともう片方にも効く | - |
| 単一ユースケース設計 | `voice_paste/main.py` | 貼り付け先は、文字起こしが終わった時点のアクティブなウィンドウになり、ユーザーが文字起こし中にカーソルを合わせておく前提になっている | リスク | 文字起こしの間にほかのウィンドウへ移ると、意図しない場所へ貼り付けて Enter まで送る | - |
| 現状の棚卸し | `pyproject.toml` | コードが直接使う `numpy`・`comtypes`・`nvidia-cuda-nvrtc-cu12` と、ビルドに使う `PyInstaller` が依存に書かれておらず、`nvidia-cublas-cu12` は版を固定していない | リスク | ほかのパッケージの依存の変わり方しだいで、入れ直した環境で動かなくなる | - |
| 現状の棚卸し | `voice_paste/constants.py` | 用語集とは別のプロンプトのファイル（`prompt.txt`）の置き場所と、exe での移行・補いの処理が残っているが、それを読む処理が無く、`resources/prompt.txt` も無い | 技術的負債 | 使われていない設定の置き場所が、設定の持ち方を見直すときに読み違いの元になる | 実装なし |
| 現状の棚卸し | `voice_paste/constants.py` | トレイのアイコンに `resources/icon.png` を探すが、同梱しているのは `icon.ico` だけで、常にコードで描いたアイコンになる | 技術的負債 | アイコンの画像を差し替えても効かない | - |
| 現状の棚卸し | `voice_paste/config.py` | 用語集のファイルの場所の決め方が 5 段の優先順になっており、`YOGO_FILE` に相対パスを入れても、設定の置き場に `yogo.csv` があるとそちらを使う | リスク | 設定画面で選んだ用語集が使われていないことに気づきにくい | - |
| 現状の棚卸し | `voice_paste/config.py` | 設定の読み込みの中で、exe の旧パスからの移行と同梱ファイルからの補いを、起動のたびに行っている | 技術的負債 | 設定の読み込みを変えるときに、移行の処理まで一緒に確かめることになる | - |
| 現状の棚卸し | `voice-paste.bat` | 起動のたびに、名前が今日の日付で始まらない `log/*.log` を消すため、`crash.log` と前日までのログも消える | リスク | 前日に起きた落ち方を、次に起動した後では調べられない | - |
| 現状の棚卸し | `tests/transcription/test_whisper_transcriber.py` | テストは `WhisperModel` を同じプロセスで呼ぶ前と、`prompt` 引数がある前の実装に合わせたままで、今の実装（子プロセスのワーカー）では動かない | 技術的負債 | テストが実装を守っておらず、残す価値が無い | 作り直す前提で消してよい |
