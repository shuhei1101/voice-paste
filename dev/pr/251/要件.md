# 要件

## 要望

| Issue | 終わりの条件 |
| --- | --- |
| [#243](https://github.com/shuhei1101/voice-paste/issues/243) | 非機能要件テスト（`tests/nfr/`）を、Linux（Ubuntu 24.04 の Xorg のセッション）でも実行できる。Linux で流すときの決定値・測り方の扱いが決まっている |
| [#244](https://github.com/shuhei1101/voice-paste/issues/244) | スプリントの release の E2E の実行（tester が release ブランチで E2E を全件流す）に、検証環境の VM `voice-paste-ubuntu`（Ubuntu 24.04 の Xorg のセッション）での実行が加わっている |

Windows での非機能要件テストと E2E の動き・決定値は変えない。
`src/` は変えない。

- 非機能要件テスト（#243）
  - Windows の音声合成（SAPI）で書き出していた WAV を、`tests/support/inprocess.py` の `synthesize_speech`（Windows は SAPI、Linux は Open JTalk）で書き出す
  - `tests/nfr/test_max_segment_length.py` の `sys.platform != "win32"` の skip を外し、Linux の VM で pass する
  - `tests/nfr/test_segment_callback_latency.py` の docstring の SAPI の記述を、今の音声合成の扱いに合わせる
  - GPU を前提にするテストの Linux での扱いは、下の `未確定` で決める
  - テスト実行方法の非機能要件テストの層に Linux の前提とコマンドを記載し、共通の前提の「非機能要件テストのうち Windows の音声合成（SAPI）で書き出した WAV を前提にするものは Linux では skip する」を今の扱いに合わせる
  - 非機能要件の各項目の `measurement`・測り方の `condition`・`notes` のうち、SAPI・Windows・GPU を前提にした記述に Linux での扱いを記載する
- release の E2E の実行（#244）
  - tester が release の E2E の実行で、Windows での実行に加えて、検証環境の VM で `.venv/bin/python -m pytest tests/e2e --run-e2e` を全件流し、結果を対象ケースの集約に含める
  - プロジェクトの直下の `agent_context.yaml`（新規）の `phase_extensions.tester` に拡張の行を追加し、フェーズの本文を `dev/エージェント運用/エージェント/tester/` に置く
  - VM の前提（自動起動の常駐アプリを終わらせてから流す・メモリを 8 GB の固定で割り当てる・全件で約 36 分かかる）を手順に含める

`未確定`: GPU を前提にする非機能要件テストの Linux での扱い（決める段: PoC 検証）

対象は `requires_real_whisper` を付けたテスト（`test_paste_latency.py`・`test_single_instance_timeout.py`・`test_worker_recovery_time.py`・`test_worker_stop_timeout.py`）と、`test_transcription_parity.py`・`test_segment_callback_latency.py`。
検証環境の VM には GPU が無い（[#203](https://github.com/shuhei1101/voice-paste/issues/203)）。

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | Linux では GPU を前提にするテストを skip し、GPU を使わないテストだけを流す。決定値は OS で分けない | 決定値の根拠（Windows 11・RTX 5070 の実測）を変えずに済む | Linux の CPU での時間は非機能要件テストで確かめない |
| B | Linux の既定の設定（`local_whisper`・`cpu`・`int8`）で測り、Linux 用の決定値を非機能要件に追加する | Linux での時間を決定値で守れる | 決定値を OS ごとに持つ設計の変更になり、`main.py` の定数も OS で分けるかを決め直す |
| C | Linux の CPU で、Windows と同じ決定値で測る | 決定値が 1 つのまま | CPU では GPU の決定値を超えて fail しうる |

推奨: A

決定値は Windows と GPU で測った値から決めており、CPU の値で守る対象が要望に無い。
GPU のある Linux での測定は #203 で扱う。
PoC 検証で、GPU を使わないテストが VM で pass することと、GPU を前提にするテストの CPU での値を参考に測る。

`未確定`: tester が検証環境の VM を操作する手段（決める段: PoC 検証）

tester は VM の外（WSL）で動くため、VM の起動・VM へ入る手段・Xorg のセッションへのログイン（ロックの解除を含む）が要る。

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | Windows の PowerShell（Hyper-V の `Start-VM`）で VM を起動し、WSL から鍵で SSH して、Xorg のセッションの `DISPLAY` を渡して pytest を流す。Xorg のセッションは自動ログインにする | tester だけで流せる | SSH の鍵の登録と自動ログインの設定にユーザーの操作（sudo）が要る |
| B | ユーザーが VM を起動・ログインして流し、結果のログを PR に貼る | VM の設定を変えない | release のたびにユーザーの操作が要る |

推奨: A

release のたびに約 36 分の実行をユーザーに頼まずに済む。
設定はユーザーの操作が 1 回で済み、PoC 検証で通ることを確かめてから反映作業に書く。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| Linux の GPU（CUDA）での非機能要件テストの実行 | 検証環境の VM に GPU が無い。GPU のある Linux の端末を用意できるまでの範囲 | [#203](https://github.com/shuhei1101/voice-paste/issues/203) |
| Wayland のセッションでの非機能要件テスト・E2E の実行 | 要望は Xorg のセッション。Wayland のホットキーと貼り付けは別の Issue の範囲 | [#200](https://github.com/shuhei1101/voice-paste/issues/200) |
| Linux で非機能要件の決定値を測り直して変える | 決定値は Windows の実測から決めている。案 B を選んだ場合だけ範囲に入れる | 予定なし |
