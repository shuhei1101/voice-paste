E2E の常駐アプリは venv の `python.exe` で動き、通知の送り主も `python.exe` になる。
この PC の通知の設定は `ToastEnabled=1` で、`HKCU\Software\Microsoft\Windows\CurrentVersion\Notifications\Settings` に python の項目は無い（[Issue #69](https://github.com/shuhei1101/voice-paste/issues/69) の tester の切り分け）。

## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 通知の切り分け | 実機で `--data-dir` の一時フォルダの常駐アプリを起動の失敗の状態で立ち上げ、通知のトーストが画面に出るかと、通知センターに残るかを確かめる | 結果をこの計画書に書き、要件の `未確定` を決める |
| E2E の確かめ | 通知が画面に出る場合、`_notification_in_center` の確かめを外し、2 件とも `notified`（`engine_unavailable`・`api_unavailable`）で知らせを出したことを確かめる | 要件の `未確定` の案 A のとき |
| 常駐アプリの通知 | 通知が画面に出ない場合、原因を調べて `show_failure` の出し方を直す | 起点 Issue を `type:bug` に書き直し、モジュール構成設計・単体テスト作成の行を開き直す |
| 待ちの定数 | `_notification_in_center` を外す場合、それだけが使う `TOAST_SETTLE_SEC` も消す | - |
| 既存機能への影響 | 常駐アプリの知らせの見出し・本文・押したときの動きを変えない | 結合テスト `test_tray_notification.py` で確かめる |
