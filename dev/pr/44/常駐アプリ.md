## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 固定の出力先 | 貼り付けて送信・貼り付けのみ・コピーのみの 3 つは今の `OUTPUTS` と `outputs[]` のまま残す。`ai_chat` の出力先は消し、設定の `ai_chat` の項目（`open_delay_sec`・`targets[]`）は読み替えの元として非推奨（deprecated）で残す | - |
| 既存の設定の読み替え | `settings.toml` の `outputs` に `id = "ai_chat"` の項目があれば、検証の前に `targets[]` をブラウザ添付種類のプリセット（Enter まで送る）へ読み替え、`ai_chat` の項目を外す。保存するときは新しい形で書く | 今の `load_settings` は検証に通らなければ `SettingsError` で起動できず、`save_settings` の `_read_existing` は検証に通らない文書を空の文書として書き直すため、読み替えは両方の読み込みの前に入れる |
| カスタムプリセットの設定 | 設定にプリセットの一覧を持つ。1 件は、タイトル・種類・URL・確定のホットキー・有効 / 無効と、種類ごとの値（ブラウザ添付: Enter まで送るか。エンドポイントへ送る: `Authorization` の値）を持つ。既定は空の一覧 | 画面設計の段で `presets[]`（`kind` で種類を分ける 1 つの一覧）と `preset_options.{種類}` に決めた（設定の設計書）。`Authorization` の値は秘密として扱う |
| プリセットの種類 | 種類ごとに届け方の関数を持つ一覧を作り、種類を足すときはその一覧へ登録する形にする。まずはブラウザ添付・エンドポイントへ送るの 2 つ | 品質シナリオ 5 と同じく、種類どうしは import しない |
| ブラウザ添付 | 今の `send_to_ai_chat` の届け方（クリップボード・Edge の `--app`・開くまでの間・貼り付け・Enter までの間・Enter）を、プリセットの「Enter まで送るか」がオフなら貼り付けで止める形にする | 開くまでの間は種類のオプション `preset_options.browser.open_delay_sec`（全てのプリセットで共通）に置く。Enter までの間は今のとおり貼り付けて送信の `enter_delay_sec` を使う |
| エンドポイントへ送る | 起こした文字を JSON にして URL へ POST し、2xx で届いたとする。リダイレクトは追わない。送り直さず、届かなければ `DeliveryError`。送り先のホストは制限しない | 送る中身・認証はインターフェース定義『設定のエンドポイントへ送る』 |
| HTTP の送り方 | `callback/client.py` の `post_json` を `integrations/http/client.py` へ移し、ヘッダーを渡せるようにして、呼び出し元へ返すとエンドポイントへ送るの両方が注入で受ける。送る中身（`ResultPayload`）は `features/outputs/types.py` に置いて両方が使う | 出力先どうしを import しないため、`features/outputs` の外か親の `types.py` に置く |
| 確定の操作 | 録音の画面のプリセットのボタンとプリセットのホットキーは、今の AI チャットの送り先と同じく、`SessionManager.complete` へプリセットを指す値を渡して確定する | 確定したときのプリセットの写し（`Preset`）を `SessionManager.complete(preset=...)` で渡し、セッションが `output_preset` に持つ（`output_target` は無くす） |
| 配線 | `main.py` の `_wire_outputs` と `build_hotkey_bindings` を、プリセットの種類ごとの注入と、有効なプリセットのホットキーの登録に置き換える。プリセットは確定したときの写しで届け、種類のオプション（開くまでの秒数・タイムアウト）は届けるたびに設定を読む | - |
| 画面 | 録音の画面は AI チャットの見出しと送り先のボタンを、カスタムプリセットの見出しとボタンに置き換える。設定画面は AI チャットの送り先の一覧を、種類ごとのタブ（ブラウザ添付・エンドポイントへ送る）に分け、それぞれにプリセットの一覧（有効 / 無効・タイトル・URL・種類ごとの値・確定のホットキー・上へ / 下へ・消す・足す）とその種類のオプションを置く | 画面設計『設定画面』『録音の画面』 |
| エラー | 届けられなければ `DeliveryError` を送出し、セッションが `delivery_failed` を知らせて待機中へ戻す | 今の仕組みのまま |
| テスト | 単体は種類ごとの届け方を、外部の操作を差し替えて確かめる（ブラウザ添付は Enter まで送る / 送らない、エンドポイントへ送るは送る中身・2xx 以外・接続できない）。結合は 127.0.0.1 のテスト用の受け口へ届くこと（無効のプリセットと API の録音で送らないことは、単体の deliver・build_hotkey_bindings と画面の結合テストで確かめる）、`ai_chat` の項目が残った `settings.toml` を読んでプリセットに読み替え、保存すると `ai_chat` の項目が無くなり同じ送り先がプリセットとして書かれることを確かめる。画面の結合テストはプリセットのボタンと設定画面のプリセットの一覧を確かめる | E2E は単一ユースケース設計でシナリオに `test_file` を置いてから作る。モジュール構成の `test_files` は、まだ無いテスト関数を書くと検証に通らないため設計の段で空にしてあり、単体テスト作成で次のとおり戻す: 5504ff4 の各設計書の `test_files` から `features/outputs/ai_chat/test_service.py`・`features/outputs/callback/test_client.py` を外し、`features/outputs/test_types.py`・`features/outputs/browser/test_service.py`・`features/outputs/endpoint/test_service.py`・`integrations/http/test_client.py`・`ui/windows/test_settings_presets.py` を足す |
