# 要件

## 要望

画面・トレイの E2E を、実機のマウス・キーボードを使わず、操作された体を常駐アプリへ渡す形にする。

- `--run-e2e` を付けて E2E を全件流しても、マウスカーソルを動かさず、マウスのボタンとキーの押下を合成しない（`tests/` に `SetCursorPos`・`mouse_event`・`keybd_event`・SendInput（pynput の `keyboard.Controller`）を呼ぶコードが無い）
- クリックした・キーを打ったという操作は、常駐アプリが受け取る形で渡す
- 流している間、テストが出す画面・メニュー・ウィンドウがユーザーの前面のウィンドウとキーボードのフォーカスを取らないようにする（取らない形にできない確かめは、下の `未確定` で扱いを決める）
- 単一ユースケース「常駐アプリを起動する」「設定を変える」「トレイから操作する」の E2E の各ケースが確かめている期待値は保つ。確かめ方を替えるケースは、替えた後の確かめ方をシナリオとテスト実行方法に書く
- 使われなくなった支えのコード（`click`・`type_keys`・`press_hotkey`・`force_foreground`・使われていない `open_notification_center` など）は消す
- 常駐アプリは pytest のプロセスの中で `main()` から起動し（`--data-dir` の一時フォルダ、Qt は offscreen で画面に出さない）、起動・設定の読み込み・文字起こしワーカー・API・片付けは本物を通す。トレイのメニューは項目の trigger、画面のボタン・欄はクリックとキーを Qt のイベントで渡し、ホットキーの受付は差し替えて押された体で登録された関数を呼ぶ。終了コードは `main()` の戻り値で、Ctrl+Break は自分のプロセスへ送る SIGBREAK で確かめる
- 単一インスタンスの入れ替わりのケースと、再起動で起動し直す新しいプロセスは、別プロセス（Qt は offscreen）で動かし、操作をせずにログ・トークンのファイル・プロセスで確かめる。別プロセスの常駐アプリは録音開始のホットキーを普段使わない組み合わせにした設定で起動し、ユーザーの打鍵で録音を始めない

`未確定`: Windows のシェルの部品（タスクバーのトレイのアイコン・隠れたアイコンの一覧・エクスプローラー）に触る確かめをどこまで残すか（決める段: 単一ユースケース設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 残さない。トレイの状態は常駐アプリが持つヒントの文字で、フォルダを開くは開く呼び出しに渡されたパスで確かめる | 隠れたアイコンの一覧を開いて閉じ、前面を戻す操作が無くなる。シェルの表示の違いで読めない・選べない不備が起きなくなる | シェルにアイコンが出る・ヒントが変わる・エクスプローラーが開くことを E2E で確かめなくなる |
| B | 読むだけ残す。トレイのヒントは UI Automation で読み続け（隠れたアイコンの一覧は開かない）、エクスプローラーも開いて確かめる | シェルへの表示を E2E で確かめ続けられる | アイコンが隠れたアイコンの一覧に入ると読めない。エクスプローラーの窓が前面に出る |

推奨: A

シェルへの表示は Qt（`QSystemTrayIcon`・`QDesktopServices`）が受け持ち、常駐アプリが決めているのは渡す文字とパス。
シェルの読み方は同じ範囲を直し続けており（`## 変更箇所の由来`）、依存を残すと同じ直しが続く。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| 「設定を変える」の正常シナリオと「カスタムプリセットを足す」の E2E（変えた設定で録音を始める） | 実機のマイクを開くため #65 で外した。この PR のプロセスの中で起動する形に、録音の入力を WAV に差し替える形を足せば置けるが、要望に含まれない | 起票予定 |
| v0.3.0 の E2E（#38・#52）を流す時期 | 計画の扱いで、この PR の変更ではない。計画では #38 がこの PR の後に流す形になっている | [#38](https://github.com/shuhei1101/voice-paste/issues/38) |
| E2E だけが使う常駐アプリの口（`VOICE_PASTE_ACCEPT_INJECTED_HOTKEYS` で合成したキーをホットキーとして受ける起動）を消す | `src/` を変える別の変更。この PR で E2E が合成したキーを使わなくなれば、口を消す前提が揃う | [#67](https://github.com/shuhei1101/voice-paste/issues/67) |
| E2E の貼り付け先が前面に出せないときの失敗と、失敗したテストの窓の残り | `force_foreground` に触るが、報告の元の貼り付け先は [#66](https://github.com/shuhei1101/voice-paste/pull/66) で消えている。残りの範囲は #61 の着手時に確かめる | [#61](https://github.com/shuhei1101/voice-paste/issues/61) |
| 外部デバイスからの実際の入力を通さず、入力された体からテストする規約 | 全プロジェクトに当てる規約で、AI Monitor 側が持つ | [ai-monitor#2579](https://github.com/shuhei1101/ai-monitor/issues/2579) |
