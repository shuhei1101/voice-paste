# 要件

## 要望

Ubuntu 24.04 の Xorg のセッションで、起動から貼り付けまでが通り、Linux の起動の手段と手順がある。
Windows の起動（`voice-paste.bat`）と環境の作り方は変えない。

- 起動から貼り付けまでの通しの確認
  - 検証環境の VM（`voice-paste-ubuntu`）の Xorg のセッションで、起動の手段から起動 → ホットキーで録音 → 文字起こし → アクティブなアプリへの貼り付けまでが通る
  - トレイのメニュー・設定画面・録音の画面が表示され、操作できる
  - 文字起こしは `local_whisper` を `device = "cpu"`・`compute_type = "int8"`（Linux の既定値）で動かす。OpenAI API でも起こせることを確かめる
  - マイクの入力は、WAV を PipeWire の仮想マイクへ流して与える
  - 確かめた結果は、VM の画面のスクリーンショットを PR ドキュメントに残す
- 起動の手段
  - リポジトリの直下に Linux の起動のスクリプトを置く。`voice-paste.bat` と同じく、起動のたびに `uv sync --frozen --extra local-whisper` を流して `.venv/` を `uv.lock` に揃え、`voice_paste` を import できるか確かめてから、端末から切り離して常駐サービスを起動する
  - 起動の記録（起動した時刻・`uv sync --frozen` の出力・使った Python・終了コード）は、Linux のログの置き場所（`~/.local/share/voice-paste/log/launcher.log`）に書く
  - 環境を作れないときは常駐サービスを起動せず、理由の行（`voice-paste.bat` と同じ `[ERROR]` の行）と `launcher.log` の場所を出して 0 以外の終了コードで終わる
  - ログイン時に自動で起動できる `.desktop` のファイルを置き、アプリの一覧（GNOME のアプリの一覧）からも起動できるようにする
- Linux の既定のホットキー
  - Ubuntu が Ctrl+Alt+D を「デスクトップを表示」に割り当てているため、Linux の既定の 5 つのホットキーを Super+Alt にする（録音開始・貼り付けて送信 `<cmd>+<alt>+d`、一時停止 `<cmd>+<alt>+z`、取り消し `<cmd>+<alt>+q`、貼り付けのみ `<cmd>+<alt>+v`、コピーのみ `<cmd>+<alt>+c`）
  - Windows の既定（Ctrl+Alt）は変えない
- 手順
  - `docs/使い方/起動と設定.md` に、Linux の環境の作り方（入れる OS のパッケージ: `xclip`・`libportaudio2`・`libxcb-cursor0`）・起動・自動起動の設定と止め方・起動に失敗したときの理由の行と、モデルを取得する初回の起動でトレイのアイコンが出ないときに起動し直す回避を記載する

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| Linux での E2E の自動の実行（SAPI に代えて WAV を仮想マイクへ流す E2E の仕組み） | スコープに含めるか判断が分かれる。Issue の要望は VM で通して確かめることで、E2E の自動化は求めていない。E2E の前提（SAPI・Windows のシェル）を Linux に置き換える作業は 3 pt の範囲を超えるため、含めない判断にする。PoC で仮想マイクの入力が通れば、その手段を元に起票する | 起票予定 |
| Wayland のセッションでのホットキーと貼り付け | 別の Issue の範囲 | [#200](https://github.com/shuhei1101/voice-paste/issues/200) |
| Linux の GPU（CUDA）での文字起こし | 別の Issue の範囲。検証環境の VM に GPU が無い | [#203](https://github.com/shuhei1101/voice-paste/issues/203) |
| Ubuntu 以外のディストリビューションのパッケージ名と起動の手段 | 対応する Linux は Ubuntu 24.04 の GNOME（非機能要件『動作環境』） | 予定なし |
| モデルを取得する初回の起動で、トレイのアイコンが上のバーに出ない | PoC で見つかった不具合で原因を特定できておらず、作業量が読めない。手順のページに再起動での回避を記載する（[確認ログ](./確認ログ.md)） | 起票予定 |
| Linux で設定画面の左の一覧の「エンドポイントへ送信」の末尾が切れ、横のスクロールバーが出る | PoC で見つかった崩れ。横にスクロールすれば読めて操作もできる。原因（文字幅・フォント）の調査と、Windows と共通の画面のレイアウトの変更は Linux の起動の手段という主題から外れる | 起票予定 |
| Linux で設定画面のチェックボックスの描画の結合テストが fail する | base ブランチでも fail する既存の不具合で、要望に含まれない | [#212](https://github.com/shuhei1101/voice-paste/issues/212) |
