# 要件

## 要望

Ubuntu の Wayland のセッションで、ホットキーで録音を始め、起こした文字をアクティブなアプリへ貼り付けられる。
Windows と Ubuntu の Xorg のセッションの動きは変えない。

- セッションの種類で実装を選ぶ
  - Linux では、起動したときのセッションの種類（`XDG_SESSION_TYPE` が `wayland` か）で、ホットキーの受付・キーの送信・クリップボードの実装を選ぶ
  - 選ぶのは `main.py` の配線だけにし、各モジュールはセッションの種類を見ない
- ホットキー
  - Wayland のセッションでも、設定のホットキー（録音開始・一時停止・取り消し・出力先ごとのホットキー）で操作できる
- 貼り付け
  - Wayland のセッションで、ネイティブの Wayland のアプリ（GNOME のテキストエディター 等）と XWayland のアプリの両方へ、設定の貼り付けのキーで貼り付けられる
  - 貼り付けて送信の Enter も送信できる
  - クリップボードへ書けて、「コピーのみ」で書いた文字を Wayland のアプリで貼り付けられる
- 画面
  - 録音の画面・文字起こし中の表示・トレイ・設定画面が、Wayland のセッションでも表示され、操作できる
- 確かめ方
  - 検証環境の VM（`voice-paste-ubuntu`）を Wayland のセッションで起動し、起動の手段から起動 → ホットキーで録音 → 文字起こし → 貼り付けまでを通す
  - 確かめた結果は、VM の画面のスクリーンショットを PR ドキュメントに残す
- 手順
  - `docs/使い方/起動と設定.md` の Linux の節に、Wayland のセッションで入れる OS のパッケージと、要る設定（`/dev/uinput` の権限）を記載する

PoC 検証で決めた方法（[PoC 結果](./常駐アプリ.md#poc-結果)）:

| 論点 | 決めた方法 | 理由 |
| --- | --- | --- |
| 対象にする Ubuntu のバージョン | Ubuntu 24.04（GNOME 46）の Wayland のセッション | 動作環境（非機能要件『動作環境』）の Ubuntu 24.04 は Wayland が既定で、検証環境の VM で確かめられる。下の方法は portal の GlobalShortcuts に依らず、25.10 以降でも同じ方法で動く |
| Wayland のホットキーの受け方 | 常駐サービスが設定のホットキーを GNOME のカスタムショートカット（ユーザーの dconf の `custom-keybindings`）へ登録し、押されるとコマンドが単一インスタンスの終了の依頼のソケット（同じ uid の接続だけを受ける）へ押されたホットキーを伝える。常駐サービスは今のホットキーと同じく状態で操作を振り分ける。登録はトレイの終了・SIGTERM での終了・設定画面を開いている間に外し、起動のたびに前の登録の残りを外してから登録する | 24.04 の GNOME の portal に GlobalShortcuts が無い。`/dev/input` を読む方法は、全てのキー入力を読める権限を常駐サービスへ渡す |
| Wayland のキーの送信の方法 | python-evdev の `UInput` の仮想キーボードで、貼り付けのキーと Enter（修飾キーつき）を送信する。`/dev/uinput` の権限（udev の規則と `input` グループへの追加の後に再起動）は利用者が sudo で設定する | portal の RemoteDesktop は許可のダイアログと画面の共有の表示が出続ける。pynput の uinput のバックエンドは root で動かす必要がある。`ydotool` は使わずに済んだ |
| Wayland のクリップボード | XWayland の `xclip` で書く（pyperclip の書き先を `xclip` に指定する）。貼り付けのキーの前の待ちは Xorg のセッションと同じにする | `wl-copy` は書くたびに貼り付け先のフォーカスを取り、文字起こし中の表示を出した通しで 20 回中 8 回貼り付けのキーが落ちた。`xclip` は 20 回とも落ちず、フォーカスも動かなかった |
| Wayland の画面 | Qt のプラットフォームを `xcb`（XWayland）に固定する | ネイティブの `wayland` では、録音の画面と文字起こし中の表示が設定の位置に置けず、貼り付け先のフォーカスを取る |

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| Wayland のセッションで、端末アプリへの貼り付けを Ctrl+Shift+V に替えること | スコープに含めるか判断が分かれる。Xorg では `python-xlib` でアクティブなウィンドウの WM_CLASS を読んで端末アプリを見分けているが、GNOME の Wayland にはアクティブなウィンドウを読む標準のインターフェースが無い。Issue の要望は貼り付けまでで、端末アプリは求めていない。含めない判断にし、レビューで確定する | 起票予定 |
| Linux での E2E の自動の実行 | 別の Issue の範囲 | [#219](https://github.com/shuhei1101/voice-paste/issues/219) |
| GNOME 以外のデスクトップ環境（KDE Plasma 等）の Wayland | 対応する Linux は Ubuntu の GNOME（非機能要件『動作環境』） | 予定なし |
