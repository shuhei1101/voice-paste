# 要件

## 要望

文字起こしのエンジンに Haas-ja-v1.0（以下 Haas）を追加し、設定の `transcription.engine` で選べるようにする。

- Haas は WSL の中で動かす文字起こしのサーバーで実行し、Windows の常駐アプリは録音をサーバーへ HTTP で送信して、起こした文字を受け取る
- エンジンが Haas でサーバーへ接続できない環境では、faster-whisper（`local_whisper`）で文字に起こす
- ホットキー・トレイ・API の録音、連続録音の区間、外の端末のブラウザから送信した音声のどれも、選んだエンジンで起こす
- 表記のヒントの単語ごとに読みを入力する欄を追加し、表記と読みの組を Haas の `haas_asr.Vocabulary` へ指定する。文字起こしの後の用語集の補正は今と同じ
- 既定のエンジンは `local_whisper` のまま変えない
- 採用の判断: PoC 検証で、表記のヒントの単語を含む voice-paste の録音を Haas と faster-whisper で起こし、精度（CER）・速さ・表記のヒントの単語の認識を比べる。Haas が表記のヒントの単語の認識で faster-whisper より劣る場合は、続けるかをユーザーへ確認する

判断: 表記のヒントの単語ごとに読みを入力する欄を追加し、読みを Vocabulary へ指定する（PoC で、読みを指定しない Vocabulary は指定しないときとほとんど変わらなかった。[確認ログ](./確認ログ.md)）

判断: 常駐アプリが起動時に `wsl.exe` で WSL の文字起こしのサーバーを起動し、終了・再起動で止める。起動の前から接続先が応答するときは、そのサーバーを使い、止めない（今の常駐アプリはショートカットからの起動だけで文字起こしまで準備でき、同じ流れに揃える）

判断: faster-whisper へは起動の単位で切り戻す。起動時にサーバーへ接続できなければ終了まで faster-whisper で起こし、起動の後のサーバーの失敗はその録音の文字起こしの失敗にする（Issue の要望は環境の単位の切り戻しで、Haas と faster-whisper のモデルを同時に GPU へ読み込まない）

判断: Haas を使用できるのは、WSL2 のネットワークが mirrored のモードの端末に限る。使い方『起動と設定』に mirrored へ切り替える手順を記載する（[確認ログ](./確認ログ.md)）

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| 既定のエンジンを Haas にする | WSL と NVIDIA GPU が無い環境では動かないため、既定は `local_whisper` のままにする | 予定なし |
| Haas の低遅延のストリーミング | 連続録音も区間を区切ってから起こすため、オフラインの書き起こしで足りる | 予定なし |
| Docker の Linux で Haas を動かす | 要望は WSL の環境で使用できること | 予定なし |
| Linux（Ubuntu）の常駐アプリから Haas を使用する | 判断: 今回は Windows の常駐アプリと WSL に限る。Linux の常駐アプリは同じサーバーを WSL を通さずに起動すれば使用できる見込みだが、今回の方針が決まらないと中身が決まらない。検証の VM には NVIDIA GPU が無い | 起票予定 |
