# 要件

## 要望

E2E と実機の非機能要件テストが起こす常駐アプリ（`python -m voice_paste --data-dir {一時フォルダ}`）を、`QT_QPA_PLATFORM=offscreen` でなく実機の Windows の画面で起動し、画面とトレイのアイコンを実機に出す。

- `tests/support/real_service.py` の `spawn_process` が常駐アプリへ渡す環境変数に `QT_QPA_PLATFORM` を含めない。pytest を `QT_QPA_PLATFORM` を付けて起こしても、付けずに起こしても同じにする
- 結合テストの画面（`tests/integration/ui/`）は、これまでどおり `tests/conftest.py` の設定で offscreen の QApplication で開く
- Issue #63 で fail した複合ユースケース「ほかのシステムから録音を文字に起こす」の `test_error_when_hotkey_recording` と、複合ユースケース「声で入力した文字を貼り付ける」の `test_normal` が、`start_app` の `wait_tray_state(IDLE)` で `トレイが 待機中 にならなかった（今は None）` によって fail しない
- 下の表の `実行のみ` の行の E2E も、常駐アプリが offscreen で起動したことでトレイの状態を読めずに fail しない
