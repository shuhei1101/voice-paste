# 要件

## 要望

knowledge の規約『文章の書き方』の `## 語の選び方` を正として、`src/`・`tests/` の次の文言を修正する。

| 対象 | 修正方法 |
| --- | --- |
| `.py` のコメント・docstring・式文だけの文字列 | 対応表の避ける語を使う語に置き換える。文章の中の自然な用法（取り消す・やり直す・立て直す などの複合語）は残す |
| `.py` のログの呼び出しの引数の文字列 | 同じ。「消した」は「削除した」、「消せなかった」は「削除できなかった」、「送った」は「送信した」にする。その文言を引くモジュール構成の設計書のログの行と、ログの文言を照合するテストを合わせる |
| ログに出る表示の文字列 `DELETED_MARK`（`features/correction/service.py`） | `（消す）` を `（削除）` にする。文でなく 1 語の表示のため、対応表の使う語にする |
| `.ts`・`.css`・`.html` のコメント | `.py` のコメントと同じ。`app.js` は `app.ts` から生成し直す |

コードの識別子・Enum の値・定数名・設定のキーは英語のまま変えない。
ログは開発者が原因を調べるための記録で、画面にも通知にも出ないため、ユーザーの目に触れる語彙として扱わない。

終わりの条件:

- 修正した後に [集計/commentscan.py](./集計/commentscan.py) で数え直し、前後の件数を PR に記載する。修正前は develop の `a2f2614` で 1329 件（135 ファイル。`src/` 646 件・`tests/` 683 件）
- 残った件数は全て、文章の中の自然な用法か、`## スコープ外` の範囲のもの

| 例外のメッセージ（`raise` の引数の文字列。`src/` で 4 件） | Issue はコメント・docstring・ログを挙げている。例外のメッセージは設定画面の入力チェックやトレイの通知で利用者の目に触れ、画面の文言として扱う範囲になる。この PR に含めるかはレビューで確定する | 起票予定 |
| `src/`・`tests/` の外のファイル（起動のバッチファイル `voice-paste.bat`・`pyproject.toml` など） | Issue の範囲は `src/`・`tests/` | 予定なし |
| テストの期待値として画面の文言を持つ文字列リテラル | 画面の文言の一部で、#183 が画面設計に合わせて修正済み | 予定なし |
