## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| メッセージ | `protocol.py` に 1 行の JSON の型（`config` / `ready` / `transcribe` / `progress` / `result` / `error`）を置き、常駐アプリの窓口（`client.py`）と共有する | - |
| ワーカーの本体 | `run_worker` は config を受けてモデルを読み、ready を返してから transcribe を 1 件ずつ処理し、区間ごとに progress、最後に result を返す。標準入力が閉じたら 0 で終わる | モデルを読む処理は注入で受け、単体テストで差し替える |
| 失敗の扱い | モデルを読めなければ error を返して 1 で終わる。1 件の文字起こしの例外は error を返して次の行を待つ。CUDA のクラッシュはプロセスごと落ち、常駐アプリが立て直す | - |
| 文字起こしの設定 | 言語・ビーム幅・温度・VAD などは transcribe のメッセージで受け、`voice_paste_legacy` と同じ引数で faster-whisper を呼ぶ | 品質シナリオ 2（刷新前と同じ文字）の前提 |
| CUDA の DLL | 常駐アプリの窓口がワーカーを起動するときに、venv の `nvidia-*` パッケージの DLL の場所を子プロセスの PATH の先頭へ足す | `voice_paste_legacy` は `voice-paste.bat` が PATH へ足している。新しい構成は起動のバッチファイルに頼らない |
| クラッシュの記録 | config で受けたログの置き場所の `worker_crash.log` へ faulthandler を向ける | `voice_paste_legacy` と同じファイル名 |
| 性能 | モデルの読み込みは起動時の 1 回だけにし、文字起こしのたびに読み直さない | 立て直しの時間の測り直しは [#22](https://github.com/shuhei1101/voice-paste/issues/22) |
