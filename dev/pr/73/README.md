# 前のケースのトレイのアイコンが残っていても、画面・トレイの E2E が自分のアイコンを選べるようにする

## 概要

前のケースの常駐アプリのトレイのアイコンが隠れたアイコンの一覧に残っていても、画面・トレイの E2E が、この常駐アプリのアイコンを選んでトレイのメニューを開けるようにする。

## 背景

[Issue #70](https://github.com/shuhei1101/voice-paste/issues/70) の E2E の不備。
release PR [#52](https://github.com/shuhei1101/voice-paste/pull/52)（`release/v0.3.0`、`8bac365`）の E2E で、単一ユースケース「トレイから操作する」のケースが `AppDriver.open_tray_menu` の `この常駐アプリのトレイのアイコンが見つからない` で fail した。
同じケースでも先頭で流すと pass し、流す順で fail するケースが変わる。

- 全件の実行では、直前の `test_normal_when_restart` の後始末が再起動した常駐アプリを強制終了した後に、再実行では、直前の `test_normal_when_quit` がトレイの「終了」で常駐アプリを終わらせた後に fail した
- 常駐アプリは `常駐サービスを始めた` まで進み、トレイのヒントも読めている。fail するのは、メニューを開くために自分のアイコンを探す `AppDriver.own_tray_icon`
- テストの常駐アプリのアイコンは隠れたアイコンの一覧に入る。前のケースのアイコンが一覧に残っていると、右クリックとメニューを閉じる操作で一覧が閉じ、残りの候補を押せなくなると見ている（fail した時点の一覧の中身は読んでいない）

実機のトレイの E2E の支えのコードの直しは [#54](https://github.com/shuhei1101/voice-paste/issues/54)・[#59](https://github.com/shuhei1101/voice-paste/issues/59) に続くもの。
