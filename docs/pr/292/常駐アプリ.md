## 変更方針

<!-- table: data -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 設定 | `recording.keep_display_on`（真偽値）を追加する | 既定値はオン |
| 抑止の開始と解除 | 録音の service が録音の開始で抑止し、確定・取り消し・失敗・打ち切りで録音を終えるときに解除する。音量の下げ・戻しと同じ箇所で呼び、解除は 1 回だけにする | 一時停止中も抑止を続ける |
| Windows の抑止 | `PowerCreateRequest` で電源要求を作り、`PowerSetRequest` の `PowerRequestDisplayRequired` と `PowerRequestSystemRequired` で抑止し、`PowerClearRequest` で解除する | 要求はハンドルで持つため、どのスレッドから呼んでもよい（PoC で確認した） |
| Linux の抑止 | 子プロセス `gnome-session-inhibit --inhibit idle --app-id voice-paste --reason ... cat` を、標準入力を親とのパイプにして録音の間だけ生かし、パイプを閉じて解除する | Xorg で PoC を確認した。Wayland は同じ GNOME のセッションの API のため Xorg の結果で代えた |
| アダプタの構成 | 音量のアダプタと同じく、OS ごとの実装と何もしない実装を `integrations/` の下に配置し、`main.py` の配線で選ぶ | 録音の service は関数型だけを受け取る |
| 失敗の扱い | 抑止・解除に失敗しても録音は止めず、警告のログを残す | - |
| 異常終了 | Windows はプロセスの終了で電源要求が消える。Linux は親の終了でパイプが EOF になり、子プロセスが終了して解除される | どちらも PoC で確認した |
| 設定画面 | 「録音」の区画に、録音中に画面を暗くしないかのチェックボックスを追加する。文言と位置はモックで決める | Windows と Linux のどちらでも欄を出す |
| 外の端末の画面 | 録音の開始で `navigator.wakeLock.request("screen")` を取得し、録音の停止・上限での自動送信・画面を離れるときに解放する。画面に戻ったとき録音中なら取得し直す | Wake Lock に対応しないブラウザでは抑止せず録音を続ける |
| 外の端末の画面のオン・オフ | 画面に端末ごとのオン・オフを配置し、localStorage に残す（既定はオン） | 文言と位置はモックで決める |
| 既存機能への影響 | 音量の下げ・戻しと録音の流れは変えない。API の要求・応答の構造は変えない | - |
| テスト | 単体: 録音の service の抑止と解除の呼び出し・設定のモデル・アダプタ（OS の API は差し替える）。結合: 設定画面の欄・外の端末の画面の Wake Lock の取得と解放 | - |

## PoC 結果

<!-- table: data -->

| 検証構成 | 成功条件 | 結果 | PoC PR | 補足 |
| --- | --- | --- | --- | --- |
| Windows W2: `PowerSetRequest`（ハンドルで持つ） | 依頼したスレッドの終了後も抑止が残り、解除と強制終了で消える。スクリーンセーバーが動かない | ✅ 全て満たした | [#293](https://github.com/shuhei1101/voice-paste/pull/293)（closed） | 採用 |
| Windows W1: `SetThreadExecutionState` の常駐スレッド | 同上 | ✅ 全て満たした | [#293](https://github.com/shuhei1101/voice-paste/pull/293)（closed） | 不採用（常駐スレッドとキューが要る） |
| Linux: `gnome-session-inhibit --inhibit idle ... cat`（VM の Xorg） | 抑止中はアイドルの抑止が 1 件。パイプを閉じる・子の強制終了・親の `kill -9` の後に 0 件 | ✅ 全て満たした | [#293](https://github.com/shuhei1101/voice-paste/pull/293)（closed） | 採用。Wayland は Xorg の結果で代えた |
| 外の端末の画面: 手元の Edge の `navigator.wakeLock.request("screen")` | 取得が resolve し、抑止が入る。`release()` で `released` が true になり、抑止が消える | ✅ 1 秒以内に抑止が入った | [#293](https://github.com/shuhei1101/voice-paste/pull/293)（closed） | 採用 |

結論: 成立。
Windows の観測は、非昇格で読める `CallNtPowerInformation(SystemExecutionState)` の `ES_DISPLAY_REQUIRED` で行い、各測定の前に値が含まないことを確認した。
スクリーンセーバーは、1 分に設定して 90 秒無操作のとき、抑止なしでは動き、W1・W2 では動かなかった。測定の後に設定を元に戻した。
管理者権限の `powercfg /requests` との突き合わせと、消灯の目視は、ユーザーの判断で行わず、AI の観測だけで成立とした（[確認ログ](./確認ログ.yaml)）。

最小再現コードの要点（[windows_inhibit.py](https://github.com/shuhei1101/voice-paste/blob/93b1ef1/poc/keep-display-on/windows_inhibit.py) の W2）:

```python
reason = REASON_CONTEXT(POWER_REQUEST_CONTEXT_VERSION, POWER_REQUEST_CONTEXT_SIMPLE_STRING, "voice-paste: recording")
handle = kernel32.PowerCreateRequest(ctypes.byref(reason))
for kind in (POWER_REQUEST_DISPLAY_REQUIRED, POWER_REQUEST_SYSTEM_REQUIRED):
    kernel32.PowerSetRequest(handle, kind)
# 解除
for kind in (POWER_REQUEST_DISPLAY_REQUIRED, POWER_REQUEST_SYSTEM_REQUIRED):
    kernel32.PowerClearRequest(handle, kind)
kernel32.CloseHandle(handle)
```

[linux_inhibit.py](https://github.com/shuhei1101/voice-paste/blob/93b1ef1/poc/keep-display-on/linux_inhibit.py) の抑止:

```python
proc = subprocess.Popen(
    ["gnome-session-inhibit", "--inhibit", "idle", "--app-id", "voice-paste", "--reason", "recording", "cat"],
    stdin=subprocess.PIPE,
    stdout=subprocess.DEVNULL,
)
proc.stdin.close()  # 解除。親が終了しても同じくパイプが閉じる
```

diff の見どころ: [windows_screensaver.py](https://github.com/shuhei1101/voice-paste/blob/93b1ef1/poc/keep-display-on/windows_screensaver.py) の対照（抑止なし）と W1・W2 の比べ方、[wake_lock.html](https://github.com/shuhei1101/voice-paste/blob/93b1ef1/poc/keep-display-on/wake_lock.html) の取得・保持・解放の記録。
