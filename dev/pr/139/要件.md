# 要件

## 要望

開発コマンドのページを足し、依存の追加・更新・削除と取り込み後の追従のコマンドを書く。

- Schema は AI Monitor の `dev/テンプレート/開発コマンド.schema.yaml` を書き換えずに取り込む（AI Monitor の v0.2.0 には無く、[ai-monitor#2430](https://github.com/shuhei1101/ai-monitor/pull/2430) で足された。取り込む版は AI Monitor の develop の [6470a86d5](https://github.com/shuhei1101/ai-monitor/commit/6470a86d5) 時点）
- 取り込んだ Schema に沿って `dev/設計書/開発コマンド/開発コマンド.yaml` を作り、次の 2 つの分類を書く
  - `依存の追加・更新・削除`: 依存を足す `uv add`（dev グループへ足すときは `--group dev`）・上げる `uv lock --upgrade-package`・外す `uv remove`
  - `取り込み後の追従（pull 後）`: `uv.lock` どおりに環境を合わせる `uv sync --frozen`
- 環境を作り替えるコマンドは Windows の uv（WSL からは `uv.exe`）で流す前提を書く（モジュール構成『起動と配線』の記述と揃える）
- 各分類のコマンドを流して確かめた記録（`verification`）を残す
- 設計書の検証（`design_docs validate`）が通り、`dev/テンプレート/README.md`・`dev/設計書/README.md`・`dev/設計書/開発コマンド/README.md` を `index.yaml` から生成し直す

## 影響するユースケース

なし（アプリの振る舞いを変えず、開発者が打つコマンドのページだけを足す）。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| 開発コマンドのページの残りの分類（環境構築（クローン直後）・起動・停止・テスト・静的検査・ビルド・生成・取り込み前の検査・管理作業） | 『コマンドの書き先』は差分で変わるコマンドごとに書き先を決め、この要望で書くのは依存の追加・更新・削除と取り込み後の追従のコマンドだけ。環境構築の `uv sync --frozen` は[使い方『起動と設定』](https://github.com/shuhei1101/voice-paste/blob/develop/docs/%E4%BD%BF%E3%81%84%E6%96%B9/%E8%B5%B7%E5%8B%95%E3%81%A8%E8%A8%AD%E5%AE%9A.md)と[テスト実行方法](https://github.com/shuhei1101/voice-paste/blob/develop/dev/%E8%A8%AD%E8%A8%88%E6%9B%B8/%E3%83%86%E3%82%B9%E3%83%88/%E3%83%86%E3%82%B9%E3%83%88%E5%AE%9F%E8%A1%8C%E6%96%B9%E6%B3%95.yaml)の前提が持っている。分類を足す差分が出たときにその作業 PR が書く | 予定なし |
| 開発コマンドの Schema 以外の AI Monitor の配布物への追従（`ai-monitor-version.ini` の更新を含む） | 要望に含まれない。配布元が起票する追従 Issue（`AI Monitor v{版} の配布物へ追従する`）で扱う | 予定なし |
