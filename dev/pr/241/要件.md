# 要件

## 要望

Ubuntu 24.04 の Xorg のセッション（検証環境の VM `voice-paste-ubuntu`）で、`.venv/bin/python -m pytest tests/e2e --run-e2e` の 1 コマンドで E2E テストが人の操作なしに最後まで走り、全てのケースが pass する。
Windows での E2E の動き（SAPI・Edge・GPU）は変えない。

- 録音の入力
  - SAPI で決めた文を書き出していた WAV を、Linux では Linux で動く音声合成で書き出す。録音の入力を WAV を流すものに差し替える仕組み（マイクを開かない）は変えず、仮想マイク（`tests/support/feed_mic.py`）は使わない
  - 書き出した WAV を起こした文字に、各ケースが期待する言葉（`SPEECH_WORD`・連続録音の文ごとの言葉など）が含まれる
- 外の端末の画面のケース
  - Linux で動くブラウザーを headless・偽のマイク（`--use-file-for-fake-audio-capture`）で起動し、DevTools Protocol で操作する
- プロセスとシグナル
  - プロセスの一覧と終了（`tests/support/processes.py` の PowerShell・`taskkill`、`tests/support/inprocess.py` の Toolhelp の snapshot）を Linux でも動くようにする
  - Windows だけのシグナル（Ctrl+Break の `SIGBREAK`）を上げるケースと、SIGBREAK のハンドラを元に戻す後片付けは、Linux では SIGBREAK を扱わない
- 文字起こし
  - Linux の既定の設定（`local_whisper`・`device = "cpu"`・`compute_type = "int8"`）で起こす
- テスト実行方法
  - E2E の層に Linux の前提（OS のパッケージ・Xorg のセッション・コマンドの読み替え）を記載し、「SAPI を使う `tests/support/inprocess.py` に依存するテストは Linux では skip する」の行を今の扱いに合わせる

`未確定`: Linux で WAV を書き出す音声合成の手段（決める段: PoC 検証。sudo で OS のパッケージを入れるため、ユーザーへ確かめる）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | Open JTalk（`open-jtalk`・`open-jtalk-mecab-naist-jdic`・`hts-voice-nitech-jp-atr503-m001` を apt で入れる） | 日本語の音声合成で、文の読みが自然 | sudo で 3 つのパッケージを入れる |
| B | eSpeak NG（`espeak-ng` を apt で入れる） | パッケージが 1 つで済む | 日本語の読みが機械的で、Whisper が期待する言葉に起こさないおそれがある |
| C | SAPI で書き出した WAV を文ごとにリポジトリへ置き、Linux ではそれを読む | Linux に OS のパッケージを入れない | 文を足す・変えるたびに Windows で WAV を書き出し直す |

推奨: A

各ケースは起こした文字に決めた言葉が含まれるかで判定するため、Whisper が正しく起こせる自然な読みが要る。

`未確定`: Linux で外の端末の画面のケースに使うブラウザー（決める段: PoC 検証。sudo で入れるため、ユーザーへ確かめる）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | Microsoft Edge の Linux 版（Microsoft の apt のリポジトリから `microsoft-edge-stable` を入れる） | Windows と同じブラウザーで、起動の引数をそのまま使える | apt のリポジトリと署名の鍵を追加する |
| B | Google Chrome（`.deb` を入れる） | Chromium 系で起動の引数が同じ | Windows と違うブラウザーになる |
| C | Ubuntu の Chromium（snap） | Ubuntu の標準の手段で入る | snap の閉じ込めで、偽のマイクの WAV（一時フォルダ）を読めないおそれがある |

推奨: A

Windows と同じブラウザーで、`tests/support/browser.py` の起動の引数と DevTools Protocol の操作を変えずに済む。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| 非機能要件テストを Linux で実行する（SAPI の skip の条件を持つ `tests/nfr/test_max_segment_length.py` など） | Issue の要望は E2E テストで、非機能要件テストの多くは Windows と NVIDIA GPU を前提にした値を測る。今回入れる Linux の音声合成を前提にした後続にする | 起票予定 |
| release の E2E の実行（tester）に Linux の実行を加える | スコープに含めるか判断が分かれる。Issue の要望は Linux で自動で実行できることで、スプリントの E2E の実行の手順を変えることは求めていない。含めない判断にする | 起票予定 |
| Linux の GPU（CUDA）での文字起こし | 別の Issue の範囲。検証環境の VM に GPU が無い | [#203](https://github.com/shuhei1101/voice-paste/issues/203) |
| Wayland のセッションでの E2E の実行 | Issue の要望は Xorg のセッション。Wayland のホットキーと貼り付けは別の Issue の範囲 | [#200](https://github.com/shuhei1101/voice-paste/issues/200) |
| Ubuntu 以外のディストリビューションでの実行 | 対応する Linux は Ubuntu 24.04 の GNOME（非機能要件『動作環境』） | 予定なし |
