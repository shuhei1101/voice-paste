# 要件

## 要望

- 文字起こし・用語集の補正・履歴を、方針の記録（[構造の決定](https://github.com/shuhei1101/voice-paste/blob/develop/dev/pr/12/%E6%96%B9%E9%87%9D%E6%B1%BA%E3%82%81/4_%E6%A7%8B%E9%80%A0%E3%81%AE%E6%B1%BA%E5%AE%9A.md)・[リスクと移行計画](https://github.com/shuhei1101/voice-paste/blob/develop/dev/pr/12/%E6%96%B9%E9%87%9D%E6%B1%BA%E3%82%81/5_%E3%83%AA%E3%82%B9%E3%82%AF%E3%81%A8%E7%A7%BB%E8%A1%8C%E8%A8%88%E7%94%BB.md)）と、[#26](https://github.com/shuhei1101/voice-paste/pull/26) で起こしたモジュール構成のとおりに `src/voice_paste/` に作る
  - 文字起こし: `features/transcription` にエンジンの型（関数型）とエンジンの種類を置き、設定で選んだエンジンで録音を起こして区間を改行でつなぐ。エンジンの失敗は `TranscriptionError` に変える
  - ローカルの Whisper: `integrations/whisper` の窓口が文字起こしワーカーの子プロセスを起動し、標準入出力の JSON Lines で録音を渡す。ワーカーが応答の途中で落ちたら 1 回だけ起動し直して同じ録音を送り直し、やり直しも落ちたら次の録音に備えて起動し直してから `EngineError` を送出する
  - 文字起こしワーカー: `integrations/whisper/worker.py` が faster-whisper のモデルを持ち、受けた録音を区間ごとの進みと結果で返す。モデルを読めなければ error を返して終わる
  - OpenAI: `integrations/openai` が OpenAI のエンジンの設定（API キー・モデル・言語・温度）で録音を送る。ローカルの Whisper の設定を流用しない。非機能要件の送れる大きさ（20,000,000 バイト）を超える録音は送らずに `EngineError` を送出する
  - 補正: `features/correction` が用語集の CSV（設定の `glossary_path`）を読み、誤変換を正しい表記へ用語集の行の順に置き換える
  - 履歴: `features/history` が確定した録音を `%LOCALAPPDATA%\voice-paste\history\{YYYYMMDD}\` に書き（履歴を残さない設定なら一時の音声のフォルダ）、録音と同じ名前の `.txt` に起こした文字を書き足し、保持期間を過ぎた日付のフォルダを消す
- 完了の定義
  - ローカルの Whisper と OpenAI の両方のエンジンで録音を起こせる
  - 特性テスト（品質シナリオ 2）を新しい構成の文字起こしと補正に向けて回し、履歴から選んだ 10 件の録音で補正後の文字が固めた期待値と 10 件一致し、補正だけを切り出したケースも全て一致する
  - ワーカーが落ちても録音が履歴に残る（品質シナリオ 4）: 録音の保存が文字起こしに依らず、ワーカーが落ちても 1 回の立て直しで起こし直せ、やり直しも落ちたときは `EngineError` で知らせて次の録音を受け付けられる
- 文字起こしの結果が空のときは空文字を返す（録音を履歴に残し、API の呼び出し元へ空の文字を返すのはセッションの流れ）
- 普段使い（`voice_paste_legacy` と、リポジトリの直下の `.env`・`history/`・`log/`）には触れない
  - 並走の間の動作確認と単体テストは、普段使いの置き場所（`%APPDATA%\voice-paste\`・`%LOCALAPPDATA%\voice-paste\`）に書かない
