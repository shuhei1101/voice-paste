## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 環境の確かめ | 起動のたびに `"%~dp0.venv\Scripts\python.exe" -c "import voice_paste"` を流し、終了コードが 0 なら今の起動へ進む。結果を `launcher.log` に書く | `python.exe` が無いときも終了コードが 0 以外になり、作り直しへ進む |
| 環境の作り直し | import できなければ、リポジトリの直下（`%~dp0`）で `uv sync --frozen` を流し、出力を `launcher.log` に追記する。uv は `where uv` で PATH から探し、無ければ `%USERPROFILE%\.local\bin\uv.exe` を使う | 作り直した後にもう一度 import を確かめる |
| エラー表示 | uv が見つからない・`uv sync` が 0 以外・作り直しても import できないときは起動せず、コンソールに理由と `launcher.log` のパスを表示して `pause` で止まり、0 以外の終了コードで終わる | 文言は設計書『常駐アプリ / 起動と配線』の `directory` |
| システムの `pythonw` | `.venv` が無いときにシステムの `pythonw` で起動する分岐を消す | - |
| 既存機能への影響 | import できるときの起動（`.venv` の有効化・CUDA の DLL の `PATH`・`chcp 65001`・`FOR_DISABLE_CONSOLE_CTRL_HANDLER`・`.venv\Scripts\pythonw.exe -m voice_paste` を引数なしで `start`）は変えない | バッチファイルの中は ASCII だけで書く。改行は CRLF（`.gitattributes`） |
| 性能 | import の確かめは起動のたびに流す | Issue の起票時の手元の測定で 0.1 秒弱 |
| 確かめ方 | 実装の工程で、Windows で次の 3 つの状態でバッチファイルを流し、`launcher.log` とコンソールの出力を `テスト結果/` に置く: `.venv` で import できる（そのまま起動する）・`.venv` が無い（`uv sync` の後に起動する）・`uv sync` が失敗する（uv を見つけられない状態にして、理由が出て止まる） | 自動のテストは置かない |
