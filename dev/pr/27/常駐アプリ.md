## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| パッケージの移し替え | `git mv voice_paste voice_paste_legacy` で移し、中の `voice_paste.` の import と patch の対象を `voice_paste_legacy.` へ置き換える | 履歴を追えるよう、移す commit と中身を直す commit を分ける |
| ログ | ハンドラーを付けるロガーを `voice_paste_legacy` にして、子ロガーのログが今と同じログファイルに出るようにする | ログファイルの名前（`{日時}_voice_paste.log`）は変えない |
| 名前を変えないもの | PID ファイル（`voice_paste.pid`）・ログと履歴の置き場所・トレイの名前・`.env` の読み込み先 | 普段使いの設定と履歴をそのまま引き継ぐ |
| 起動のバッチファイル | `-m voice_paste` を `-m voice_paste_legacy` にする | 失敗時のメッセージも追随させる |
| pyproject.toml | スクリプトの入口を `voice_paste_legacy.main:run`、パッケージの検出を `voice_paste_legacy*` にする | 新しい構成の `src/voice_paste/` は #16 で足す |
| 配布用のビルド | `setup/build_exe.bat` の入口のパスを `voice_paste_legacy\__main__.py` にする | ビルドの仕組みは #23 で消す |
| 既存のテスト | import と patch の対象を `voice_paste_legacy.` へ追随させ、今と同じに通す | - |
| 特性テスト | `tests/nfr/test_transcription_parity.py` に、履歴から選んだ録音を今のローカルの Whisper で起こして補正した文字が履歴の文字と一致すること、補正だけを切り出した決まった入力と出力の一致を置く | Windows の GPU が要るため、無い環境では skip する |
| 特性テストの録音 | 履歴から長さの違う録音を 10 件選び、録音と履歴の文字を git 管理外のフォルダ（`tests/nfr/fixtures/`、中身が `*` の `.gitignore` を置く）へ写して使う | 録音と話した中身をリポジトリへ入れない。履歴は保持期間で消えるため写しを持つ |
| 測定 | 選んだ約 10 秒の録音を今の経路（ワーカーの文字起こし → 補正 → クリップボード）へ流し、録音を止めた時点から貼り付けのキーを送る直前までをミリ秒で 20 回測る計測のスクリプトを置き、中央値を記録する。モデルの読み込みの時間と、ホットキーを受けてから録音が始まるまで・処理中のホットキーを捨てるまでの時間も同じスクリプトで測る | 今のログは秒の単位で中央値の比較に使えない。マイクと利用者の操作を使わず、貼り付けのキーは送らない（前面のアプリへ打ち込まない）。#22 で新しい構成を同じ区間で測る |
| 測定の記録 | 測った値を非機能要件の外部の制約・根拠・決定値に書き、測った手順と生の値をこの PR ドキュメントに残す | - |
