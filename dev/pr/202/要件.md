# 要件

## 要望

Ubuntu で dev の依存を含む環境を作り、常駐アプリが起動する。
Windows の動きは変えない。

- Ubuntu 24.04 で `uv sync --frozen`（dev グループを含む）が成功する
  - `pycaw`・`comtypes`（dependencies）と `pywin32`（dev）に `; sys_platform == "win32"` を付け、`uv.lock` を作り直す
- Ubuntu の Xorg のセッションで `python -m voice_paste` が起動し、トレイのアイコンが出て録音の開始を待つ
- OS の判定を 1 か所に集め、`main.py` の配線で OS に合った実装を選ぶ（各モジュールに `sys.platform` の分岐を置かない）
- 単一インスタンスの排他が Linux でも働く
  - 同じ設定の置き場所で 2 つ目を起動すると、前のプロセスに終わるよう頼み、前のプロセスが排他を放してから取る
  - 待つ上限は Windows と同じ決定値（非機能要件『前の常駐サービスの終わりを待つ時間』）を使う
  - 前のプロセスが片付けずに落ちても、次の起動で排他を取れる
- 音量
  - Linux では録音中に音量を下げる処理を行わない（何もしない実装を渡す）
  - Linux の設定画面には `recording.lower_volume`・`recording.volume_percent`・`recording.fade_sec` を出さない。`settings.toml` に値があっても使わない
- 設定
  - 設定のスキーマ（`Settings`）は OS で変えない。既定値だけを OS で変える（共通の既定値に OS ごとの上書きを重ねる）
  - Linux の `recording.lower_volume` の既定値は `false` にする
  - Linux の `transcription.local_whisper.device` の既定値は `cpu`、`compute_type` の既定値は `int8` にする（Linux では CUDA のライブラリを読ませる手当てが無く、`cuda` の既定値では文字起こしのワーカーが起動に失敗する）
- ブラウザ添付のプリセットの画面を Linux でも開く
  - Chromium 系のブラウザが見つかれば `--app` のアプリのウィンドウで、無ければ既定のブラウザ（`xdg-open`）で開く
  - 探すブラウザと順序は `google-chrome`・`chromium`・`chromium-browser`・`microsoft-edge` の順に PATH から探す（Ubuntu では入れ方によって実行ファイルの名前が違い、どれか 1 つが入っていればアプリのウィンドウで開けるため。モジュール構成設計で決めた）
- Linux で動かせない Windows 専用のテスト（Win32・pycaw・SAPI を使うもの）は、Linux では skip する

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| 文字起こしのエンジンに OpenAI API を追加し、faster-whisper・nvidia-* を入れなくても使えるようにする | 別の Issue の範囲 | #197 |
| Linux でのキーの表示（Win → Super）と既定のホットキー・貼り付けのキー | 別の Issue の範囲 | #198 |
| Ubuntu の Xorg のセッションで起動から貼り付けまでを通すことと、Linux の起動の手段（ショートカット等）と手順（使い方のページ） | 別の Issue の範囲。この PR は `python -m voice_paste` で起動できるところまで | #199 |
| Wayland のセッションでのホットキーと貼り付け | 別の Issue の範囲 | #200 |
| Linux での E2E の実行 | E2E の前提（SAPI・Windows のシェル）が Windows に依存し、Linux で通す仕組みは起動から貼り付けまでを通す #199 で扱う | #199 |
| Linux の GPU（CUDA）での文字起こし | 検証環境の VM に GPU が無く確かめられない。Linux の既定値は `cpu`・`int8` にする | #203 |
