E2E の常駐アプリは venv の `python.exe` で動き、通知の送り主も `python.exe` になる。
この PC の通知の設定は `ToastEnabled=1` で、`HKCU\Software\Microsoft\Windows\CurrentVersion\Notifications\Settings` に python の項目は無い（[Issue #69](https://github.com/shuhei1101/voice-paste/issues/69) の tester の切り分け）。

## 切り分けの結果

2026-10-08 に、E2E と同じ venv の `python.exe` から、`QSystemTrayIcon.showMessage` で見出し・本文・`Warning`・10 秒の通知を出して確かめた（トレイのアイコンは失敗のアイコン）。

| 確かめたこと | 方法 | 結果 |
| --- | --- | --- |
| 通知が画面に出るか | 通知を出してから 8 秒の間、デスクトップ全体から見出しの名前の部品を UI Automation で探す | 出る。見出しの部品が `FlexibleToastView`（通知のトースト）の中に見つかった |
| 通知センターに残るか | 通知を出してから約 18 秒後、トレイのアイコンを出したまま、通知の記録（`%LOCALAPPDATA%\Microsoft\Windows\Notifications\wpndatabase.db`）を写して読む | 残らない。記録の件数は通知の前と同じで、この通知の行は無い |
| ほかのトレイのアイコンの通知 | 同じ記録の、トレイのアイコンの通知の送り主（`NotifyIconGeneratedAumid_*`）を読む | 9 つの送り主のどれも、残っている通知が 0 件 |

トレイのアイコンから出す通知は、この PC では画面に出るが通知センターに残らない。
起動の失敗・API を使えない知らせは常駐アプリから出ており、E2E の fail はテストの確かめの不備になる。

## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| E2E の確かめ | `_notification_in_center` の確かめを外し、2 件とも `notified`（`engine_unavailable`・`api_unavailable`）で知らせを出したことを確かめる | `test_error_when_engine_unavailable` は `wait_tray_state(FAILED)` の後に確かめる |
| 待ちの定数 | `_notification_in_center` と、それだけが使う `TOAST_SETTLE_SEC`・`ENGINE_FAILURE_TITLE`・`API_FAILURE_TITLE`・`open_notification_center` の import を消す | `tests/support/desktop.py` の `open_notification_center` は残す |
| 設計書 | 画面設計『トレイの通知』の冒頭リードを、通知センターに残らず、畳まれた後はトレイのメニューの「ログフォルダを開く」から理由を見る、に書き直す。単一ユースケース『録音を文字に起こす』の「失敗の通知を通知センターから押す」を「失敗の通知を押す」にし、畳まれる前の通知を押す流れにする | 要件の `未確定` の案 A |
| 常駐アプリの説明 | `src/voice_paste/ui/tray.py` の `FAILURE_MESSAGE_MSEC` の説明の「通知センターに残る」を、画面設計に合わせて直す | 振る舞いは変えない |
| 結合テストの説明 | `tests/integration/ui/test_tray_notification.py` の docstring の「通知センターから押したときは実機の E2E に残す」を、畳まれる前の通知を押したときは実機の E2E に残す、に直す | テストの中身は変えない |
| 既存機能への影響 | 常駐アプリの知らせの見出し・本文・押したときの動きを変えない | 結合テスト `test_tray_notification.py` で確かめる |
