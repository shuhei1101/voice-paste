## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 要求の守り | `_guard_web` で、Origin の無い要求はメソッドによらず通す。Origin が付いていれば `_allowed_web_origins` にあるときだけ通し、無ければ今と同じく 403 で断る | Host の確認と、Linux で `/web/` の下を 404 にする扱いは変えない |
| 権限・認可 | インターフェース定義『音声を受け付ける』の認可の constraint を「Origin が無いか許す Origin にあること」へ、403 の condition を「Origin が付いていて許す Origin に無い」へ修正する | 『文字起こしの結果を返す』『用語集のプリセットの一覧を返す』『画面を配信する』と同じ書き方に統一する |
| エラー返却 | Origin の無い POST は 403 にならず、本文の検証（400・413・415・503）へ進む | - |
| 既存機能への影響 | ブラウザは POST に Origin を付けるため、外の端末の画面からの送信の扱いは変わらない | - |
| 単体テスト | Origin の無い POST を通す正常系を追加し、`test_dispatch_when_web_post_without_origin` は許さない Origin の 403 だけを検査する `test_dispatch_when_web_origin_not_allowed` へ名前を変更する | モジュール構成『server/middleware.py』のテストの name・summary・condition も同じ名前と内容へ修正する |
| 結合テスト | `test_error_when_origin_not_allowed` から `no_origin` を除き、Origin を付けない POST で 202 とジョブの ID が返る正常系を追加する | - |
| セキュリティ | ゲートウェイを通した外からの Origin の無い POST も通るが、外からの認証は Cloudflare Access が持つ | 要件『スコープ外』 |
