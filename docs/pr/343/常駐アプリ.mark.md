## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 配信元の設定 | 反映作業の実行スクリプトで `dev-docs.yaml` に種類の行を追加し、設計の工程の最初に commit する | スキーマのコピーは作らない（knowledge のスキーマを参照する） |
| LLM の呼び出しの設計書 | `docs/llm-call/` に OpenAI API の文字起こしの設計書を 1 枚作成し、目次 `docs/llm-call/index.yaml` を置く | モデル・入力（音声・言語・手がかりの語）・出力・失敗時の扱いを実装から起こす |
| 実装 | 設計書と食い違う箇所だけ `transcriber.py` を直し、単体テストを合わせる | 食い違いが無ければ実装・テストの工程を `skipped` にする |
| 待つ上限 | LLM の呼び出しの設計書の `timeout`（必須）を、判定フローチャート『タイムアウトの決め方』の外部 API の行に沿って OpenAI の公式の SDK の既定の 600 秒（`published_spec`）にし、`transcriber.py` の `timeout=None` を 600 秒へ合わせる | `未確定`（決める段: 承認確認） |
| プロンプト | `keywords[]` を受けないモデルへ `prompt` で指定する手がかりの単語を、プロンプトファイル `content/prompts/openai-transcribe.yaml` から描いた本文にする | Jinja2 で描くため、モジュール構成設計で依存と外部ライブラリの設計書を追加する |

`未確定`: 待つ上限。[#232 の回答](https://github.com/shuhei1101/voice-paste/pull/232#discussion_r4431424473)（#234 で反映）で、アプリ側ではタイムアウトを設けないと決めている。一方、テンプレート `template-llm-call` のスキーマは `timeout.seconds`（1 以上）を必須にしていて、「設けない」を記載できない。

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 設計書を OpenAI の公式の SDK の既定の 600 秒（`published_spec`）にし、実装も 600 秒へ合わせる。非機能要件『OpenAIの文字起こしのタイムアウトと再送』の決定値も 600 秒に戻す | テンプレートのとおりに設計書を作れ、応答が返らないときに 600 秒で失敗にできる | 600 秒を超える文字起こしは失敗になる |
| B | アプリ側ではタイムアウトを設けないまま実装を変えない。knowledge のテンプレートに「待つ上限を設けない」を記載できる値を追加する Issue を起票し、LLM の呼び出しの設計書の作成はその追加を待つ | #232 の回答のまま、どれだけ長くても待つ | 設計書を作れないまま #342 が止まる。応答が返らないと待ち続ける |

推奨: A

600 秒は OpenAI が公式の SDK で決めている値で、#232 の回答の「向こうに任せる」の範囲に収まるため。
