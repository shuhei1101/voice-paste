# 要件

## 要望

トレイのアイコンのボタンの名前にヒントが 2 つ並ぶ環境（Issue #59 の `voice-paste: 準備中 voice-paste: 待機中`）でも、画面・トレイ・ホットキーの E2E がトレイの今の状態を読んで流れるようにする。

ヒントが 2 つ並ぶのは Windows の振る舞いで、常駐アプリのトレイの更新の仕方によるものではない（確かめた内容は [常駐アプリ](./常駐アプリ.md) の `## 現状`）。
Windows はアイコンのボタンの UI Automation の名前に、アイコンを出した時点のヒントと今のヒントを並べる。
同じ実行ファイルのアイコンでも、ボタンはアイコンごとに分かれる。

- `Uia` は、名前が `voice-paste:` で始まるボタンを 1 つのアイコンとみなし、名前の最後のヒントをそのアイコンの今の状態として読む
- `AppDriver.tray_state`・`wait_tray_state`・`tray_icon_gone` が、ボタンの名前にヒントが 2 つ並んでいても、この常駐アプリの今の状態を返す
- `AppDriver.own_tray_icon`（メニューを開くアイコンの選び方）が、名前にヒントが 2 つ並んだボタンも、この常駐アプリのアイコンの候補にする
- `start_app` の起動の前の確認は、タスクバーにほかの voice-paste のボタンがあっても、隠れたアイコンの一覧の中のアイコンを読み落とさない
- `python.exe` が `IsPromoted=0` の環境で、Issue #59 で fail した複合ユースケース「声で入力した文字を貼り付ける」の `test_normal`・`test_normal_when_cancel`・`test_error_when_transcription_failed` と、下の表の `実行のみ` の行の E2E が、トレイの状態を読めないことでは fail・skip しない

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| E2E の前提として `python.exe` のトレイのアイコンをタスクバーへ出しておく（`IsPromoted=1`） | ユーザーの Windows のトレイの表示設定を変える前提になる（#58 で予定なしとした）。テストが隠れたアイコンの一覧を開いて読む形で足りる | 予定なし |
| 常駐アプリがアイコンを出す前にヒントを付けない形にして、ボタンの名前を今のヒントだけにする（スクリーンリーダーが読む名前に、起動の時点の `準備中` が残らなくなる） | 要望はテストの読み方で、ヒントが 2 つ並ぶのは Windows の振る舞いのため。ただ、ヒントを付けずにアイコンを出すとボタンの名前が今のヒントだけになることは確かめており、普段使いのアクセシビリティの名前にも関わるため、別 Issue にするかをレビューで確定する。今回は常駐アプリを変えない | 起票予定 |
| エクスプローラーの再起動の直後に前面がタスクバーのままで `PasteTarget.focus` の `SetForegroundWindow` が失敗すること・失敗したテストが貼り付け先の窓を残すこと | Issue #59 の実行の環境で整えたことで、トレイの状態の読み取りとは別の事象。要望に含まれない | [#61](https://github.com/shuhei1101/voice-paste/issues/61) |
