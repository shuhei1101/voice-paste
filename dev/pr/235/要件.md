# 要件

## 要望

AI Monitor の配布物を v0.2.0 から v0.3.0 へ追従する（差分: [v0.2.0...v0.3.0](https://github.com/shuhei1101/ai-monitor/compare/v0.2.0...v0.3.0)）。
終わりの条件は次の表の全ての行を満たすこと。

| 分類 | 終わりの条件 |
| --- | --- |
| テンプレート | `dev/テンプレート/` の `*.schema.yaml` が v0.3.0 と同じ中身になる（v0.3.0 と違う index・シナリオ・テスト実行方法・モジュール構成・共通・画面設計・非機能要件を差し替え、無い `フェーズ.schema.yaml` を追加して `dev/テンプレート/index.yaml` に行を追加する） |
| テンプレート | `python -m ai_monitor.design_docs convert --from v0.2.0 --to v0.3.0` を流し、設計書の検証の結果が develop と変わらない（v0.2.0 から v0.3.0 の間に変換の定義は無く、v0.3.0 の Schema での検証は develop と同じ 78 件） |
| 規約・外部規約・フェーズ手順・判定・観点 | v0.2.0 から v0.3.0 で変わったページを読み直し、従っていない成果物を修正するか、無いことを確かめた結果を計画書に記載する |
| サイトのレイアウト・配信設定 | 下の `未確定` の決着どおりに取り込む（取り込む場合は `docs/_theme/`・`ai-monitor-theme.yaml`・`docs/_config.yml`） |
| ルール索引 | 追加する行が無いことを確かめる（全プロジェクト共通の `rules.global.yaml` は AI Monitor のクローンから直接読み、voice-paste の `docs/rules.yaml` はこのプロジェクト固有の行だけを持つ） |
| プラグイン・設定スキーマ・MCP ツール | [反映作業](./反映作業/index.yaml) の全ての作業の状態が `済` になる |
| 準拠バージョン | `ai-monitor-version.ini` の先頭行が `v0.3.0` になる |

`未確定`: サイトのレイアウトと配信設定を取り込むか（決める段: ドキュメント修正の依頼の前）

voice-paste は `master` の `docs/` を GitHub Pages で公開しているが、`docs/_config.yml` も `docs/_theme/` も無く、Jekyll の既定の見た目で出ている。

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `import-site --version v0.3.0` で `docs/_theme/` と `ai-monitor-theme.yaml` を取り込み、`docs/_config.yml` を v0.3.0 を元に新規作成する（`title`・`baseurl` は voice-paste の値） | 公開サイトが AI Monitor と同じレイアウト・検索・図の表示になり、以降の版上げも同じコマンドで追従できる | 公開サイトの見た目が変わる。リポジトリに配布物のファイル（`mermaid.min.js` など）が増える |
| B | 取り込まない | 公開サイトが今のまま変わらない | 以降の追従 Issue でも同じ分類が残り続け、配布元のサイトの機能が使えない |

推奨: A

公開サイトは既に配信されており、配布元が版上げのたびに取り込む前提でコマンドと控えを用意しているため。

## 影響するユースケース

なし（アプリの振る舞い・API・画面を変えない）
