# 要件

## 要望

| Issue | 終わりの条件 |
| --- | --- |
| [#243](https://github.com/shuhei1101/voice-paste/issues/243) | 非機能要件テスト（`tests/nfr/`）を、Linux（Ubuntu 24.04 の Xorg のセッション）でも実行できる。Linux で流すときの決定値・測り方の扱いが決まっている |
| [#244](https://github.com/shuhei1101/voice-paste/issues/244) | スプリントの release の E2E の実行（tester が release ブランチで E2E を全件流す）に、検証環境の VM `voice-paste-ubuntu`（Ubuntu 24.04 の Xorg のセッション）での実行が加わっている |

Windows での非機能要件テストと E2E の動き・決定値は変えない。
`src/` は変えない。

- 非機能要件テスト（#243）
  - `tests/nfr/test_max_segment_length.py` の `sys.platform != "win32"` の skip を外す。WAV は今の `speech_sequence_input` のまま `synthesize_speech`（Windows は SAPI、Linux は Open JTalk）で書き出す
  - GPU を前提にするテスト（`requires_real_whisper` を付けたテスト・`test_transcription_parity.py`・`test_segment_callback_latency.py`）は、Linux（GPU が無い環境）では skip する。`test_segment_callback_latency.py` には GPU が無い環境で skip する条件を追加する。決定値は OS で分けない
  - 外の端末のブラウザの文字起こしを使うテスト（`test_web_body_limit.py`・`test_web_finished_jobs_kept.py`・`test_web_queue_limit.py`・`test_web_response_time.py`）は、常駐アプリが Linux でブラウザの文字起こしを持たない（`OS_UNAVAILABLE_FEATURES`）ため、Linux では skip する
  - 上の skip を除く非機能要件テストが、Linux の VM で `--run-e2e` を付けて pass する
  - `tests/nfr/test_segment_callback_latency.py` の docstring の SAPI の記述を、今の音声合成の扱いに合わせる
  - テスト実行方法の非機能要件テストの層に Linux の前提とコマンドを記載し、共通の前提の「非機能要件テストのうち Windows の音声合成（SAPI）で書き出した WAV を前提にするものは Linux では skip する」を今の扱いに合わせる
  - 非機能要件の各項目の `measurement`・測り方の `condition`・`notes` のうち、SAPI・Windows・GPU を前提にした記述に Linux での扱いを記載する
- release の E2E の実行（#244）
  - tester が release の E2E の実行で、Windows での実行に加えて、WSL から鍵の SSH（`ssh voice-paste-ubuntu`）で VM に入り、VM の中の作業用のクローンを release ブランチにして、`DISPLAY=:0`・`XAUTHORITY=/run/user/1000/gdm/Xauthority` を渡した `.venv/bin/python -m pytest tests/e2e --run-e2e` を `systemd-run --user` で全件流し、結果を対象ケースの集約に含める
  - VM が止まっていて SSH が通らないときは、ユーザーに VM の起動を頼む（VM は別のホストの Hyper-V で動き、tester の端末から起動できない）
  - プロジェクトの直下の `agent_context.yaml`（新規）の `phase_extensions.tester` に拡張の行を追加し、フェーズの本文を `dev/エージェント運用/拡張/tester/` に置く
  - VM の前提（自動起動の常駐アプリを終わらせてから流す・メモリを 8 GB の固定で割り当てる・全件で約 36 分かかる）を手順に含める

GPU を前提にするテストの扱いと VM を操作する手段は、PoC 検証の結果で決めた（[常駐アプリ](./常駐アプリ.md) の `## PoC 結果`）。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| Linux の GPU（CUDA）での非機能要件テストの実行 | 検証環境の VM に GPU が無い。GPU のある Linux の端末を用意できるまでの範囲 | [#203](https://github.com/shuhei1101/voice-paste/issues/203) |
| Wayland のセッションでの非機能要件テスト・E2E の実行 | 要望は Xorg のセッション。Wayland のホットキーと貼り付けは別の Issue の範囲 | [#200](https://github.com/shuhei1101/voice-paste/issues/200) |
| Linux で非機能要件の決定値を測り直して変える | 決定値は Windows の実測から決めている。Linux では GPU を前提にするテストを skip する | 予定なし |
| 非機能要件テストのうち設定のモデルを一部の引数だけで作るもの（`test_max_segment_length.py`・OpenAI の 2 ファイル・`test_web_queue_limit.py`）が、[#246](https://github.com/shuhei1101/voice-paste/pull/246) の後に `ValidationError` で失敗する | OS によらない不具合で、この PR がマージされなくても同じ内容で成り立つ。`test_max_segment_length.py` を Linux で pass させるには先に直っている必要がある | [#253](https://github.com/shuhei1101/voice-paste/issues/253) |
