# 要件

## 要望

同じ端末のほかのプロセスが、API で連続録音のセッションを始められるようにする。

- 連続録音のセッションは、呼び出し元が完了を呼ぶまで録音を止めない
- 録音中に話し声の後で無音が設定の長さ以上続いたところで区切り、区切った単位（区間）ごとに文字に起こして用語集で補正し、開始で指定した返送先へ送る
- 区間の返送は区切った順に返送先へ届く。各返送に区間の通し番号（1 から 1 ずつ増える）を付け、受け口が順と抜けを見分けられるようにする
- 最後の区間の返送の後に、セッションが終わったことと区間の数が分かる返送を 1 回送る
- 区間を文字に起こしている間も録音を続け、区間の境目で話し声を落とさない
- 話し声を含まない無音だけの間は区間にせず、文字に起こさず、返送もしない
- 区間ごとに録音を履歴に残す（履歴を残す設定のとき）
- 連続録音のセッション中は、今と同じくほかの開始（API は 409、ホットキー・トレイは処理中のダイアログ）を断る
- 開始で連続録音を指定しない呼び出しは、今の 1 回だけ録って返す振る舞いのまま変わらない

連続録音は、`POST /sessions` の body の `continuous` を `true` にして始める（省略時は今の 1 回の録音）。排他・守り・返送先の確かめは今のセッションのものを使い回す。

- 連続録音のセッションへの停止（`/stop`）は、止めずに 409 で断る。連続録音は完了で終える
- 区間の返送には通し番号（`segment_number`）を付ける。終わりの返送は、`result` が `completed`（完了）か `truncated`（上限での打ち切り）で、区間の数（`segment_count`）を付ける
- 区切りの無音の長さは設定（`api.continuous.min_silence_sec`、既定 2 秒）で変えられる
- 無音が来ないまま話し続けたときは、区間の最大の長さ（20 秒）に達したところで、直近の短い無音の中か今の位置で区切る
- 連続録音のセッションには 1 回の録音とは別の上限時間を持ち、設定（`api.continuous.session_limit_sec`、既定 4 時間）で変えられる
- 区切ってから返送が届くまでの時間は 4 秒以内にする（非機能要件テストの実測は 20 秒以下の区間で最大 3.46 秒）
- 無音の区切りは、faster-whisper に同梱の Silero VAD を録音側で 512 サンプルごとに流して見つける（PoC で録音に遅れず判定できることを確かめた。計画書の `## PoC 結果`）
- 背景にノイズがあると、区切りの無音をわずかに超える間では区切れないことがある。そのときは区間が長くなるのを受け入れる（[確認ログ](./確認ログ.md)）
- 背景に人の声（ゲームの台詞など）があると話し声と見分けられない。この使い方は要件の対象の外とする

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| ホットキー・トレイ・録音の画面からの連続録音 | Issue は API の上に足すと限っており、想定する使う側（#1 のゲーム実況・声での操作）は API から呼ぶ | 予定なし |
| 区間の文字を設定の送り先のエンドポイントや貼り付けなどの出力先へ届ける | 返送先は開始で呼び出し元が指定し、出力先へ届ける要望が無い | 予定なし |
| WebSocket などのストリームでの区間の受け渡し | 今の返送（HTTP の POST）を区間ごとに使えば順に渡せる | 予定なし |
| 話者の分離・区間をまたいだ文脈での補正 | 要望に含まれない | 予定なし |
| 背景に人の声（ゲームの台詞など）がある中での区切り | Silero VAD が背景の台詞を話し声と判定し、区切れない（PoC の結果）。見分けるには話者の分離などの別の仕組みが要る | 予定なし |
