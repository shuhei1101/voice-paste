# トレイのヒントに状態が 2 つ並んでも画面・トレイの E2E が今の状態を読めるようにする

## 概要

常駐アプリのトレイのアイコンにヒントの状態が 2 つ並ぶ環境でも、画面・トレイ・ホットキーの E2E がトレイの今の状態を読んで流れるようにする。

## 背景

[Issue #59](https://github.com/shuhei1101/voice-paste/issues/59) の E2E の不備。
release PR [#52](https://github.com/shuhei1101/voice-paste/pull/52)（Sprint v0.3.0、[#55](https://github.com/shuhei1101/voice-paste/pull/55)・[#58](https://github.com/shuhei1101/voice-paste/pull/58) の修正を含む `df717a0`）で E2E を再実行すると、複合ユースケース「声で入力した文字を貼り付ける」の 3 件が、録音を始める前に `トレイが 待機中 にならなかった（今は None）` で fail した。

- 常駐アプリを 1 つだけ動かしても、トレイの 1 つのボタンの名前が `voice-paste: 準備中 voice-paste: 待機中` になり、`Uia.tray_tooltips` が `['準備中', '待機中']` を返す。普段使いの `pythonw.exe` をタスクバーに出したときも同じ名前になる
- `AppDriver.tray_state` は並んだ状態の先頭を今の状態とみなすため、`準備中` を読み、`待機中` を待っても一致しない
- `start_app` の起動の前の確認は、タスクバーにほかの voice-paste のボタンがあると、そこだけを読んで隠れたアイコンの一覧を開かない

ヒントが 2 つ並ぶのが Windows の表示によるものか、常駐アプリのトレイの更新の仕方によるものかは、Issue の時点で切り分けていない。
