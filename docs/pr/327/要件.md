# 要件

## 要望

`dev-docs.yaml` に `nav` を追加し、規約『開発ドキュメントのナビゲーション』（knowledge の `dev-docs-navigation`）に従って、開発ドキュメントサーバーのタブとサイドバーを構成する。

- タブは 7 件以下にし、規約の順（はじめに・使い方・設計書・規約・コード・リファレンス・用語集）で、配信元に無いタブを飛ばして並べる
- 設計書の種類ごとの行（データ・アーキテクチャ図・非機能要件・シナリオ・インターフェース定義・モジュール構成・画面設計・ER 図・設定・外部API・外部ライブラリ・テスト実行方法・開発コマンド・フォルダ構成）は、タブ「設計書」1 つにまとめ、種類をサイドバーのグループにする
- 公開ドキュメント（`docs/guide/files.yml`）の文書は、`category`（はじめに・使い方・リファレンス）でそれぞれのタブに分ける
- コード（常駐アプリ・Haas の文字起こしのサーバー・テスト）はタブ「コード」にまとめ、サイドバーのグループで分ける
- フォルダの目次（`kind: index`）と、読む人が参照しない内部のファイル（モックの Markdown・docs の直下の Markdown のうち内部のもの）は、タブとサイドバーに並べない
- 入れ子は 2 階層までにし、グループの中は手順の順か重要さの順に並べる（名前の順は用語集だけ）
- 修正した後、開発ドキュメントサーバーの画面（タブの並びと数・サイドバーのグループ・目次や内部のファイルが出ていないか・文書をスクロールした状態）をスクリーンショットで確認し、レビューを通す（[shuhei1101/ai-monitor#3509](https://github.com/shuhei1101/ai-monitor/issues/3509)）
