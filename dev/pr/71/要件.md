# 要件

## 要望

設定画面で値を変えたまま開いている間に常駐アプリを終了しても、変えた値を捨てる確認を出さずに設定画面を閉じ、片付けて終了コード 0 で終わる。

- 対象の終え方は、トレイの「終了」・起動したコンソールの Ctrl+Break と Ctrl+C・後から起動したプロセスからの終了の依頼（どれも `QApplication.quit` でイベントループを抜ける）
- 変えた値は保存せず、`settings.toml` を書き換えない
- 終了のときは、設定画面を開いていない終了と同じ片付け（ホットキーの受付・API の待ち受け・文字起こしワーカーを止め、`常駐サービスを終えた` をログに出す）を行う
- 設定画面の「キャンセル」・Esc・窓の × で閉じるときは、今までどおり変えた値を捨てる確認を出す
- E2E の `test_normal_when_quit_with_unsaved_settings` の 2 通り（`tray_quit`・`ctrl_break`）が、終了の操作から 20 秒以内に終了コード 0 で終わる

`未確定`: 設定画面で値を変えたままトレイの「再起動」を選んだときの扱い（決める段: 単一ユースケース設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 「終了」と同じく、変えた値を捨てる確認を出さずに設定画面を閉じて再起動する | 「終了」と「再起動」の扱いが揃う | 変えた値が確認なしで消える |
| B | 変えた値を捨てる確認を出し、捨てるなら再起動し、設定画面へ戻るなら再起動を取りやめる | 変えた値を消す前に確かめられる | 「終了」と扱いが分かれる。取りやめたときに再起動の依頼を取り消す処理が要る |

推奨: A

「終了」と「再起動」は同じ `request_exit` を通り、シナリオは「終了」で確認を出さないと決めている。
