# 要件

## 要望

#65 で E2E を外したままの次のシナリオ・期待値の E2E を置き、`--run-e2e` を付けて流しても実機のマイクを開かないようにする。

- 常駐アプリを起動する: 正常シナリオと「API の待ち受けを始められない」の期待値「録音開始のホットキーを押すと録音が始まる」と、「古い AI チャットの設定が残っている」の期待値のうちプリセットのボタンと確定して送るまで
- 録音する: 全シナリオ（Windows の窓の重なり・モニター・窓の移動を使う 4 つを除く。`## スコープ外`）
- 起こした文字を届ける: 全シナリオ
- 録音を文字に起こす: 正常シナリオ（文字起こしの手がかりを渡す）以外の全シナリオ

置き方は次のとおりにする。

- 常駐アプリは画面・トレイの E2E と同じく pytest のプロセスの中で `main()` から起動し、`run_resident_app` の `wav_input` で録音の入力を WAV を流すものに、システム音量を呼ばれた値を控えるものに差し替える（実機のマイクを開かず、システム音量を変えない）
- 録音を始める操作は、差し替えたホットキーの受付に登録された関数を呼ぶか、トレイのメニュー・API から行う
- 貼り付けのキーは送ったキーを控えるものに差し替え、実機のキーボードへ送らない
- 返送先・送り先のエンドポイントは、テストが立てる 127.0.0.1 の受け口にする
- 4 つのシナリオの各シナリオに `test` を、`録音する`・`起こした文字を届ける` に `test_file` を持たせ、Mock の行と補足『E2E のテスト』を差し替えた形に合わせる

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| 録音する の「ほかの窓を前面に出す」「主のモニターに出す」「カーソルのあるモニターに出す」「録音の画面を動かす」の E2E | Windows の窓の重なり・モニター・窓の移動を使い、offscreen の Qt では起こせない。画面の結合テストが、最前面を保つ指定・表示位置・ドラッグで動かす呼び出しを確かめる | 予定なし |
| 録音する の「録音を取り消す」「録音の画面を隠して戻す」の期待値のうち、前面の窓（Windows のフォアグラウンド） | E2E は Windows のシェルを読まず、offscreen の Qt では Windows のフォアグラウンドを持たない。フォーカスを取らないことは Qt のアクティブな窓で確かめる | 予定なし |
| 起こした文字を届ける の「Enter と一緒に修飾キーを押す」の「Ctrl が押されたままになっていない」 | E2E は貼り付けのキーを控えるものに差し替えて実機のキーボードへ送らない。修飾キーを離すことはキーを送る部品の単体テストが確かめる | 予定なし |
