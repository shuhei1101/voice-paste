# 要件

## 要望

YAML の設計書と、コード・テストの `files.yml` の行に、規約 [文書のタグと description の記載](https://github.com/shuhei1101/knowledge/blob/develop/docs/rule/dev-doc-tag-description.yaml) に沿ったメタデータを記載する。

| 対象 | 記載するキー | 完了の条件 |
| --- | --- | --- |
| YAML の設計書（`docs/` の種類のフォルダの下。目次の `index.yaml` と用語集を除く） | `tags`（`action:`・`topic:`・`tool:` の接頭辞付きのタグと、最も分量の多い主題の 1 つに `main: true`）・`aliases`・`lead`（dev-docs.yaml で description に割り当てたキー） | 全ての設計書が `tags` を持ち、`main: true` のタグが 1 つある。`lead` を持たない設計書に「何を受け持ち、どんなときに参照するか」の 1 文の `lead` がある。`aliases` は本文や会話で別の名前で呼ばれる設計書に記載する |
| `dev-docs.yaml` | 設計書の種類の行の `metadata` | 設計書の種類の行が `tags`・`main_tags` を割り当て、全ての種類の行が `lead` を description に割り当てている |
| `src/files.yml`・`tests/files.yml`・`haas_server/src/files.yml` の行 | `tags`・`description` | 全ての行が、設計書と同じ語彙のタグと、「何を受け持ち、どんなときに参照するか」の 1 文の description を持つ |
| 検査 | - | 設計書の検証のコマンド（`ai_monitor.design_docs validate`）と project-index の検査で、追加したキーによる違反が無い |

タグは付ける前に project-index の `group_by: tags` で使用されているタグを検索し、同じ意味のタグを再利用する。
既存の `lead` は、Schema の決まり（初回に記載した内容のまま保つ）に従い書き換えない。
