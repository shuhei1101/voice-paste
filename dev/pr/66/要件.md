# 要件

## 要望

実機のマイクで録音するテストを消し、録音のファイルを内部で渡して文字に起こせるかを確かめるテストを置く。

- `--run-e2e` を付けて E2E・非機能要件テストを全件流しても、実機のマイクを開かず、スピーカーから読み上げない（`tests/support/desktop.py` の `speak` を使うテストが無い）
- 録音のファイルを内部で渡し、ローカルの Whisper（GPU）で起こした文字が、渡した録音の内容と合っていることを確かめるテストを置く
- テスト実行方法・シナリオ・非機能要件から「実機のマイクで録音する」前提を消し、残すテストと置くテストに合わせる
- 消すのは録音を始めるケース（ホットキー・トレイ・録音の画面・API の開始で録音するケース）だけにし、録音を始めない画面・トレイ・設定・起動のケースは E2E に残す
- 録音のファイルを渡して文字に起こすテストは E2E に置く。常駐アプリを pytest のプロセスの中で `build_handlers` で配線し、録音の入力を録音のファイルを流すものに差し替え、出力先（返送先の受け口・クリップボード）に届いた文字を確かめる。複合ユースケースのシナリオの対応テストにする
- 渡す録音のファイルは、テストの中で Windows の音声合成（SAPI）で決めた文を WAV へ書き出して作る（スピーカーもマイクも通さない）
- 実機のマイクで録る非機能要件テスト 3 つは、録音の入力をテストの中で書き出した無音の WAV を流すものに差し替えて測り直す。API の開始・処理中の 2 つ（`test_api_start_response_time.py`・`test_busy_response_time.py`）は、pytest のプロセスの中で `build_handlers` を配線する（`test_paste_latency.py` と同じ形）。セッションの上限時間（`test_api_session_limit.py`）は、SessionManager を上限時間 3 秒で自分で組む（GPU を使わない）

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| E2E の貼り付け先が前面に出せないときの失敗と、失敗したテストの窓の残り | 貼り付け先は録音のケースだけが使う。この PR で録音のケースが消えれば報告の元が無くなるため、マージの後に task-planner が受付で扱う | #61 |
| E2E だけが使う常駐アプリの口（`VOICE_PASTE_ACCEPT_INJECTED_HOTKEYS` で合成したキーをホットキーとして受ける起動） | 録音を始めるケースを外すと、残すケースが合成したキーのホットキーを使わなくなる。口を消すのは `src/` を変える別の変更になる | #67 |
| 外部デバイス（マイク・キーボードなど）からの実際の入力をテストせず、入力された体からテストする規約 | 全プロジェクトに当てる規約で、AI Monitor 側が持つ | [ai-monitor#2579](https://github.com/shuhei1101/ai-monitor/issues/2579) |
