# 要件

## 要望

常駐アプリの設定を、判定フローチャート『設定値の置き場所』の 3 レイヤーで読む。

| レイヤー | 置き場所 | git | 持つ値 |
| --- | --- | --- | --- |
| 既定値 | リポジトリの `config/defaults.yaml` | 管理する | 設定の全てのキーと既定値（今の `_item(...)` の既定値と `OS_DEFAULT_OVERRIDES` の値） |
| 環境の値 | ユーザーごとの設定のフォルダの `settings.yaml` | 管理外 | 設定画面で変えた値・ユーザーが書いた値 |
| checkout の上書き | リポジトリ直下の `settings.local.yaml` | 管理外（`.gitignore`） | その checkout だけの値 |

- 読む順は 既定値 → 環境の値 → checkout の上書きで、後のレイヤーの値が勝つ
- 既定値が読めないときと、checkout の上書きが在るのに読めないときは、今の `settings.toml` を読めないときと同じく起動の失敗として扱う。checkout の上書きが無ければ飛ばす
- 実行中に設定画面で変えた値は、環境の値へ保存する
- 環境の値のサンプル `settings.sample.yaml` をリポジトリにコミットし、今の `settings.sample.toml` を置き換える
- OpenAI の API キー（`secrets/openai_api_key`）は、環境の値と同じフォルダの `secrets/` に置いたまま変えない
- ユーザーの手元の `settings.toml` の値を、`settings.yaml` へ失わずに移す

`未確定`: 3 レイヤーに合わせるか、と設定画面が保存する値の扱い（決める段: 単一ユースケース設計。ユーザーへ確かめる）

判定フローチャートの Q3（実行中に書き換わる状態か）は YES のとき `data/` に置く。
設定画面で保存する値は、ユーザーが選んで決める人・マシンごとの値で、アプリが動きながら書き換える状態ではない。

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 3 レイヤーに合わせ、設定画面で保存する値を ※2 の環境の値として `settings.yaml` に書く | ブランチで追加・改名した設定のキーを、手元の設定を書き換えずに他の checkout で動かせる。既定値をコードから外して調整できる | 設定の読み書きと置き場所・形式が変わり、手元の設定の移行が要る |
| B | 合わせない（この Issue を取り下げる） | 手元の設定と既存のコードを変えない | 判定フローチャート『設定値の置き場所』から外れたまま残る |

推奨: A

設定画面で保存する値は Q3 の「実行中に書き換わる状態」ではなく ※2 に当たり、フローチャートどおりに 3 レイヤーへ置ける。

`未確定`: 環境の値の置き場所（決める段: 単一ユースケース設計。ユーザーへ確かめる）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 今と同じ platformdirs の置き場所に置く（Windows は `%APPDATA%\voice-paste\settings.yaml`、Linux は `~/.config/voice-paste/settings.yaml`） | Windows の慣習に沿い、フォルダ・`secrets/`・用語集の CSV の置き場所が今と変わらない。Linux はフローチャートの `~/.config/{project}/` と一致する | Windows ではフローチャートの `~/.config/{project}/` と置き場所が違う |
| B | 全ての OS で `~/.config/voice-paste/settings.yaml` に置く | フローチャートの表記と一致する | Windows の慣習（`%APPDATA%`）から外れ、`secrets/`・用語集の CSV・トレイの「設定フォルダを開く」の開く先も移る |

推奨: A

フローチャートの出典の XDG は Linux の慣習で、主な利用先の Windows ではアプリの設定を `%APPDATA%` に置くのが慣習のため。

`未確定`: 設定ファイルの形式（決める段: 単一ユースケース設計。ユーザーへ確かめる）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | YAML にする（`defaults.yaml`・`settings.yaml`・`settings.local.yaml`）。コメントを保って書ける YAML の外部ライブラリを選ぶ | フローチャートのファイル名と一致する | ユーザーが直接書く設定の書き方が TOML から YAML へ変わる。外部ライブラリの選定が要る |
| B | TOML のまま、3 レイヤーの置き場所だけ合わせる（`defaults.toml`・`settings.toml`・`settings.local.toml`） | 書き方と tomlkit の読み書きを変えない | フローチャートのファイル名と違う |

推奨: A

フローチャートのファイル名に揃えると、AI Monitor の配布物の判定フローチャート・規約とずれが残らない。

`未確定`: 手元の `settings.toml` の移行の方法（決める段: 単一ユースケース設計。ユーザーへ確かめる）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 起動時に `settings.yaml` が無く `settings.toml` が在れば、値を `settings.yaml` へ移す。`settings.toml` は消さずに残す | 手元の Windows と Linux の VM のどちらも、新しいバージョンで起動するだけで移る。`settings.toml` が残るため戻せる | TOML を読むコードと tomlkit を移行のために残す |
| B | 反映作業のスクリプトで、master へ入った後に 1 回だけ移す | アプリに TOML を読むコードを残さない | master を取り込んでからスクリプトを流すまでの起動は既定値で動く。端末ごとにスクリプトを流す |

推奨: A

取り込んだ時点から移した値で動き、`settings.toml` を残すため戻せる。
B を選んだときは `反映作業/index.yaml` に作業を追加する。
