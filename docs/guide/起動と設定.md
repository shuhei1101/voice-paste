# 起動と設定

ショートカットからの起動と終了、Linux の起動と自動起動、設定・履歴・ログの配置先

## 環境を作る

リポジトリの直下で、Windows の uv の `uv sync --frozen` を実行する。
`.venv/` に、`uv.lock` で固定したバージョンの依存が入る。

```bash
uv sync --frozen
```

ローカルの Whisper（faster-whisper と NVIDIA の CUDA のライブラリ）は `local-whisper` の extra にあり、上のコマンドだけでは入らない。
ローカルの Whisper を使用する環境は、extra を含めて作る。

```bash
uv sync --frozen --extra local-whisper
```

[文字起こしのエンジン](#文字起こしのエンジン)に OpenAI API を使用する環境は、extra を含めない `uv sync --frozen` で足りる。
faster-whisper と NVIDIA のライブラリが入らないため、GPU の無い端末でも環境を作れる。

ショートカットから起動するたびに、起動のバッチファイルが `local-whisper` の extra を含めて `uv sync --frozen` を実行し、`.venv/` を `uv.lock` に合わせてから起動する。
`.venv/` が無いときや、取り込んだ変更で依存が変わったときも、起動すれば `.venv/` が作り直される。
uv は PATH から探し、無ければ `%USERPROFILE%\.local\bin\uv.exe` を使用する。

## 起動する

デスクトップかスタートメニューの `voice-paste.bat - ショートカット` を開く。
コンソールは出ず、トレイに voice-paste のアイコンが出る。
`.venv/` を再作成する間は、コンソールに `Syncing .venv with uv sync --frozen.` の行が出たまま残る。依存を再インストールするときは数分かかることがあり、再作成が終わるとコンソールが閉じて常駐サービスが立つ。
文字起こしのモデルを読み込む間は準備中のアイコンで、読み込みが終わるとアイコンが待機中になり、録音を始められる。

常駐中にもう一度ショートカットを開くと、前の常駐サービスに終わるよう頼み、終わってから新しい常駐サービスが立つ。
常駐サービスはいつも 1 つだけ動く。
前の常駐サービスが 55 秒までに終わらないときは、新しい常駐サービスは立たずに終わり（トレイのアイコンは出ない）、理由は `%LOCALAPPDATA%\voice-paste\log\` の日付つきのログに書き込まれる。

起動に失敗したときは、トレイのアイコンが失敗の表示になり、理由が通知される。

- [設定](#設定)のファイルを読み込めないときは、「録音を開始」も「設定…」も押せない。通知に出たファイルを修正し、「再起動」を選ぶ。`settings.yaml` は「設定フォルダを開く」から開ける
- 文字起こしのモデルを読み込めないときは、録音を始められない。「設定…」から設定を開いて修正できる
- 文字起こしのエンジンを準備できないときも、録音を始められない。エンジンが OpenAI API で API キーを読み込めないとき、エンジンがローカルの Whisper で `local-whisper` の extra が入っていないときが当たる。理由が通知され、ログに記載される。「設定…」でエンジンを選び直すか、API キーを配置するか extra を含めて環境を作り直してから、「再起動」を選ぶ
- API の待ち受けを始められないときは、API だけが使用できず、ホットキーとトレイからの録音は使用できる
- ホットキーを受け付けられないときは、トレイから録音できる

環境を作れないときは常駐サービスは立たず、コンソールに `[ERROR]` で始まる理由と `launcher.log` の場所が出て止まる。

| 理由の行 | 起きたこと |
| --- | --- |
| `[ERROR] uv not found. ...` | uv が PATH にも `%USERPROFILE%\.local\bin\uv.exe` にも無く、`.venv/` から voice-paste を読み込めない。uv を入れてからショートカットをもう一度開く |
| `[ERROR] uv sync --frozen failed with code ...` | `uv sync --frozen` が失敗した。出力は `launcher.log` にある |
| `[ERROR] voice_paste cannot be imported from .venv after uv sync.` | `.venv/` を再作成しても voice-paste を読み込めない |

起動の記録（起動した時刻・使用した Python・終了コード）は `%LOCALAPPDATA%\voice-paste\log\launcher.log` に書き込まれる。
`uv sync --frozen` の出力もここに書き込まれる。
起動のたびに上書きされる。

## Linux で起動する

Ubuntu 24.04 の Xorg のセッション（ログイン画面で歯車から「Ubuntu on Xorg」を選ぶ）と Wayland のセッション（既定）で使用する。
Wayland のセッションでは、[Wayland のセッションで要る設定](#wayland-のセッションで要る設定)が要る。
Xorg のセッションでは要らない。

### Linux の環境を作る

OS のパッケージを入れる。

```bash
sudo apt install xclip libportaudio2 libxcb-cursor0 gcc linux-libc-dev
```

| パッケージ | 用途 |
| --- | --- |
| `xclip` | 起こした文字をクリップボードへコピーする |
| `libportaudio2` | マイクから録音する |
| `libxcb-cursor0` | 画面（録音の画面・設定画面・トレイ）を出す |
| `gcc`・`linux-libc-dev` | 依存の `evdev` を導入するときにビルドする |

uv は Linux の uv を入れる。
起動のスクリプトは uv を PATH から探し、無ければ `~/.local/bin/uv` を使用する。
`.venv/` と Python は起動のスクリプトが uv で作るため、`uv sync --frozen` を自分で実行する必要はない。

文字起こしのエンジンの既定はローカルの Whisper で、Linux では CPU（`device: cpu`・`compute_type: int8`）で動く。

### Wayland のセッションで要る設定

Wayland のセッションでは、貼り付けのキーと Enter を、仮想のキーボード（`/dev/uinput`）から送信する。
`/dev/uinput` を開く権限が要る。
次を、sudo で 1 回だけ設定する。

```bash
echo 'KERNEL=="uinput", GROUP="input", MODE="0660", OPTIONS+="static_node=uinput"' | sudo tee /etc/udev/rules.d/99-voice-paste-uinput.rules
sudo usermod -aG input "$USER"
```

設定の後に、再起動する。
グループの追加は、ログアウトしてログインし直しても反映されない。

権限が無いまま起動すると、貼り付けのキーを送信できないことと権限の設定の手順がトレイで通知される。
このときも録音はでき、「コピーのみ」はクリップボードにコピーする。

ホットキーは、常駐サービスが GNOME のカスタムショートカットへ登録する。
設定画面を開いている間は登録が外れ、新しいホットキーは設定画面を閉じると有効になる。
常駐サービスを終えると登録は外れる。

### Linux の起動の手順

リポジトリの直下で、起動のスクリプトを実行する。

```bash
./voice-paste.sh
```

起動のたびに、`local-whisper` の extra を含めて `uv sync --frozen` を実行し、`.venv/` を `uv.lock` に合わせてから常駐サービスを起動する。
常駐サービスは端末から切り離して立つため、スクリプトは起動を終えると 0 で終わり、端末を閉じても常駐サービスは残る。
実行している間は `Syncing .venv with uv sync --frozen. See log: {launcher.log のパス}` の行が出る。依存を再インストールするときは数分かかることがある。
上のバーのトレイにアイコンが出る。モデルを読み込む間は準備中のアイコンで、読み込みが終わると待機中になる。

常駐中にもう一度実行すると、Windows と同じく前の常駐サービスに終わるよう頼み、終わってから新しい常駐サービスが立つ。

### アプリの一覧から起動する

雛形の `voice-paste.desktop` をアプリの一覧に登録すると、GNOME のアプリの一覧から起動できる。

```bash
mkdir -p ~/.local/share/applications
sed "s|@REPO_DIR@|$PWD|g" voice-paste.desktop > ~/.local/share/applications/voice-paste.desktop
```

アプリの一覧から除外するときは、`~/.local/share/applications/voice-paste.desktop` を削除する。

### ログイン時に自動で起動する

同じ雛形を `~/.config/autostart/` に配置すると、ログインのたびに起動のスクリプトが実行される。

```bash
mkdir -p ~/.config/autostart
sed "s|@REPO_DIR@|$PWD|g" voice-paste.desktop > ~/.config/autostart/voice-paste.desktop
```

自動起動を止めるときは、`~/.config/autostart/voice-paste.desktop` を削除する。
動いている常駐サービスはトレイの「終了」で止める。

クローンを別の場所へ移したときは、上のコマンドを新しい場所で実行し直す。

### Linux で起動に失敗したとき

環境を作れないときは常駐サービスは立たず、`[ERROR]` で始まる理由の行と `See log: {launcher.log のパス}` の行を標準エラーに出して、0 以外の終了コードで終わる。
標準エラーが端末でなく（自動起動・アプリの一覧からの起動）、`notify-send` があるときは、同じ 2 行を通知する。

| 理由の行 | 起きたこと |
| --- | --- |
| `[ERROR] uv not found. Install uv and run voice-paste.sh again.` | uv が PATH にも `~/.local/bin/uv` にも無く、`.venv/` から voice-paste を読み込めない。uv を入れてからもう一度実行する |
| `[ERROR] uv sync --frozen failed with code ...` | `uv sync --frozen` が失敗した。出力は `launcher.log` にある |
| `[ERROR] voice_paste cannot be imported from .venv after uv sync.` | `.venv/` を再作成しても voice-paste を読み込めない |
| `[ERROR] failed to launch voice_paste with code ...` | 常駐サービスを端末から切り離して起動できなかった |

起動の記録（起動した時刻・`uv sync --frozen` の出力・使用した Python・終了コード）は `~/.local/share/voice-paste/log/launcher.log` に書き込まれる。
起動のたびに上書きされる。

### モデルを取得する初回の起動

ローカルの Whisper のモデルを取得する初回の起動は、取得に数十秒から数分かかる。
取得の間も、上のバーのトレイに準備中のアイコンが出る。
準備中はトレイのメニューの「設定…」を押せない。
「再起動」と「終了」は押せる。

### Linux の配置先

Windows の `%APPDATA%\voice-paste\` と `%LOCALAPPDATA%\voice-paste\` に当たる配置先は次のとおり。

| 配置先 | 中身 |
| --- | --- |
| `~/.config/voice-paste/settings.yaml` | 設定 |
| `~/.config/voice-paste/secrets/openai_api_key` | OpenAI の API キー |
| `~/.local/share/voice-paste/` | 履歴（`history/`）・ログ（`log/`）・一時の音声（`tmp/`）・API のトークン（`api_token`） |

## トレイから操作する

トレイのアイコンを右クリックするとメニューが開く。

<!-- table: data -->

| 項目 | 操作 |
| --- | --- |
| 録音を開始 | 録音を始める（アイコンの既定の操作）。[録音して貼り付ける](./録音して貼り付ける.md) |
| 録音の画面を表示 | 録音中に非表示にした録音の画面を再表示する。非表示にしている間は、アイコンの左クリックもこの操作になる |
| 設定… | 設定画面を開く |
| 設定フォルダを開く | `settings.yaml` のあるフォルダをエクスプローラーで開く |
| ログフォルダを開く | ログのフォルダをエクスプローラーで開く |
| 再起動 | 常駐サービスを終え、同じ引数で新しく起動する。[設定](#設定)の 3 つのファイルを読み直した今の設定で立つ |
| 終了 | 録音の受付・API・文字起こしのワーカーを止めて終わり、アイコンを削除する |

<!-- /table -->

録音から届けるまでの間は「録音を開始」と「設定…」を押せない。
その間に「再起動」「終了」を選ぶと、アイコンはすぐに消え、その回が終わってから再起動・終了する。
「録音の画面を表示」は、録音の画面を非表示にしているときだけ押せる。

## 設定

設定は次の 3 つのファイルを上から順に読み込み、同じキーは後のファイルの値で上書きする。

| ファイル | 中身 | 無いとき |
| --- | --- | --- |
| リポジトリの `config/defaults.yaml` | 全てのキーの既定値 | 起動に失敗する |
| `%APPDATA%\voice-paste\settings.yaml` | この端末で既定値から変えた値 | 既定値で動く |
| リポジトリの直下の `settings.local.yaml` | このクローンでだけ変えたい値 | 読み込まずに進む |

`settings.yaml` は、設定画面で既定値と違う値を保存したときと、起動時に `settings.toml` から移したとき（[`settings.toml` からの移行](#settingstoml-からの移行)）にできる。
`settings.local.yaml` は git の管理外で、自分で配置する。
`--data-dir` を引き渡して起動したときは、`settings.yaml` をそのフォルダから読み込み、`settings.local.yaml` は読み込まない。

設定画面（トレイの「設定…」）で変更して保存する。
「保存」を押しても設定画面は閉じず、フッターの上に「保存しました。」と出る。
保存した値は `settings.yaml` に書き込まれ、既定値と同じ値に戻したキーは `settings.yaml` から外れる。
`settings.local.yaml` にあるキーは、設定画面で保存しても `settings.local.yaml` の値で動く。
ホットキーは設定画面を閉じてから新しい組み合わせで有効になる。
`settings.yaml`・`settings.local.yaml` を直接書き換えてもよく、その場合は再起動してから有効になる。
設定画面の「再起動で反映」のマーカーがある項目は、保存した後に再起動してから有効になる。

`settings.yaml`・`settings.local.yaml` の記載方法の見本はリポジトリの直下の `settings.sample.yaml` にある。
全てのキーの既定値は `config/defaults.yaml` にある。

### `settings.toml` からの移行

前のバージョンの設定 `settings.toml` があり、同じフォルダに `settings.yaml` が無いときは、起動時に `settings.toml` の値のうち既定値と違うものを `settings.yaml` へ移す。
移した元と先のパスはログに書き込まれる。
`settings.toml` は削除せずに残るが、移した後は読み込まないため、書き換えても有効にならない。
`settings.toml` を読み込めないときは `settings.yaml` を作らず、設定のファイルを読み込めないときと同じく起動に失敗する。

### 画面の明暗

設定画面の「画面」のまとまりの「画面の明暗」で、全ての画面（録音の画面・文字起こし中の表示・設定画面・ダイアログ・トレイのメニュー）の明暗を選ぶ。
保存すると、再起動せずに開いている画面と次に出す画面へ有効になる。

| 選択肢 | 配色 |
| --- | --- |
| Windows の設定に従う（既定） | Windows の明暗に合わせる。常駐中に Windows の明暗を切り替えると、画面の配色も切り替わる |
| ライト | Windows の明暗によらずライトにする |
| ダーク | Windows の明暗によらずダークにする |

`settings.yaml` では `ui.theme` に `system`・`light`・`dark` を書き込む。
このキーが無い `settings.yaml` は「Windows の設定に従う」として動く。

### ボタンのホットキーの表示

設定画面の「画面」のまとまりで、録音の画面と文字起こし中の表示のそれぞれについて、ボタンの名前の下にホットキーを表示するかを選ぶ（既定は表示する）。
表示しないときはボタンに名前だけが出て、ホットキーでの操作はそのまま使用できる。
保存すると、次に出す録音の画面・文字起こし中の表示から有効になる。

`settings.yaml` では、録音の画面は `ui.show_hotkeys`、文字起こし中の表示は `ui.transcribing_show_hotkeys` に `true`・`false` を書き込む。
どちらも、キーが無い `settings.yaml` は「表示する」として動く。
`settings.toml` から移すときだけ、`ui.transcribing_show_hotkeys` が無ければ `ui.show_hotkeys` と同じ値で移す。

### 外の端末のブラウザに許す Origin

外の端末のブラウザから文字起こしの画面を使用するときは、`settings.yaml` の `api.allowed_web_origins` に、ゲートウェイの公開のサブドメインのオリジンを記載する。

```yaml
api:
  allowed_web_origins:
    - https://voice-paste.shuhdev.com
```

- オリジンは `scheme://host[:port]` の形式で記載する。末尾の `/` とパスは付けない
- 既定は空で、空のままでは画面は開けても音声を送信できない（`403`）
- 設定画面の「API」のまとまりの「外の端末に許す Origin」の欄（1 行に 1 つ）でも変えられる。再起動してから有効になる

### 文字起こしのエンジン

録音を文字に起こすエンジンを、設定画面の「文字起こし」のまとまりの「使う文字起こしのエンジン」で選ぶ。
再起動してから有効になる。
エンジンごとの値は、その下のエンジンごとのタブで変える。今選んでいるエンジンのタブには「使用中」が出る。選んでいないエンジンのタブの値も変えて保存できる。

| 選択肢 | `settings.yaml` の値 | 文字の起こし方 |
| --- | --- | --- |
| ローカルの Whisper（既定） | `local_whisper` | この端末の faster-whisper で起こす。`local-whisper` の extra を含めて作った環境が要る |
| OpenAI API | `openai` | 録音を OpenAI API へ送信して起こす。API キーが要り、OpenAI の従量課金がかかる |
| Haas（WSL） | `haas` | WSL の中の Haas-ja-v1.0 のサーバーで起こす。Windows の端末で、[Haas の文字起こしのサーバーの用意](#haas-の文字起こしのサーバーの用意)が要る |

```yaml
transcription:
  engine: openai
```

どれを選んでも、ホットキー・トレイ・API の録音、連続録音の区間、外の端末のブラウザから送信した音声を同じエンジンで起こす。
表記のヒントは OpenAI API にも引き渡し、文字起こしの後の補正は同じ。
Haas へは表記のヒントの表記と読みの組を引き渡す。
OpenAI API を選んだ間は、起こす録音の音声が OpenAI へ送信される。Haas の音声は端末の外へ送信しない。
OpenAI API と Haas の文字起こし中の表示は、進みと残りの時間を出さず、経過の時間だけを出す。

設定画面の「文字起こし」のまとまりの「OpenAI API」のタブで、OpenAI API のときに使用する値を変える。

| 設定のキー | 内容 |
| --- | --- |
| `transcription.openai.model` | 文字起こしに使用するモデル |
| `transcription.openai.language` | 文字起こしの言語（ISO-639-1。日本語は `ja`） |
| `transcription.openai.base_url` | 送信先のベース URL（http か https で始まる URL） |

既定値は `config/defaults.yaml` にある。

### OpenAI の API キー

API キーは設定のファイルにも設定画面にも記載しない。
エンジンが OpenAI API のときだけ起動時に読み込み、次のどちらかに配置する。
環境変数があれば、そちらを使用する。

| 配置先 | 中身 |
| --- | --- |
| 環境変数 `OPENAI_API_KEY` | API キーの文字列 |
| `%APPDATA%\voice-paste\secrets\openai_api_key` | API キーの文字列だけを記載したファイル。`settings.yaml` と同じフォルダの `secrets\openai_api_key` に自分で配置する（常駐サービスは作らない）。前後の空白と改行は除く |

どちらにも無いときは、起動に失敗する。
API キーはログにも出ない。

### Haas の文字起こしのサーバーの用意

エンジンを Haas（WSL）にすると、常駐アプリは起動のときに WSL の中のサーバーを起動し、終了・再起動で止める。
起動の前からサーバーが動いていれば、そのサーバーを使用し、止めない。
そのサーバーのモデル・計算の精度・装置が設定と違うときは、トレイの通知とログで通知し、そのサーバーのまま起こす。
設定の値で起こすには、WSL の中で `curl -X POST http://127.0.0.1:{ポート}/shutdown` を実行してサーバーを止めてから、常駐アプリを再起動する。
サーバーへ接続できないときは、終了までローカルの Whisper で起こし、トレイの通知とログで通知する（`settings.yaml` の値は変えない）。
サーバーが起動できなかった原因は、WSL の中の `~/.local/state/voice-paste/haas_server.log` で確認できる。
Linux の常駐アプリからは使用できない。

使用する端末には次が要る。

- WSL2 と NVIDIA GPU（GPU のメモリの空きが約 4 GB）
- WSL2 のネットワークが mirrored のモード（Windows 11 22H2 以降の機能）

mirrored のモードにするには、Windows の `%USERPROFILE%\.wslconfig` に次を書き込み、PowerShell で `wsl --shutdown` を実行して WSL を起動し直す。

```ini
[wsl2]
networkingMode=mirrored
```

サーバーの環境は、WSL の中で作る。
WSL の中に `uv` が要る（Windows 側の `uv` とは別に入れる）。
`{リポジトリの直下}` は、常駐アプリを動かす Windows のクローンを WSL から見たパス（例: `/mnt/c/Users/{ユーザー}/repo/voice-paste`）にする。
依存で数 GB のダウンロードが要り、モデルの取得に約 2 分かかる。

```bash
cd {リポジトリの直下}/haas_server
export UV_PROJECT_ENVIRONMENT="$HOME/.local/share/voice-paste/haas_server/.venv"
uv sync --frozen
uv run python -c "import haas_asr; haas_asr.load_model('third-intelligence/Haas-ja-v1.0')"
```

設定画面の「文字起こし」のまとまりの「Haas（WSL）」のタブで、次の値を変える。反映が「再起動」の値は再起動してから、「すぐ」の値は保存した後の次の文字起こしから有効になる。

<!-- table: data -->

| 設定のキー | 反映 | 内容 |
| --- | --- | --- |
| `transcription.haas.distribution` | 再起動 | サーバーを動かす WSL のディストリビューション。空なら WSL の既定のディストリビューション |
| `transcription.haas.port` | 再起動 | サーバーのポート（既定は `47824`）。`api.port` と同じ番号にできない |
| `transcription.haas.model` | 再起動 | 読み込むモデル（既定は `third-intelligence/Haas-ja-v1.0`）。Hugging Face Hub のモデルの名前か、WSL の中の .nemo ファイルのパス |
| `transcription.haas.dtype` | 再起動 | 計算の精度（`auto`・`bfloat16`・`float16`・`float32`。既定は `auto`）。`auto` は GPU では bfloat16、CPU では float32 |
| `transcription.haas.device` | 再起動 | 装置（`cuda`・`cuda:{番号}`・`cpu`。既定は `cuda`） |
| `transcription.haas.alpha` | すぐ | 手がかりの強さ（0.0〜10.0。既定は `2.0`）。上げると聞き逃した単語を検出しやすくなるが、話していない単語を出力することも増える |
| `transcription.haas.guard` | すぐ | 手がかりの採否を確認するか（既定は `true`）。手がかりなしでも起こし、ヒントの単語が丸ごと入った変化だけを採用する |
| `transcription.haas.short_audio_limit_sec` | すぐ | 一度に起こす音声の長さの上限（1.0〜60.0 秒。既定は `30.0`）。これより長い音声は静かな箇所で区切って起こす |
| `transcription.haas.chunk_sec` | すぐ | 区切る長さ（1.0〜60.0 秒。既定は `30.0`） |
| `transcription.haas.search_sec` | すぐ | 区切る位置の前後で静かな箇所を探す幅（0.0〜10.0 秒。既定は `2.0`） |
| `transcription.haas.window_sec` | すぐ | 静かさを測る窓（0.01〜1.0 秒。既定は `0.1`） |
| `transcription.haas.separator` | すぐ | 区切って起こした文字をつなぐ文字（16 文字以下。既定は空） |
| `transcription.haas.batch_size` | すぐ | まとめて起こす区切りの数（1〜256。既定は `64`）。変えると紙一重の箇所の結果がまれに変わる |

環境・ログ・モデルは WSL の中に配置する。使わなくなったら、WSL の中で次の順に削除する。
モデルの本体は Hugging Face のキャッシュの共有のフォルダにあるため、フォルダを手で削除せず、環境の `hf` で削除する。

```bash
~/.local/share/voice-paste/haas_server/.venv/bin/hf cache rm model/third-intelligence/Haas-ja-v1.0
rm -rf ~/.local/share/voice-paste/haas_server
rm ~/.local/state/voice-paste/haas_server.log*
```

## 外の端末へ公開する

スマホ・iPad・外の PC のブラウザから使用できるように、ゲートウェイ（shuhdev-gateway）で常駐サービスの API を公開する。
外からの認証はゲートウェイの Cloudflare Access が持ち、常駐サービスはトークンの代わりに許す Origin の一覧で `/web/` の下だけを通す。
使用方法は[外の端末から文字に起こす](./外の端末から文字に起こす.md)。

<!-- steps -->

1. ゲートウェイが動いている端末の `~/.config/shuhdev-gateway/settings.toml` に、voice-paste の固定の登録を記載する。ポートは設定の `api.port`（既定 47823）。`rewrite_origin` は `false` のままにする。

   ```toml
   [[fixed_registrations]]
   name = "voice-paste"
   port = 47823
   title = "voice-paste"
   path = "/web/"
   rewrite_origin = false
   ```

   `rewrite_origin` を `true` にすると Origin が書き換わり、許す Origin の一覧と合わなくなって `403` になる。
2. ゲートウェイを再起動して、固定の登録を有効にする。`gw ls` に `voice-paste` が出て、公開 URL（例 `https://voice-paste.shuhdev.com`）が分かる。
3. 公開 URL を `settings.yaml` の `api.allowed_web_origins` に記載し、トレイの「再起動」で反映する。
4. 外の端末のブラウザで、公開 URL の末尾に `/web/` を付けて開く。Cloudflare Access のログインの後に、文字起こしの画面が出る。

<!-- /steps -->

固定の登録は、常駐サービスを止めても外れない。公開 URL と許す Origin は変わらないため、常駐サービスを再起動しても操作は要らない。
固定の登録のキーとゲートウェイの再起動の仕方は、shuhdev-gateway のドキュメントにある。

## 履歴とログ

履歴・ログ・一時の音声・API のトークンは `%LOCALAPPDATA%\voice-paste\` の下に配置する。

| 配置先 | 中身 |
| --- | --- |
| `history\{日付}\` | 確定した録音（WAV）と起こした文字（テキスト）。`history.enabled` が `false` のときは残さない |
| `log\` | 日付つきのログ、`launcher.log`、クラッシュの記録 |
| `tmp\` | 履歴を残さない設定のときに、文字に起こすまで配置する録音 |
| `api_token` | API のトークンとポート。[API](./API.md) |

保持期間を過ぎた履歴とログは、起動時と常駐中の 24 時間ごとに消える。

| 設定のキー | 既定値 | 削除する対象 |
| --- | --- | --- |
| `history.retention_days` | 1 日 | この日数より前の日付の履歴のフォルダ |
| `logging.retention_days` | 7 日 | この日数より前の日付のログ |

`launcher.log` は日付の名前を持たないため、保持期間では消えない。

## `.env` から移した設定

刷新前の設定（リポジトリの直下の `.env`）は `settings.toml` へ移してあり、元の `.env` は `.env.migrated` の名前で残っている。
刷新前の履歴（リポジトリの直下の `history\`）は `%LOCALAPPDATA%\voice-paste\history\` へコピーしてある。

次の設定はコピーしていない。

- OpenAI で文字を起こす設定（`TRANSCRIPTION_ENGINE=openai`・`OPENAI_API_KEY`）。文字起こしのエンジンはローカルの Whisper が既定で、OpenAI API は `settings.yaml` の `transcription.engine` と API キーを自分で設定して使用する（[文字起こしのエンジン](#文字起こしのエンジン)）
- 1 回だけ録音して終わる設定（`RESIDENT_MODE`）。常駐だけになった
