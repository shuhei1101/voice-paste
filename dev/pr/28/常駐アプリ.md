## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| レイアウト | `src/voice_paste/` に `__main__.py`・`main.py`・`shared/`・`features/`・`integrations/`・`runtime/`・`server/`・`ui/` を置く。中身を作らない層は `__init__.py` だけを置く | パッケージ名は `voice_paste`。`pyproject.toml` で `src/` の `voice_paste` と、直下の `voice_paste_legacy` の両方をパッケージにする |
| 起動 | `python -m voice_paste` で、置き場所を決め、ログを設定し、設定を読んで、読んだ設定をログに書いて終わる | 常駐・配線・入口は後続の Issue。秘密の値（API キー）はログに出さない |
| 開発用の置き場所 | 起動の引数 `--data-dir` で置き場所の根を差し替え、並走の間の動作確認と単体テストは普段使いの `%APPDATA%\voice-paste\`・`%LOCALAPPDATA%\voice-paste\` に書かない | 並走の間は `--data-dir` を必須にする |
| 設定のモデル | `Settings` と各まとまり（文字起こし・録音・ホットキー・出力先・履歴・API・ログ）を pydantic で持ち、項目ごとに再起動が要るかの印を持つ。API キーは `SecretStr` | キーの一つ一つは新しい設定の設計書に書く |
| 設定の読み書き | `load_settings` は無ければ既定値で作り、値が合わなければどのキーが合わないかを持つ `SettingsError` を送出する。`save_settings` は tomlkit でコメントを保ったまま書き戻し、再起動が要る項目が変わったかを返す | - |
| `.env` からの移行 | `.env` を読むだけで改名も書き込みもせず、`.env.sample` の全キーを `settings.toml` のキーへ写す。番号付きの `AI_SEND_{n}_*` は出力先の一覧へ写す。書き込み先は呼び出し側が渡す | `.env` の改名（`.env.migrated`）は #22 の反映作業。対応表を `.env.sample` の全キーで単体テストする |
| ログ | 標準の logging を日付ごとのファイルへ書き、保持期間を過ぎた日付のログだけを消す | uvicorn のロガーを寄せる処理は API を作る #19 で確かめる |
| 例外 | `AppError` を根にした例外の階層を `shared/errors.py` に置く | HTTP への変換は #19 |
| 依存の検査 | import-linter の契約（層・feature の独立・出力先の独立）を `pyproject.toml` に置き、単体テストと同じく 1 コマンドで回せるようにする | 中身の無い層でも契約が通る |
| 依存 | 新しい構成が使う依存（fastapi・uvicorn・httpx・pydantic・tomlkit・platformdirs・numpy・comtypes）と開発用の依存（pytest・import-linter）を `pyproject.toml` に書く。pycaw は普段使いの venv に入っている版で `==` 固定する | PySide6 は #21。`voice_paste_legacy` が使う依存は消さない |
| 既存機能への影響 | `voice_paste_legacy`・`voice-paste.bat`・リポジトリの直下の `.env`・`history/`・`log/` を変えない | `pyproject.toml` の `[project.scripts]` も `voice_paste_legacy` のまま |
